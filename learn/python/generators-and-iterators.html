Generators and iterators

Python · part of the free zero-to-hero guide

A generator function uses yield instead of return, producing values one at a time, lazily, instead of building an entire list in memory upfront — essential when processing something too large to hold in memory at once, like reading through a multi-gigabyte log file line by line.

yield pauses the function exactly where it is, returning a value to whoever is iterating, and resumes right there — with all local variables intact — the next time a value is requested. This is fundamentally different from a normal function call, which restarts from the top and forgets everything every time.

Any object with a __next__ method (and typically __iter__, which returns the iterator itself) satisfies Python's iterator protocol; generators are simply the easiest way to create a working iterator without writing that boilerplate by hand. Calling next() on an exhausted iterator raises StopIteration, which is exactly the signal a for loop relies on internally to know when to stop.

A generator can only be iterated once — once exhausted, it doesn't reset. To loop over the same sequence of values again, you need to call the generator function again to get a brand-new generator object, which is a common source of confusion when a generator is accidentally reused as if it were a list.

Generator expressions ((x*2 for x in range(10))) are the lazy counterpart to list comprehensions — same syntax with parentheses instead of square brackets, but nothing is computed until you actually iterate. Passing a generator expression directly into a function like sum(x*x for x in nums) avoids building an intermediate list entirely.

yield from delegates to another generator or iterable, effectively flattening its values into the outer generator's output — genuinely useful for composing generators together, such as one generator that reads several files and yields from each one's line generator in turn.

generators.py
def count_up_to(n):
    i = 1
    while i <= n:
        yield i
        i += 1

for number in count_up_to(5):
    print(number)  # prints 1 through 5, one at a time
lazy_pipeline.py
def read_lines(path):
    with open(path) as f:
        for line in f:
            yield line.rstrip("\n")

def only_errors(lines):
    for line in lines:
        if "ERROR" in line:
            yield line

# nothing is read into memory until this loop actually runs
for line in only_errors(read_lines("app.log")):
    print(line)

total = sum(x * x for x in range(1_000_000))  # no intermediate list built
exhausted_generator.py
gen = count_up_to(3)
print(list(gen))   # [1, 2, 3]
print(list(gen))   # [] -- already exhausted, this is NOT a fresh copy

# to iterate again, call the function again:
print(list(count_up_to(3)))  # [1, 2, 3]
Key points
  • yield pauses the function, returning a value, and resumes exactly where it left off — with local state intact — on the next call.
  • Generators compute values lazily — nothing runs until you actually iterate over the generator.
  • A generator can only be iterated once; to loop over it again, you need to call the function again to get a fresh generator.
  • Generator expressions ((x*2 for x in range(10))) are the lazy counterpart to list comprehensions.
  • Passing a generator expression straight into a function like sum() or max() avoids building an intermediate list in memory.
  • The iterator protocol relies on __next__ raising StopIteration when there's nothing left — this is how a for loop knows to stop.
  • yield from delegates to another generator or iterable, flattening its output into the current generator.
