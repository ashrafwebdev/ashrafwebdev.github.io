Decorators and context managers

Python · part of the free zero-to-hero guide

A decorator wraps a function to extend its behavior without modifying its source — written with @decorator_name directly above a function definition. Common uses include logging, timing, caching, retrying on failure, and access control, and under the hood a decorator is just a function that takes a function and returns a (usually wrapped) function.

@wraps(func) from functools preserves the original function's __name__, docstring, and other metadata when wrapping it — without it, every decorated function would report its name as wrapper in stack traces and introspection, which is genuinely confusing to debug and easy to forget.

Decorators can themselves take arguments by adding an extra layer of nested functions — a decorator factory. @retry(times=3) looks like a decorator with a configuration option, but it's really a function that returns a decorator, which is why the pattern needs three nested function levels instead of two.

A context manager (used with with) guarantees setup and teardown code runs correctly, even on error — open() is the most common built-in example, guaranteeing the file gets closed. You can write your own using a class with __enter__ (runs at the start of the with block) and __exit__ (runs at the end, even if an exception happened inside).

The @contextmanager decorator from the contextlib module offers a much shorter way to write the same thing as a generator function: code before the single yield is the setup, code after it is the teardown, and it runs even if the block raises — far less boilerplate than writing a full class with __enter__/__exit__.

Python's with statement can open multiple context managers at once, separated by commas — with open("a") as a, open("b") as b: — and will correctly tear both down even if the second one fails to open, which is more reliable than nesting them or managing them by hand.

decorators.py
import time
from functools import wraps

def timed(func):
    @wraps(func)
    def wrapper(*args, **kwargs):
        start = time.time()
        result = func(*args, **kwargs)
        print(f"{func.__name__} took {time.time() - start:.3f}s")
        return result
    return wrapper

@timed
def slow_add(a, b):
    time.sleep(0.1)
    return a + b
decorator_with_args.py
from functools import wraps

def retry(times=3):
    def decorator(func):
        @wraps(func)
        def wrapper(*args, **kwargs):
            for attempt in range(1, times + 1):
                try:
                    return func(*args, **kwargs)
                except Exception as e:
                    print(f"Attempt {attempt} failed: {e}")
            raise RuntimeError(f"{func.__name__} failed after {times} attempts")
        return wrapper
    return decorator

@retry(times=2)
def flaky():
    raise ValueError("simulated failure")
context_manager.py
from contextlib import contextmanager
import time

@contextmanager
def timer(label):
    start = time.time()
    try:
        yield              # code inside the with-block runs here
    finally:
        print(f"{label}: {time.time() - start:.3f}s")

with timer("batch job"):
    time.sleep(0.2)
Key points
  • @wraps(func) from functools preserves the original function's name and docstring when wrapping it — easy to forget, worth doing every time.
  • A decorator is just a function that takes a function and returns a (usually wrapped) function.
  • Decorators that accept arguments (@retry(times=3)) need an extra layer of nested functions — a decorator factory.
  • A context manager guarantees its teardown code runs even if an exception happens inside the with block.
  • @contextmanager lets you write a context manager as a generator function with a single yield, far less boilerplate than a full class.
  • Put teardown logic after the yield inside a try/finally so it still runs if the code in the with block raises.
  • You can open multiple context managers in one with statement, separated by commas.
Try it yourself

Write a @timed decorator (like the example) and apply it to a function that does some work, confirming it prints the execution time. Then write your own context manager, either as a class with __enter__/__exit__ or using @contextmanager, that prints 'starting' and 'finished' around a block of code even if that block raises an exception.
