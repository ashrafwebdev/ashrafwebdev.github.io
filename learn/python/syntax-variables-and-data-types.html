01 Zero stage

Syntax, variables, and data types

Python · part of the free zero-to-hero guide

Python uses indentation, not curly braces, to mark blocks of code — this isn't just a style choice, it's part of the language's syntax, so consistent indentation (4 spaces is the convention, per PEP 8) actually matters for your code to run at all. Mixing tabs and spaces in the same file raises a TabError in Python 3, which is why almost every editor is configured to insert spaces when you press Tab.

Variables need no type declaration; Python figures the type out from the value assigned, and a variable name is really just a label pointing at an object in memory rather than a fixed box that holds it. The core built-in types are int, float, str, and bool, plus the collection types (list, dict, tuple, set) covered in a later lesson.

Naming matters: the convention is snake_case for variables and functions, PascalCase for classes, and UPPER_SNAKE_CASE for constants. Python won't enforce any of this — it's a style convention (PEP 8), not a rule the interpreter checks — but breaking it makes code harder for other Python developers, including future you, to read at a glance.

Python's int type has arbitrary precision — it grows as large as memory allows, with no silent overflow the way fixed-width integers in C or Java have. Floats, by contrast, are standard 64-bit binary floating point, so a number like 0.1 can't be represented exactly: 0.1 + 0.2 evaluates to 0.30000000000000004, not 0.3. For money or anywhere exactness matters, reach for the decimal module instead of plain floats.

Python distinguishes three division-related operators: / (true division) always returns a float, // (floor division) rounds down to the nearest whole number, and % (modulo) returns the remainder. Strings, meanwhile, are immutable — every operation that looks like it 'changes' a string, such as .upper(), actually returns a brand-new string object and leaves the original untouched.

None represents the deliberate absence of a value and is the sole value of type NoneType — it is not the same thing as 0, an empty string, or False, even though all of those, along with empty collections, are considered 'falsy' when used inside an if condition. Comments start with # and run to the end of the line; triple-quoted strings are commonly used both for multi-line text and for docstrings that document a function or class.

basics.py
name = "Amina"
age = 27
height = 1.68
is_admin = False
middle_name = None

print(type(name), type(age), type(height), type(is_admin), type(middle_name))
numeric_quirks.py
big = 2 ** 100                # ints never overflow
print(big)

print(0.1 + 0.2)               # 0.30000000000000004 -- binary float imprecision
print(round(0.1 + 0.2, 2))     # 0.3 -- round for display

print(7 / 2)                   # 3.5   -- true division, always float
print(7 // 2)                  # 3     -- floor division
print(7 % 2)                   # 1     -- remainder
print(-7 // 2)                 # -4    -- floors toward negative infinity, not zero
strings.py
title = "Learn Python"

print(title[:5])          # 'Learn' -- slicing, end index excluded
print(title[-6:])         # 'Python' -- negative index counts from the end
print(title.lower())      # returns a new string, title is unchanged
print(title)              # still 'Learn Python'

price = 19.9
print(f"${price:.2f}")   # '$19.90' -- format spec inside an f-string
Key points
  • Indentation defines code blocks — mixing tabs and spaces will cause errors, so pick spaces (4 is standard) and stay consistent.
  • Variables are dynamically typed: the same name could later be reassigned to a different type, though doing so on purpose is usually a code smell.
  • int has arbitrary precision and never overflows; float is binary floating point and can't represent numbers like 0.1 exactly.
  • / always returns a float, // floors to an integer, and % gives the remainder — mixing them up is a common source of off-by-one bugs.
  • Strings are immutable: methods like .upper() or .replace() return new strings rather than modifying the original in place.
  • type() tells you exactly what type a value currently is, useful when debugging.
  • None is not the same as 0, "", or False, even though all of them evaluate as falsy in a boolean context.
  • Python is case-sensitive: name and Name are different variables.
Try it yourself

Create variables for your name, age, and a boolean for whether you're currently learning Python, then print a sentence combining all three using an f-string. Afterward, in a second script, compute and print the result of 0.1 + 0.2, then print it again rounded to 2 decimal places, and write a one-line comment explaining why the two outputs differ.
