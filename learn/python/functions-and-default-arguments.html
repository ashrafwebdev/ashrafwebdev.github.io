Functions and default arguments

Python · part of the free zero-to-hero guide

Builds on: Control flow: if/elif/else, loops

Functions are defined with def. Parameters can have default values, so callers only need to supply the arguments that differ from the default — extremely common for optional configuration, like a page-size parameter that most callers leave alone.

Python also supports keyword arguments, letting callers specify arguments by name rather than position, which makes call sites more readable when a function takes several parameters — compare resize(img, 800, 600) to resize(img, width=800, height=600), and it's obvious which call is easier to review months later.

*args collects any extra positional arguments into a tuple, and **kwargs collects any extra keyword arguments into a dict, which lets a function accept a variable, open-ended number of inputs — this is exactly how functions like print() can take any number of values to print.

A genuinely important gotcha: default argument values are evaluated exactly once, when the function is defined, not each time it's called. Using a mutable default like def add_item(item, bucket=[]): means every call that relies on the default shares the exact same list, and items silently pile up across unrelated calls — the fix is to default to None and create the mutable object inside the function body.

Since Python 3.8, you can force certain parameters to be keyword-only (after a bare * in the signature) or positional-only (before a bare /), which lets a library author lock down exactly how a function is meant to be called and keep the freedom to rename internal parameter names later without breaking callers.

Functions are first-class objects in Python: they can be assigned to variables, stored in a list, and passed as arguments to other functions, which is the foundation that decorators, callbacks, and the whole functional-programming style in Python (map, filter, sorted(key=...)) is built on.

functions.py
def greet(name, greeting="Hello"):
    return f"{greeting}, {name}!"

print(greet("Amina"))
print(greet("Yusuf", greeting="Welcome"))
args_kwargs.py
def order_summary(customer, *items, **details):
    print(f"Customer: {customer}")
    print(f"Items: {items}")
    print(f"Details: {details}")

order_summary("Amina", "book", "pen", gift_wrap=True, express=False)
# Items: ('book', 'pen')
# Details: {'gift_wrap': True, 'express': False}
mutable_default_bug.py
# BAD -- the empty list is created once, and reused on every call
def add_item(item, bucket=[]):
    bucket.append(item)
    return bucket

print(add_item("apple"))   # ['apple']
print(add_item("banana"))  # ['apple', 'banana']  -- surprise!

# GOOD -- default to None, create a fresh list inside the function
def add_item_fixed(item, bucket=None):
    if bucket is None:
        bucket = []
    bucket.append(item)
    return bucket
Key points
  • Default argument values are evaluated once, when the function is defined — never use a mutable default like [] or {}, it's a classic Python gotcha.
  • Keyword arguments (greeting="Welcome") can be passed in any order once positional arguments are supplied.
  • A function without an explicit return returns None.
  • *args and **kwargs let a function accept a variable number of positional and keyword arguments.
  • Parameters after a bare * in the signature become keyword-only; parameters before a bare / become positional-only.
  • Functions are first-class values — they can be stored in variables and collections and passed to other functions, e.g. as the key= argument to sorted().
  • The fix for the mutable-default bug is always the same pattern: default to None, then create the real mutable object inside the function body.
Try it yourself

Write a function that formats a price with a default currency symbol parameter, then call it once with the default and once overriding it by keyword. Then write a second function demonstrating the mutable-default-argument bug on purpose with a list, call it twice, and fix it using the None-default pattern.
