Lists, dictionaries, tuples, sets

Python · part of the free zero-to-hero guide

Builds on: Functions and default arguments

Lists ([]) are ordered, mutable sequences — you can append, insert, remove, and reorder items after creation. Tuples (()) are ordered but immutable — once created, their contents can't change, which makes them useful for fixed collections like coordinates, and safe to use as dictionary keys since they're hashable when their contents are.

Dictionaries ({} with key: value pairs) map keys to values and, since Python 3.7, preserve insertion order as a guaranteed language feature rather than an implementation detail. Sets ({} without key:value pairs, or set() for an empty one) hold unique, unordered values and are built for fast membership testing and mathematical set operations.

Choosing the right collection type communicates intent to anyone reading the code: a tuple signals 'this is a fixed record that won't change,' a set signals 'duplicates don't matter, only membership does,' and a dict signals 'I'm looking things up by a key,' not by position.

Dictionary keys must be hashable — strings, numbers, and tuples of hashable items all work, but a list or another dict cannot be used as a key because they're mutable and their hash would change if their contents did. This same rule applies to what you can put inside a set.

List, dict, and set comprehensions ([x*2 for x in nums], {k: v*2 for k, v in prices.items()}, {x for x in nums if x > 0}) are the idiomatic, often faster alternative to building a collection with a manual loop and .append() calls — they read as 'build this collection from that source, optionally filtered.'

Nesting these types is common and powerful — a list of dicts is the natural Python shape for a list of database records or API results, and a dict of lists is a natural way to group items by category. Just be careful copying nested structures: assigning b = a doesn't copy a list, it creates a second name pointing at the same object, so mutating b mutates a too — use a.copy() or the copy module's deepcopy for nested structures.

collections.py
fruits = ["apple", "banana", "cherry"]  # list
point = (3, 4)                          # tuple
user = {"name": "Amina", "age": 27}     # dict
unique_tags = {"python", "web", "python"} # set, dedupes automatically

print(fruits[0], user["name"], len(unique_tags))
comprehensions.py
nums = [1, 2, 3, 4, 5, 6]

squares = [n * n for n in nums]                  # [1, 4, 9, 16, 25, 36]
evens = [n for n in nums if n % 2 == 0]           # [2, 4, 6]
by_parity = {n: ("even" if n % 2 == 0 else "odd") for n in nums}
unique_remainders = {n % 3 for n in nums}         # {0, 1, 2}

print(squares, evens, by_parity, unique_remainders)
copy_gotcha.py
original = ["a", "b", "c"]
alias = original          # NOT a copy -- same list, two names
alias.append("d")
print(original)           # ['a', 'b', 'c', 'd']  -- original changed too!

real_copy = original.copy()   # or list(original), or original[:]
real_copy.append("e")
print(original)               # unchanged by the copy
Key points
  • Lists are mutable and ordered; tuples are immutable and ordered; sets are mutable but unordered and deduplicated.
  • Dictionaries preserve insertion order (guaranteed since Python 3.7) and map keys to values for fast lookup by key.
  • Dictionary keys — and set members — must be hashable — strings, numbers, and tuples of hashable items work, but lists and dicts can't be used as keys.
  • List/dict/set comprehensions are the idiomatic, often faster alternative to building a collection with a manual loop.
  • Use .get(key, default) on a dict to avoid a KeyError when a key might not exist, and dict.setdefault() to fill in a default only if the key is missing.
  • Assigning one list to another name (b = a) doesn't copy it — both names point at the same object, so mutating one mutates the other.
  • collections.Counter and collections.defaultdict solve two very common dict patterns (counting things, grouping things) without manual boilerplate.
  • Sets support real set algebra: a | b (union), a & b (intersection), a - b (difference).
