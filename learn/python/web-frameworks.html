03 Advanced stage

Web frameworks: Flask/FastAPI (or Django) fundamentals

Python · part of the free zero-to-hero guide

Builds on: Testing with pytest

Flask and FastAPI are lightweight frameworks — you assemble the pieces you need rather than getting everything bundled in from the start. FastAPI additionally generates automatic interactive API docs (via Swagger/OpenAPI) and validates request data using ordinary Python type hints, making it a strong default for building JSON APIs today. Django is a full 'batteries-included' framework with a built-in ORM, admin panel, authentication, and templating out of the box.

All three use route decorators or URL patterns to map incoming requests to Python functions — a route is really just a mapping from an HTTP method and a URL path to the function that should handle it, and the framework's job is to parse the incoming request, call the right function, and turn its return value back into an HTTP response.

FastAPI's biggest practical advantage is how it uses type hints not just for editor autocomplete, but as real, enforced request validation: declaring a parameter as user_id: int means FastAPI automatically rejects a non-numeric value with a structured 422 error, without you writing any validation logic by hand. Pydantic models extend the same idea to entire JSON request bodies with nested fields.

Django's ORM lets you describe database tables as Python classes and query them with Python method calls instead of raw SQL — User.objects.filter(active=True) instead of a hand-written SELECT statement — and its migrations system tracks and applies schema changes over time, which Flask and FastAPI leave entirely up to you to add via a separate library like SQLAlchemy and Alembic.

Choose based on the project's actual shape: FastAPI or Flask for a focused API, a microservice, or something where you want full control over which pieces you include; Django when you want a complete, opinionated toolkit — auth, admin, ORM, forms — for a larger application where minimizing setup decisions matters more than flexibility.

Whichever framework you pick, the same core concepts carry over: request/response objects, route parameters versus query parameters versus request bodies, middleware that runs before or after every request, and dependency injection (explicit in FastAPI, more implicit in Django and Flask) for things like database sessions and authenticated users.

main.py (FastAPI)
from fastapi import FastAPI

app = FastAPI()

@app.get("/users/{user_id}")
def get_user(user_id: int):
    return {"id": user_id, "name": "Amina"}

# Run with: uvicorn main:app --reload
main.py (FastAPI + Pydantic body validation)
from fastapi import FastAPI
from pydantic import BaseModel

app = FastAPI()

class UserIn(BaseModel):
    name: str
    age: int

@app.post("/users")
def create_user(user: UserIn):
    # user.name and user.age are already validated and typed
    return {"created": user.name, "age": user.age}
app.py (Flask, for comparison)
from flask import Flask, jsonify, request

app = Flask(__name__)

@app.get("/users/<int:user_id>")
def get_user(user_id):
    return jsonify({"id": user_id, "name": "Amina"})

@app.post("/users")
def create_user():
    data = request.get_json()   # no automatic validation, unlike FastAPI
    return jsonify({"created": data["name"]}), 201

# Run with: flask --app app run
Key points
  • FastAPI generates interactive Swagger docs automatically from your route type hints — a real productivity win.
  • Flask is more minimal and flexible; Django is more complete and opinionated, with a steeper but more guided learning curve.
  • All three use route decorators or URL patterns to map incoming requests to Python functions.
  • Type hints in FastAPI routes double as automatic request validation — invalid input returns a 422 error without you writing that logic.
  • Pydantic models let FastAPI validate an entire nested JSON request body, not just individual path or query parameters.
  • Django's ORM and migrations system are built in; Flask and FastAPI leave database tooling to a separate library like SQLAlchemy.
  • Choose Flask/FastAPI for a focused API with full control over the pieces; choose Django for a larger app where an opinionated, complete toolkit saves setup time.
Try it yourself

Build a small FastAPI (or Flask) app with two routes: one that returns a static JSON message, and one that accepts a path parameter and echoes it back. Then add a third route that accepts a POST body (using a Pydantic model if you're using FastAPI) and returns a confirmation including the data you received, and test all three routes with the framework's auto-generated docs or a tool like curl.
