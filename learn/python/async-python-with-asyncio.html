Async Python with asyncio

Python · part of the free zero-to-hero guide

Builds on: Generators and iterators

asyncio lets Python run many I/O-bound operations (network requests, file access, database queries) concurrently on a single thread, without the complexity of real multithreading — ideal when a program spends most of its time waiting on external systems, not actually computing.

An async def function is a coroutine; calling it doesn't run it immediately, it returns a coroutine object that must be awaited (or scheduled onto the event loop some other way) to actually execute. Forgetting the await keyword is a very common mistake — it produces a 'coroutine was never awaited' warning and the code inside simply never runs.

asyncio.gather() runs multiple coroutines concurrently and waits for all of them, and the total wait time ends up being roughly the longest single task rather than the sum of all of them, since they overlap while waiting on I/O. asyncio.run(main()) is the standard entry point that starts the event loop, runs the given coroutine to completion, and shuts the loop back down.

Async only helps with I/O-bound work; CPU-bound work (heavy number-crunching, image processing) doesn't release control back to the event loop on its own, so it blocks everything else that's supposed to be running concurrently. For genuinely CPU-bound work, multiprocessing (or running it in a thread/process pool via loop.run_in_executor) is the correct tool, not asyncio.

Mixing blocking, synchronous calls into async code stalls the entire event loop for everyone — calling the regular requests library or time.sleep() inside an async def function blocks the whole program, not just that one coroutine. Use async-compatible libraries (like httpx or aiohttp instead of requests, and asyncio.sleep() instead of time.sleep()) inside async functions.

Beyond gather, asyncio.wait_for(coro, timeout=5) adds a timeout to a single coroutine, and structured concurrency tools like asyncio.TaskGroup (added in Python 3.11) manage a group of tasks together, automatically canceling the rest of the group if one of them raises an exception — a safer default than manually tracking a list of tasks.

async_demo.py
import asyncio

async def fetch_data(name, delay):
    await asyncio.sleep(delay)
    return f"{name} done"

async def main():
    results = await asyncio.gather(
        fetch_data("A", 1),
        fetch_data("B", 2),
    )
    print(results)   # takes ~2s total, not ~3s

asyncio.run(main())
taskgroup_and_timeout.py
import asyncio

async def fetch(name, delay):
    await asyncio.sleep(delay)
    return name

async def main():
    try:
        result = await asyncio.wait_for(fetch("slow", 5), timeout=1)
    except asyncio.TimeoutError:
        print("gave up waiting")

    async with asyncio.TaskGroup() as tg:   # Python 3.11+
        tg.create_task(fetch("A", 1))
        tg.create_task(fetch("B", 1))
    print("both tasks finished")

asyncio.run(main())
blocking_mistake.py
import asyncio
import time

async def bad():
    time.sleep(2)   # BLOCKS the entire event loop -- nothing else runs
    return "done"

async def good():
    await asyncio.sleep(2)  # yields control back to the event loop
    return "done"
Key points
  • asyncio.gather() runs multiple coroutines concurrently — the total wait time is close to the longest single task, not the sum of all of them.
  • asyncio.run(main()) is the standard entry point for starting an asyncio program.
  • Calling an async def function returns a coroutine object; forgetting await means the code inside never actually runs.
  • Async only helps with I/O-bound work; CPU-bound work needs multiprocessing instead, since it doesn't release control back to the event loop.
  • Blocking calls (time.sleep(), the plain requests library) inside async code stall the entire event loop, not just the current coroutine.
  • Use async-compatible libraries (like httpx instead of requests) and asyncio.sleep() instead of time.sleep() inside async functions.
  • asyncio.wait_for() adds a timeout to a coroutine; asyncio.TaskGroup (3.11+) manages a group of tasks with structured error handling.
Try it yourself

Write two async functions that each sleep for a different duration, then run them concurrently with asyncio.gather and confirm the total time equals the longer one, not the sum. Then write a third version using time.sleep() by mistake instead of asyncio.sleep() inside an async function, run it alongside another coroutine, and observe that they no longer overlap.
