01 Zero stage capstone

Your résumé, built by hand in raw HTML

HTML · ties together everything in the Zero stage

Every one of the five Zero-stage topics — elements and attributes, document structure, headings and lists, links and images, and basic forms — exists to serve one goal: turning plain information into a structured page a browser can render correctly. This project forces you to use all five together, on content you actually care about: your own résumé.

You are not allowed to use any CSS or JavaScript for this project. That constraint is deliberate. With no styling to lean on, the only thing making your page readable is correct, meaningful HTML structure — which is exactly the skill this stage is testing.

By the end, you'll have a single self-contained .html file you can open directly in a browser, with no build step and no server required.

  • Elements, tags, and attributes
  • Document structure: <!DOCTYPE>, head, body
  • Headings, paragraphs, lists
  • Links and images
  • Basic forms: input, button, label
Requirements
  • A complete, valid document: <!DOCTYPE html>, an <html> element with a lang attribute, a <head> with a <title>, and a <body>.
  • A single <h1> with your name, followed by a logical heading hierarchy (<h2> for each résumé section — Experience, Education, Skills, etc.) with no skipped levels.
  • At least one ordered or unordered list (your skills, or bullet points under a job).
  • A working mailto: link for your email and at least one link to an external profile (e.g. LinkedIn or GitHub), both using real anchor text — never "click here".
  • One image: a headshot or a small icon, with meaningful alt text.
  • A simple contact form at the bottom with at least a text input, an email input, a textarea, and a submit button — it doesn't need to actually send anywhere yet.
Suggested approach
  1. Start with just the document skeleton and get it opening cleanly in a browser before adding any content.
  2. Add your name and section headings first, so the page's outline is correct before you fill in details.
  3. Fill in each section's content using the right list or paragraph elements — resist the urge to just dump text into a single <div>.
  4. Add the image and links last, since they're the easiest to get wrong (missing alt, broken href) and easiest to spot-check once everything else is in place.
  5. Build the form last, checking that every input has an associated <label>.
Stretch goals
  • Validate your finished page with the W3C Markup Validator and fix every warning, not just the errors.
  • Add semantic landmark elements (<header>, <main>, <footer>) even though you haven't formally covered them yet — see how far you can get by reading MDN.
  • Try opening your page with images disabled and confirm your alt text alone tells the story.
