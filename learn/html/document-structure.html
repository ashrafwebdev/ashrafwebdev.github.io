Document structure: <!DOCTYPE>, head, body

HTML · part of the free zero-to-hero guide

Every HTML document starts with the same skeleton. <!DOCTYPE html> tells the browser "treat this as modern HTML5," not some ancient dialect. Then a single <html> element wraps everything else, split into two children: <head> and <body>.

The <head> holds information about the page — its title, character encoding, linked stylesheets, and metadata — none of which is directly visible on the page itself. The <body> holds everything the visitor actually sees and interacts with.

Two tags inside <head> matter from day one: <meta charset="UTF-8"> so text and emoji render correctly, and <title>, which sets the browser tab text and the default search-result headline. Order matters slightly here: <meta charset> should be one of the very first tags inside <head>, because the browser needs to know the encoding before it can correctly parse any non-ASCII characters that appear later in the document.

Without a <!DOCTYPE>, older browsers fall back to "quirks mode," an intentionally bug-compatible rendering mode that reproduces decades-old layout inconsistencies from Internet Explorer. Modern browsers all support the short HTML5 doctype, so there's never a reason to use the long, XHTML-style doctypes you might see in old tutorials.

The <html> tag itself should carry a lang attribute, such as lang="en". This single attribute tells screen readers which pronunciation rules to use, tells browsers which language to offer to translate from, and helps search engines serve the right page to the right audience — it costs nothing and is easy to forget.

A well-known but often skipped detail: everything visible on the page must live inside <body>. Text or images accidentally placed inside <head>, or outside the <html> element entirely, get silently moved or dropped by the browser's error-correcting parser — which is exactly the kind of "it works but I don't know why" bug that a clear mental model of head vs. body prevents.

index.html
<!DOCTYPE html>
<html lang="en">
<head>
  <meta charset="UTF-8">
  <title>My First Page</title>
</head>
<body>
  <p>Hello, world!</p>
</body>
</html>
a more complete head
<!DOCTYPE html>
<html lang="en">
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1.0">
  <title>My Recipe Blog</title>
  <link rel="stylesheet" href="styles.css">
</head>
<body>
  <p>Hello, world!</p>
</body>
</html>
what NOT to do
<!-- Wrong: text placed inside <head>, browsers will drop or relocate it -->
<head>
  <title>Broken Page</title>
  Welcome to my site!
</head>

<!-- Right: visible content always belongs in <body> -->
<head>
  <title>Fixed Page</title>
</head>
<body>
  Welcome to my site!
</body>
Key points
  • <!DOCTYPE html> must be the very first line of the file.
  • <head> = metadata (invisible), <body> = content (visible).
  • Always set <meta charset="UTF-8"> near the top of <head> — it prevents garbled text.
  • The lang attribute on <html> helps screen readers, translation tools, and search engines.
  • Skipping the doctype triggers legacy "quirks mode" rendering in some browsers — always include it.
  • The short HTML5 doctype is the only one you need; ignore old XHTML-style doctypes from older tutorials.
  • Visible content placed outside <body> gets silently relocated or dropped by the browser's parser.
Try it yourself

Save the example above as index.html and open it directly in your browser (double-click the file). Change the title and confirm the browser tab updates. Then add a lang attribute, a viewport meta tag, and deliberately move a sentence of text into the head to see how your browser's dev tools "fix" the resulting DOM.
