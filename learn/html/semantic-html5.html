Semantic HTML5: header, nav, main, article, section, footer

HTML · part of the free zero-to-hero guide

Before HTML5, everything was a <div> — the browser (and screen readers, and search engines) had no idea which div was the navigation and which was the footer. Semantic elements fix that by naming the role directly: <header>, <nav>, <main>, <article>, <section>, <aside>, and <footer>.

Use <main> exactly once for the page's primary content. Use <article> for something that would make sense on its own (a blog post, a product card); use <section> for a thematic grouping within a page that has its own heading.

index.html
<header>
  <h1>My Blog</h1>
  <nav><a href="/">Home</a> <a href="/about">About</a></nav>
</header>

<main>
  <article>
    <h2>My First Post</h2>
    <p>Post content goes here...</p>
  </article>
</main>

<footer>
  <p>&copy; 2026 My Blog</p>
</footer>
Key points
  • One <main> per page — it's a landmark screen reader users can jump straight to.
  • <article> = stands alone; <section> = part of a larger whole with its own heading.
  • <nav> should wrap primary navigation links, not every group of links on the page.
  • Semantic tags replace <div class="header">-style guessing with names browsers understand.
