Semantic HTML5: header, nav, main, article, section, footer

HTML · part of the free zero-to-hero guide

Builds on: Basic forms: input, button, label

Before HTML5, everything was a <div> — the browser (and screen readers, and search engines) had no idea which div was the navigation and which was the footer. Semantic elements fix that by naming the role directly: <header>, <nav>, <main>, <article>, <section>, <aside>, and <footer>.

Use <main> exactly once for the page's primary content. Use <article> for something that would make sense on its own (a blog post, a product card); use <section> for a thematic grouping within a page that has its own heading.

The distinction between <article> and <section> trips people up constantly, and a useful test is: could this chunk of content be pulled out and syndicated on its own (an RSS feed entry, a standalone card) and still make complete sense? If yes, it's an <article>. If it's just one themed part of a bigger page — a "Features" block on a landing page, say — it's a <section>, and per spec it should have its own heading so it can appear correctly in a page's accessibility outline.

<header> and <footer> aren't limited to the top and bottom of the whole page — they can appear once per <article> too. A blog post's <article> commonly has its own inner <header> holding the title and publish date, distinct from the page-level <header> holding the site logo and main navigation.

<aside> marks content that's tangentially related to the surrounding content but not essential to it — a pull quote, a "related articles" list, or a sidebar of ads. It's meant to be safely skippable, which is exactly the signal it gives assistive technology.

None of these tags change how content looks by default — most render like a plain block-level <div> visually. Their entire value is the meaning they add to the document's structure: a screen reader user can pull up a landmark list and jump straight to <main> or <nav> instead of tabbing through the entire page from the top, and a search engine can better understand which part of the page is the actual content worth indexing.

index.html
<header>
  <h1>My Blog</h1>
  <nav><a href="/">Home</a> <a href="/about">About</a></nav>
</header>

<main>
  <article>
    <h2>My First Post</h2>
    <p>Post content goes here...</p>
  </article>
</main>

<footer>
  <p>&copy; 2026 My Blog</p>
</footer>
a page with sections, an article header, and an aside
<main>
  <section aria-labelledby="features-heading">
    <h2 id="features-heading">Features</h2>
    <p>Fast, simple, and free.</p>
  </section>

  <article>
    <header>
      <h2>My First Post</h2>
      <p>Published <time datetime="2026-08-01">August 1, 2026</time></p>
    </header>
    <p>Post content goes here...</p>
  </article>

  <aside>
    <h2>Related posts</h2>
    <ul>
      <li><a href="/post-2">My Second Post</a></li>
    </ul>
  </aside>
</main>
Key points
  • One <main> per page — it's a landmark screen reader users can jump straight to.
  • <article> = stands alone and could be syndicated on its own; <section> = part of a larger whole with its own heading.
  • <nav> should wrap primary navigation links, not every group of links on the page.
  • <header> and <footer> can be nested inside an <article>, not just at the page level.
  • <aside> marks tangential content that's safe for a reader to skip.
  • Semantic tags replace <div class="header">-style guessing with names browsers and assistive tech actually understand.
  • These tags carry no default visual styling of their own — their value is entirely structural and semantic.
