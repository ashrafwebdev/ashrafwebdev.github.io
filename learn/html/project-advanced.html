03 Advanced stage capstone

A full accessibility audit and remediation of an existing site

HTML · ties together everything in the Advanced stage

This is a different kind of project: instead of building something from scratch, you're auditing and fixing a real page — either your own site from the Learning-stage project, or (with permission) a small public site. Auditing other people's code is a distinct and valuable skill from writing your own.

You'll use both manual review and automated tooling, because they catch different classes of problems: automated tools are good at catching missing attributes and contrast failures, but only a human (or a screen reader) can tell you whether the experience actually makes sense.

  • ARIA roles and advanced accessibility patterns
  • Web Components basics (custom elements, templates, slots)
  • Structured data (schema.org / JSON-LD) for rich search results
  • Performance: lazy loading, preloading, resource hints
  • Progressive enhancement principles
Requirements
  • Run an automated audit (e.g. Lighthouse or axe DevTools) on the page and record every issue it reports, categorized by severity.
  • Manually navigate the entire page using only a keyboard — document every place focus gets lost, trapped, or lands somewhere with no visible focus indicator.
  • Turn on a screen reader (VoiceOver, NVDA, or a browser extension) and navigate the page by headings and landmarks only — note anywhere the announced content doesn't match what's visually there.
  • Fix every issue you found: add missing ARIA roles/labels, correct heading hierarchy, fix color-contrast failures, and add visible focus styles where missing.
  • Write up a short before/after report: what was broken, why it mattered, and what you changed.
Suggested approach
  1. Run the automated tool first — it's the fastest way to get a baseline list of concrete issues to work through.
  2. Do the keyboard-only pass next, since keyboard-trap bugs are often the most severe and the easiest to reproduce reliably.
  3. Do the screen-reader pass last, since it takes the most practice to interpret correctly — go slowly and take notes as you go.
  4. Fix issues in order of severity: keyboard traps and missing form labels first, then heading structure, then contrast and cosmetic ARIA issues.
  5. Re-run the automated audit at the end to confirm your fixes actually resolved the flagged issues and didn't introduce new ones.
Stretch goals
  • Fix a color-contrast failure by adjusting your CSS custom properties rather than hardcoding new colors, so the fix is systematic.
  • Add a "skip to main content" link and verify it actually works for a keyboard-only user.
  • Write custom Web Component wrapping a common accessibility pattern (like an accessible disclosure/accordion) and use it on the audited page.
