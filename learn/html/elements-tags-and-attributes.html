Elements, tags, and attributes

HTML · part of the free zero-to-hero guide

Every HTML page is built out of elements. An element usually has an opening tag, some content, and a closing tag — <p>Hello</p> is a paragraph element containing the text "Hello". The tag name (p, a, img, div...) tells the browser what kind of thing this is, not how it should look.

Tags can carry extra information called attributes, written inside the opening tag as name="value" pairs. An image needs a src attribute to know which file to load; a link needs an href to know where to go. Some elements, like <img> and <br>, never have closing tags or content — they're called void elements, and writing a slash before the closing angle bracket (<br />) is optional in HTML5, purely a style choice left over from XHTML.

Not every attribute needs a value. Boolean attributes like disabled, checked, and required are "on" simply by being present in the tag at all — writing disabled="false" does not turn a control back on, because the attribute is still present. To turn a boolean attribute off you have to remove it entirely, which is a common source of confusion for beginners.

Beyond the attributes a specific tag defines, every HTML element accepts a set of global attributes: id (a unique identifier for that one element on the page), class (one or more space-separated hooks for CSS or JavaScript), style (inline CSS, best used sparingly), and title (a tooltip shown on hover). Custom data-* attributes let you attach your own extra information to an element — data-user-id="42" — which JavaScript can read back through element.dataset.userId.

Tag and attribute names are case-insensitive in HTML — <DIV> and <div> behave identically — but the near-universal convention is lowercase, and mixing cases makes markup harder to scan. Attribute values, by contrast, are almost always wrapped in double quotes; browsers tolerate single quotes or even unquoted values in simple cases, but quoting consistently avoids subtle bugs once a value contains a space.

Elements must be properly nested: if you open <b> inside <p>, you must close </b> before you close </p>, not after. Browsers are famously forgiving about broken markup — they'll silently guess what you meant and fix it while rendering — but relying on that behavior produces pages that look fine in one browser and break subtly in another. Getting comfortable reading and writing this element-attribute-content pattern correctly is the single most important HTML skill; everything else in HTML is just more elements and more attributes.

index.html
<p>This is a paragraph.</p>
<a href="https://example.com">This is a link</a>
<img src="cat.jpg" alt="A sleeping cat">
<div class="card">A generic container with a class attribute</div>
boolean and data-* attributes
<!-- Boolean attribute: present = on. No value needed. -->
<input type="text" disabled>
<input type="checkbox" checked>

<!-- Custom data attribute: readable in JS as element.dataset.userId -->
<li data-user-id="42" class="user-row">Ada Lovelace</li>

<script>
  const row = document.querySelector('.user-row');
  console.log(row.dataset.userId); // "42"
</script>
common mistake: bad nesting
<!-- Wrong: <b> closes AFTER <p>, tags overlap instead of nesting -->
<p>This is <b>bold text</p></b>

<!-- Right: close tags in the reverse order you opened them -->
<p>This is <b>bold text</b></p>
Key points
  • An element = opening tag + content + closing tag (or a self-contained void tag like <img>).
  • Attributes go inside the opening tag and configure the element (href, src, class, id...).
  • Tag names describe meaning, not appearance — styling is CSS's job, not HTML's.
  • Boolean attributes (disabled, checked, required) are on by presence alone — remove them to turn them off.
  • Global attributes like id, class, and data-* work on every element, not just specific tags.
  • Attribute values are almost always wrapped in double quotes.
  • Tags nest like parentheses: close the innermost one first, in the reverse order you opened them.
Try it yourself

Create a single HTML file with one paragraph, one link to a site you like, and one image tag (it's fine if the image doesn't load — focus on the syntax). Then add a checkbox input with the checked boolean attribute and a list item carrying a custom data-* attribute, and use your browser's dev tools console to read that data attribute back with JavaScript.
