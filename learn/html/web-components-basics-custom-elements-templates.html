Web Components basics (custom elements, templates, slots)

HTML · part of the free zero-to-hero guide

Web Components let you define your own reusable HTML tags — like <user-card> — using plain browser APIs, no framework required. Three pieces work together: Custom Elements (defining the tag), the Shadow DOM (style/markup encapsulation), and <template>/<slot> (reusable markup with customizable content).

A custom element is a JavaScript class extending HTMLElement, registered with customElements.define(). Once registered, the browser treats your tag like any built-in one — including allowing it in your HTML before its JavaScript has even loaded, since custom elements "upgrade" in place once their definition arrives.

The class has a handful of lifecycle callbacks the browser calls automatically: connectedCallback() runs each time the element is inserted into the document (which can happen more than once if it's moved around the DOM), disconnectedCallback() runs on removal — the natural place to clean up event listeners or timers — and attributeChangedCallback() runs whenever an attribute listed in a static observedAttributes array changes, letting the component react to its own attributes being updated after the fact.

<template> holds inert markup — its contents are parsed by the browser but never rendered or run (scripts inside don't execute, images inside don't load) until you clone it into the live document with JavaScript. This makes it a clean, reusable stamp for a chunk of markup a component will use repeatedly.

Shadow DOM, attached with this.attachShadow({ mode: 'open' }), gives an element its own separate mini-document: CSS written inside the shadow root can't leak out to style the rest of the page, and the page's own CSS can't reach in and accidentally restyle the component's internals. This solves the classic "my component's class name collided with someone else's CSS" problem at the platform level, without needing a build-time CSS-in-JS or naming convention workaround.

<slot> is how a component accepts content from whoever is using it, similar to children in a framework component. An unnamed <slot> catches any direct children placed inside the custom element's tags; named slots (<slot name="footer"> paired with slot="footer" on the consumer's markup) let a component expose several distinct content areas at once, like a card with separate header, body, and footer slots.

A minimal custom element
class HelloBadge extends HTMLElement {
  connectedCallback() {
    this.innerHTML = `<strong>Hello, ${this.getAttribute('name')}!</strong>`;
  }
}
customElements.define('hello-badge', HelloBadge);

<!-- usage -->
<hello-badge name="World"></hello-badge>
template, shadow DOM, and a named slot
<template id="card-template">
  <style>
    .card { border: 1px solid #ccc; padding: 1rem; border-radius: 8px; }
  </style>
  <div class="card">
    <slot name="title">Untitled</slot>
    <slot></slot>
  </div>
</template>

<script>
  class InfoCard extends HTMLElement {
    connectedCallback() {
      const template = document.getElementById('card-template');
      const shadow = this.attachShadow({ mode: 'open' });
      shadow.appendChild(template.content.cloneNode(true));
    }
  }
  customElements.define('info-card', InfoCard);
</script>

<info-card>
  <h3 slot="title">Shipping Update</h3>
  <p>Your order shipped today.</p>
</info-card>
reacting to attribute changes
class HelloBadge extends HTMLElement {
  static get observedAttributes() { return ['name']; }

  attributeChangedCallback(attr, oldValue, newValue) {
    if (attr === 'name') {
      this.textContent = `Hello, ${newValue}!`;
    }
  }
}
customElements.define('hello-badge', HelloBadge);
Key points
  • Custom element names must contain a hyphen (my-widget, not widget) — this is a spec requirement to avoid clashing with future HTML tags.
  • connectedCallback() runs when the element is inserted into the page, and can run more than once.
  • attributeChangedCallback() only fires for attributes listed in a static observedAttributes array.
  • Shadow DOM scopes CSS so your component's styles can't leak out and page styles can't leak in.
  • <template> content is inert until cloned into the live document with JavaScript.
  • <slot> lets consumers of your component pass in their own markup, like children of a normal element.
  • Named slots (slot="name") let one component expose several distinct content areas at once.
Try it yourself

Build a hello-badge (or similarly named) custom element from scratch and use it three times on one page with different attribute values. Then build a second component using a template and Shadow DOM with two named slots (title and body), and verify in dev tools that CSS written inside its shadow root doesn't leak out to affect the rest of the page.
