Headings, paragraphs, lists

HTML · part of the free zero-to-hero guide

Builds on: Document structure: <!DOCTYPE>, head, body

Headings (<h1> through <h6>) create the outline of a page, from most important (h1) to least (h6). Use exactly one <h1> per page for its main title, and don't skip levels just to get a smaller font — that's what CSS is for. Screen reader users frequently navigate a page heading-by-heading, so a broken outline (jumping from h2 straight to h5) is a genuine usability problem, not just a style nitpick.

Paragraphs (<p>) hold blocks of text. A common beginner mistake is pressing Enter inside a paragraph to force a line break — HTML collapses ordinary whitespace and newlines into a single space, so that Enter key does nothing visually. If you actually need a line break within running text (like in a mailing address), use <br>, but reach for it sparingly; most spacing should come from CSS margins, not manual breaks.

Lists come in two flavors: <ul> for unordered (bulleted) lists and <ol> for ordered (numbered) lists — both contain one or more <li> (list item) elements. Choosing between them isn't just visual: use <ol> whenever the sequence itself carries meaning, like steps in a recipe or race rankings, and <ul> when the items could be reordered without losing meaning, like a shopping list.

Lists can be nested — an <li> can contain its own full <ul> or <ol> for sub-items, which is how outlines, nested menus, and table-of-contents structures are built. There's also a third, less common list type: <dl> (description list), which pairs <dt> (term) with <dd> (description) — a good fit for glossaries or key-value data like a spec sheet.

The <ol> element accepts a start attribute if a numbered list shouldn't begin at 1, and a reversed boolean attribute to count downward — handy for countdowns or "top 10" style lists ordered from #10 down to #1.

Semantically, headings and lists are not interchangeable with visually similar-looking markup. A row of <div>s styled to look like a bulleted list is invisible to a screen reader as a list — it announces nothing about item count or position. Choosing the right tag for the right structure is what makes a page usable by tools other than a mouse and a pair of eyes.

index.html
<h1>My Recipe Blog</h1>
<h2>Today's Recipe: Pancakes</h2>
<p>These pancakes come out fluffy every time.</p>

<h3>Ingredients</h3>
<ul>
  <li>2 cups flour</li>
  <li>2 eggs</li>
  <li>1.5 cups milk</li>
</ul>

<h3>Steps</h3>
<ol>
  <li>Mix dry ingredients</li>
  <li>Add eggs and milk</li>
  <li>Cook on a griddle</li>
</ol>
nested lists and a description list
<h3>Ingredients by section</h3>
<ul>
  <li>Dry
    <ul>
      <li>2 cups flour</li>
      <li>1 tsp baking powder</li>
    </ul>
  </li>
  <li>Wet
    <ul>
      <li>2 eggs</li>
      <li>1.5 cups milk</li>
    </ul>
  </li>
</ul>

<dl>
  <dt>Prep time</dt>
  <dd>10 minutes</dd>
  <dt>Cook time</dt>
  <dd>15 minutes</dd>
</dl>
ol start and reversed
<h3>Top 3 Finishers</h3>
<ol start="3" reversed>
  <li>Casey</li>
  <li>Priya</li>
  <li>Sam</li>
</ol>
<!-- Renders as: 3. Casey, 2. Priya, 1. Sam -->
Key points
  • One <h1> per page; use h2-h6 to nest sub-sections logically, without skipping levels.
  • Never pick a heading level for its default font size — that's a CSS decision.
  • <ul> = bullets, <ol> = numbers, <li> = each item in either.
  • Use <ol> when order carries meaning; use <ul> when it doesn't.
  • Lists can be nested inside list items for sub-lists.
  • <dl>/<dt>/<dd> is the right structure for term-description or key-value content.
  • Pressing Enter inside a paragraph doesn't create a line break in the rendered output — whitespace collapses.
Try it yourself

Build a page for your favorite recipe: an h1 title, a short paragraph description, an unordered list of ingredients (nested into dry/wet sub-lists), and an ordered list of steps. Add a description list summarizing prep time and cook time, and try the reversed attribute on a small top-3 list to see how the numbering changes.
