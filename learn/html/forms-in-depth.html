Forms in depth: validation attributes, input types, select/textarea

HTML · part of the free zero-to-hero guide

Beyond basic text inputs, HTML gives you a full toolkit: <select> for dropdowns, <textarea> for multi-line text, and input types like date, number, tel, and checkbox/radio for structured choices.

Validation attributes let the browser catch obvious mistakes before anything is submitted: required, minlength/maxlength, min/max for numbers, and pattern for a custom regular expression. This is a first line of defense — always validate again on the server too, since anyone can submit a request that bypasses the browser entirely with a tool like curl.

Radio buttons and checkboxes behave differently even though they look similar: radio buttons sharing the same name form a mutually exclusive group where only one can be checked, while checkboxes with the same name let multiple be checked at once and are typically submitted as an array-like set of values. A common bug is forgetting to give every radio button in a group the identical name, which silently breaks the exclusivity.

<select> elements need a value on each <option> — if you omit it, the browser falls back to using the option's visible text as the value, which is rarely what you want once that text needs to change for wording reasons without breaking whatever consumes the submitted data. Options can also be grouped visually with <optgroup label="...">, and the multiple attribute turns a dropdown into a multi-select list.

The browser's built-in validation UI (that little "Please fill out this field" bubble) is convenient but limited — it can't easily be restyled to match your design, and its wording isn't translated automatically. Many real-world forms disable it with the novalidate attribute on <form> and implement custom validation messages with the Constraint Validation API in JavaScript, while still keeping the HTML validation attributes in place as a fallback and for basic accessibility.

Two attributes worth knowing beyond the basics: placeholder shows greyed-out example text inside an empty input, but it disappears the moment the user types and is never a substitute for a real <label> — screen readers and low-vision users lose that hint entirely once typing starts. autocomplete, set to values like "email" or "given-name", lets the browser correctly offer to autofill a field from saved data, which meaningfully speeds up checkout and signup forms.

index.html
<label for="plan">Choose a plan</label>
<select id="plan" name="plan">
  <option value="basic">Basic</option>
  <option value="pro">Pro</option>
</select>

<label for="age">Age</label>
<input type="number" id="age" name="age" min="13" max="120" required>

<label for="bio">Short bio</label>
<textarea id="bio" name="bio" maxlength="200"></textarea>
radio group, checkboxes, and pattern validation
<fieldset>
  <legend>Preferred contact method</legend>
  <input type="radio" id="contact-email" name="contact" value="email" checked>
  <label for="contact-email">Email</label>

  <input type="radio" id="contact-phone" name="contact" value="phone">
  <label for="contact-phone">Phone</label>
</fieldset>

<input type="checkbox" id="newsletter" name="newsletter" value="yes">
<label for="newsletter">Subscribe to the newsletter</label>

<label for="zip">US ZIP code</label>
<input type="text" id="zip" name="zip" pattern="[0-9]{5}" title="Five digits" required>
common mistake: mismatched radio names
<!-- Wrong: different names mean both can be selected at once,
     defeating the point of radio buttons -->
<input type="radio" name="size-a" value="small"> Small
<input type="radio" name="size-b" value="large"> Large

<!-- Right: identical name groups them into one exclusive choice -->
<input type="radio" name="size" value="small"> Small
<input type="radio" name="size" value="large"> Large
Key points
  • required, min/max, pattern give free client-side validation.
  • Client-side validation is a UX nicety, never a security boundary — always re-check on the server.
  • <select> options need a value; the visible text can differ from what's submitted.
  • Radio buttons need an identical name across the group to become mutually exclusive; checkboxes don't require exclusivity at all.
  • placeholder is not a replacement for <label> — it disappears once the user starts typing.
  • autocomplete values like "email" let browsers correctly offer saved-data autofill.
  • novalidate on <form> lets you replace the browser's default validation bubbles with custom messaging.
  • <textarea> sizes with rows/cols attributes or, better, CSS.
Try it yourself

Extend your contact form with an age number input (min 13), a subject dropdown with 3 options, a required message textarea with a max length, and a fieldset of radio buttons for preferred contact method. Test what happens when you submit with a missing required field, then add novalidate to the form and observe that the browser's default validation bubbles disappear.
