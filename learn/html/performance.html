Performance: lazy loading, preloading, resource hints

HTML · part of the free zero-to-hero guide

The browser doesn't have to load everything on a page immediately, and HTML gives you direct control over that. loading="lazy" on an <img> defers loading images that are off-screen until the user scrolls near them — a one-attribute performance win.

Resource hints go the other direction: <link rel="preload"> tells the browser to fetch something critical (a font, a hero image) as early as possible, and rel="preconnect" warms up a connection to another domain before you actually need it.

There's a full spectrum of resource hints beyond just those two, roughly ordered from cheapest to most aggressive: dns-prefetch only resolves a domain name in advance (the lightest possible hint), preconnect does that plus the full TCP and TLS handshake, prefetch downloads a resource likely needed for the next navigation at low priority, and preload downloads something needed on the current page at high priority. Reaching for the strongest hint everywhere is a common mistake — each one consumes real bandwidth and competes with everything else the browser is already trying to load.

loading="lazy" should never be applied to the largest image visible without scrolling (commonly called the hero image or LCP element) — deferring it delays the single metric, Largest Contentful Paint, that most directly affects how fast a page feels to load. That same hero image is often a great candidate for fetchpriority="high" instead, which tells the browser to fetch it before other same-priority resources on the page.

<script> tags have their own loading controls worth knowing alongside resource hints: a plain <script src="..."> blocks HTML parsing entirely until it downloads and runs, defer downloads in the background and runs after parsing finishes (in document order), and async downloads in the background and runs as soon as it's ready, which can be before or after parsing finishes and out of order relative to other scripts. Using defer on non-critical scripts is one of the simplest, most reliable performance wins available in plain HTML.

Iframes get the same lazy-loading treatment as images (<iframe loading="lazy">), which matters more than it might seem — a single embedded video or map iframe can weigh far more than the entire rest of the page combined, so deferring off-screen ones is often a bigger win than lazy-loading individual images.

index.html
<!-- Defer offscreen images -->
<img src="below-the-fold.jpg" alt="..." loading="lazy">

<!-- Preload something critical -->
<link rel="preload" href="/fonts/main.woff2" as="font" type="font/woff2" crossorigin>

<!-- Warm up a third-party connection -->
<link rel="preconnect" href="https://fonts.gstatic.com" crossorigin>
hero image priority and deferred scripts
<!-- The largest above-the-fold image: never lazy, boost priority instead -->
<img src="hero.jpg" alt="Fresh pancakes on a plate" fetchpriority="high">

<!-- Lightest hint: just resolve the DNS ahead of time -->
<link rel="dns-prefetch" href="https://analytics.example.com">

<!-- Non-critical script: download in background, run after parsing, in order -->
<script src="/js/comments-widget.js" defer></script>

<!-- Off-screen iframe: defer just like an image -->
<iframe src="https://maps.example.com/embed" loading="lazy" title="Store location map"></iframe>
common mistake: lazy-loading the hero image
<!-- Wrong: this is the first thing visible on the page —
     lazy-loading it delays what the user sees first -->
<img src="hero.jpg" alt="Fresh pancakes on a plate" loading="lazy">

<!-- Right: load it eagerly (the default) and prioritize it -->
<img src="hero.jpg" alt="Fresh pancakes on a plate" fetchpriority="high">
Key points
  • loading="lazy" is a native browser feature — no JavaScript library required.
  • Never lazy-load the hero image visible on first paint — that delays what the user sees first (and hurts Largest Contentful Paint).
  • preload is for things needed almost immediately; overusing it competes for bandwidth and backfires.
  • preconnect is cheap insurance for any third-party domain you know you'll fetch from soon; dns-prefetch is an even lighter version.
  • fetchpriority="high" can push your most important image ahead of same-priority resources.
  • defer and async on scripts avoid blocking HTML parsing — prefer defer for most non-critical scripts.
  • <iframe loading="lazy"> defers heavy embeds (maps, videos) the same way images do, often with a bigger payoff.
Try it yourself

Take a page with several images and add loading="lazy" to every image below the first screenful, then check the Network tab to confirm they load later. Add fetchpriority="high" to your hero image, switch any render-blocking script tags to defer, and compare the page's load waterfall in dev tools before and after.
