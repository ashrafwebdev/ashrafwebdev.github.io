01 Zero stage

Basic forms: input, button, label

HTML · part of the free zero-to-hero guide

Builds on: Links and images

Forms collect input from visitors. A <form> wraps one or more <input> elements, each with a type (text, email, password, checkbox...) that changes how the browser handles it. A <button> submits the form.

Every input should have a matching <label>. Connect them with the label's for attribute matching the input's id — this lets clicking the label focus the input, and it's essential for screen reader users, who otherwise hear only "edit text" with no idea what the field is for.

The name attribute is what actually gets sent to the server when the form submits — id is a separate concept used for labels, CSS, and JavaScript, and the two are easy to confuse when you're starting out. A field with an id but no name will render and label correctly but silently vanish from the submitted data.

Forms have two important attributes on the <form> tag itself: action, the URL the data is sent to, and method, either GET (appends data to the URL, visible and bookmarkable, fine for search boxes) or POST (sends data in the request body, the right choice for anything that changes data or includes sensitive information like a password).

There's a meaningful difference between the three button types: type="submit" (the default inside a form) submits the form, type="reset" clears all fields back to their initial values, and type="button" does nothing by itself and exists purely as a hook for JavaScript. Forgetting to set type="button" on a button meant only to trigger a script is a classic bug — it accidentally submits the form instead.

Even before any JavaScript is written, an HTML form with a real action and method is fully functional on its own, submitting a normal page request to the server. This matters more than it might seem: it means a form still works if a script fails to load, which is the foundation of the progressive enhancement approach covered later in this roadmap.

index.html
<form action="/submit-contact" method="POST">
  <label for="name">Your name</label>
  <input type="text" id="name" name="name">

  <label for="email">Your email</label>
  <input type="email" id="email" name="email">

  <button type="submit">Send</button>
</form>
three button types
<form action="/save" method="POST">
  <label for="nickname">Nickname</label>
  <input type="text" id="nickname" name="nickname">

  <button type="submit">Save</button>
  <button type="reset">Clear form</button>
  <button type="button" onclick="alert('Just a helper, does not submit')">Preview</button>
</form>
common mistake: id without name
<!-- Wrong: has an id for the label, but no name, so this
     field's value is silently dropped from the submitted data -->
<label for="nick">Nickname</label>
<input type="text" id="nick">

<!-- Right: name is what the server actually receives -->
<label for="nick">Nickname</label>
<input type="text" id="nick" name="nickname">
Key points
  • Always pair an <input> with a <label> connected via for/id.
  • The name attribute is what gets sent to the server — id alone is not enough.
  • type="email", type="number", etc. give free validation and better mobile keyboards.
  • <button type="submit"> submits; type="button" does nothing on its own; type="reset" clears the form.
  • Use method="POST" for anything that changes data or is sensitive; GET is fine for simple searches.
  • A form with a real action works even before any JavaScript runs.
Try it yourself

Build a simple contact form with fields for name, email, and a message (use a textarea for the message), each with a proper label, plus a real action and method="POST". Add a reset button and a plain type="button" that just shows an alert, and confirm in dev tools that only fields with a name attribute appear in the submitted form data.
