Generics and advanced LINQ

C# · part of the free zero-to-hero guide

Generics in C# work much like Java's: class Box of T defines a type parameter filled in at use time, with constraints (where T : IComparable) restricting what types can be used and unlocking operations on them that wouldn't otherwise be available on an unconstrained T. Common constraint kinds include where T : class (reference types only), where T : struct (value types only), where T : new() (requires a public parameterless constructor), and where T : SomeBaseType.

Unlike Java's generics, C#'s are reified at runtime — the actual type argument is known and available via reflection, and no boxing occurs for value-type type arguments, which is why List of int stores actual ints inline rather than boxed objects the way a pre-generics or non-generic collection would have to.

Generic methods can infer their type argument from the arguments passed, so you rarely need to write Method<int>(5) explicitly; the compiler figures out T from the call site. Generic classes and generic methods can each declare their own independent type parameters, and a generic method inside a non-generic class is a common way to write a single reusable algorithm that works across many types.

Beyond basic Where/Select, LINQ supports grouping (GroupBy), joining two sequences (Join), and aggregation (Sum, Average, Aggregate), letting fairly complex data transformations be expressed in a single declarative chain instead of nested loops with manual accumulator variables.

Aggregate is LINQ's general-purpose reduce/fold operation: it takes a seed value and a function combining the running result with each element, and can express sums, products, string concatenation, or any custom fold — though for the common cases, the dedicated Sum/Average/Max methods are clearer and should be preferred when they fit.

Combining generics with LINQ is common when writing reusable utility methods, such as a generic MaxBy-style helper that works across any collection of any comparable type; constraining T to IComparable of T lets the method call CompareTo on elements of that unknown type safely.

Program.cs
record Order(string Customer, decimal Amount);

var orders = new List<Order>
{
    new("Amina", 120), new("Bilal", 75), new("Amina", 40)
};

var totalsByCustomer = orders
    .GroupBy(o => o.Customer)
    .Select(g => new { Customer = g.Key, Total = g.Sum(o => o.Amount) });

foreach (var t in totalsByCustomer)
    Console.WriteLine($"{t.Customer}: {t.Total}");
GenericConstraints.cs
// T must implement IComparable<T>, so CompareTo is guaranteed to exist
static T Max<T>(IEnumerable<T> items) where T : IComparable<T>
{
    T best = items.First();
    foreach (var item in items.Skip(1))
        if (item.CompareTo(best) > 0) best = item;
    return best;
}

Console.WriteLine(Max(new[] { 3, 7, 2, 9, 1 }));      // 9
Console.WriteLine(Max(new[] { "pear", "apple", "fig" })); // pear

// where T : new() lets a generic method construct T itself
static T CreateDefault<T>() where T : new() => new T();
JoinAndAggregate.cs
record Customer(int Id, string Name);
record Purchase(int CustomerId, decimal Amount);

var customers = new List<Customer> { new(1, "Amina"), new(2, "Bilal") };
var purchases = new List<Purchase> { new(1, 50), new(1, 30), new(2, 20) };

var report = customers.Join(
    purchases,
    c => c.Id,
    p => p.CustomerId,
    (c, p) => new { c.Name, p.Amount });

foreach (var r in report) Console.WriteLine($"{r.Name}: {r.Amount}");

// Aggregate: general fold, here concatenating names with commas
string joined = customers.Aggregate("", (acc, c) =>
    acc.Length == 0 ? c.Name : acc + ", " + c.Name);
Console.WriteLine(joined);
Key points
  • Generic constraints like where T : IComparable of T restrict and enable behavior on a type parameter.
  • C# generics are reified at runtime — no boxing for value-type type arguments, unlike Java's type erasure.
  • Type arguments are usually inferred from call-site arguments, so explicit <T> syntax is rarely needed.
  • GroupBy groups a sequence by a key selector, producing groups you can then aggregate.
  • Join combines two sequences by matching keys, similar to a SQL inner join.
  • Aggregate is LINQ's general fold/reduce operation; prefer Sum/Average/Max when they fit.
  • Anonymous types (new { ... }) are handy for shaping intermediate LINQ query results.
  • where T : new() lets a generic method construct an instance of the unknown type T itself.
Try it yourself

Given a list of order records with Customer and Amount, use LINQ GroupBy and Sum to print the total amount spent per customer, sorted from highest to lowest. Then write a generic method called MaxBy, constrained to IComparable of T, that finds the largest element of any sequence, and test it against both a list of ints and a list of strings.
