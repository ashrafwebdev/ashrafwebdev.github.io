Working with files

C# · part of the free zero-to-hero guide

Builds on: Exception handling

The System.IO namespace's File class offers simple static methods for common operations: File.WriteAllText, File.ReadAllText, and File.ReadAllLines cover most small-file needs in a single call, and their Async counterparts (File.ReadAllTextAsync, etc.) do the same without blocking a thread, which matters in a web application handling many requests concurrently.

For larger files or streaming, StreamReader and StreamWriter let you process a file line by line without loading it entirely into memory, and both implement IDisposable so they pair naturally with a using block that guarantees the underlying file handle is released even if an exception occurs partway through.

The Path class provides platform-independent helpers for building and inspecting paths — Path.Combine, Path.GetExtension, Path.GetFileName — and should always be preferred over manually concatenating strings with / or \, since the correct separator differs between Windows and Unix-like systems.

Directory and DirectoryInfo cover folder-level operations: creating, deleting, listing files with Directory.GetFiles or EnumerateFiles (the latter streams results lazily instead of building a full array up front, which matters for very large directories), and checking existence before acting on a path.

File operations can throw exceptions like FileNotFoundException, UnauthorizedAccessException, or IOException (for instance when another process has the file locked), so production file code typically wraps these calls in a try/catch alongside the resource-safe using pattern rather than assuming a file will always be there and accessible.

For structured data, reading and writing JSON with System.Text.Json's JsonSerializer.Serialize/Deserialize is now built into the framework and is generally preferred over hand-rolled text parsing for anything beyond the simplest line-based formats.

Program.cs
string path = "notes.txt";
File.WriteAllText(path, "First line\nSecond line\n");

using (var reader = new StreamReader(path))
{
    string? line;
    while ((line = reader.ReadLine()) != null)
    {
        Console.WriteLine($"> {line}");
    }
}
PathsAndDirectories.cs
string folder = Path.Combine("data", "exports");
Directory.CreateDirectory(folder); // no-op if it already exists

string filePath = Path.Combine(folder, "report.txt");
File.WriteAllText(filePath, "quarterly totals\n");

foreach (var file in Directory.EnumerateFiles(folder, "*.txt"))
{
    Console.WriteLine(Path.GetFileName(file));
}
SafeFileAccess.cs
static string? TryReadConfig(string path)
{
    try
    {
        return File.ReadAllText(path);
    }
    catch (FileNotFoundException)
    {
        Console.WriteLine("Config missing, using defaults.");
        return null;
    }
    catch (UnauthorizedAccessException e)
    {
        Console.WriteLine($"No permission to read config: {e.Message}");
        return null;
    }
}
Key points
  • File.WriteAllText/ReadAllText are convenient for small, whole-file operations; their Async variants avoid blocking.
  • StreamReader/StreamWriter handle large files line by line without high memory use.
  • Both stream classes implement IDisposable and should be wrapped in a using block.
  • Path.Combine and friends handle platform-specific path separators correctly, unlike manual string concatenation.
  • Directory.EnumerateFiles streams results lazily, which scales better than GetFiles for huge directories.
  • File I/O can throw FileNotFoundException, UnauthorizedAccessException, or IOException; wrap it in try/catch when a file's existence or permissions aren't guaranteed.
  • System.Text.Json is the built-in, preferred way to read and write structured JSON data.
Try it yourself

Write a program that writes a list of names to a file one per line using StreamWriter, then reads it back with StreamReader and prints each name numbered. Then extend it to build the file path with Path.Combine into a subfolder you create with Directory.CreateDirectory, and wrap the read step in a try/catch that handles a missing file gracefully.
