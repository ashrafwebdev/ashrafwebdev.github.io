Collections and basic LINQ queries

C# · part of the free zero-to-hero guide

Builds on: OOP: inheritance, interfaces, polymorphism

Beyond List of T, C# offers Dictionary of TKey, TValue for key-value lookups and HashSet of T for unique unordered elements, mirroring the structures found in most modern languages' standard libraries. Dictionary lookups by key are on average O(1) thanks to hashing, dramatically faster than scanning a list with Contains once a collection grows large.

Accessing a missing key with the indexer (stock["grapes"]) throws a KeyNotFoundException; the safe alternatives are TryGetValue, which returns a bool and avoids both the exception and a double lookup, or ContainsKey followed by an indexer access (slightly less efficient since it looks the key up twice).

Queue of T (first-in, first-out) and Stack of T (last-in, first-out) round out the common generic collections, useful whenever an algorithm needs strict ordering guarantees rather than arbitrary indexed access.

LINQ (Language Integrated Query) lets you filter, transform, and aggregate any IEnumerable using either fluent method syntax (.Where(...).Select(...)) or SQL-like query syntax, both compiling down to the same operations. Method syntax is far more common in real-world C# code; query syntax mainly shows up when a join or multiple from clauses make it noticeably more readable.

LINQ methods are lazily evaluated by default, meaning a query isn't actually executed until you enumerate it (with foreach, ToList(), and similar). This matters for both performance (you can build up a complex query without doing any work until needed) and correctness — if the underlying collection changes between building the query and enumerating it, the results reflect the collection's state at enumeration time, which can surprise you if you expected a snapshot.

Methods like First, Single, and their ...OrDefault counterparts differ meaningfully: First throws if the sequence is empty, FirstOrDefault returns the type's default (null for reference types, 0 for numbers) instead, and Single additionally throws if there's more than one match, which makes it a useful assertion when you expect exactly one result.

Program.cs
var stock = new Dictionary<string, int>
{
    ["apples"] = 50,
    ["bananas"] = 30,
    ["cherries"] = 5
};

var lowStock = stock
    .Where(kv => kv.Value < 40)
    .Select(kv => kv.Key)
    .ToList();

Console.WriteLine(string.Join(", ", lowStock));
SafeLookupsAndSets.cs
var stock = new Dictionary<string, int> { ["apples"] = 50 };

// Safe lookup: no exception, no double lookup
if (stock.TryGetValue("grapes", out int count))
    Console.WriteLine($"Grapes: {count}");
else
    Console.WriteLine("No grapes in stock.");

var tags1 = new HashSet<string> { "fruit", "fresh", "local" };
var tags2 = new HashSet<string> { "fresh", "organic" };
tags1.IntersectWith(tags2);
Console.WriteLine(string.Join(", ", tags1)); // fresh
LazyEvaluationGotcha.cs
var numbers = new List<int> { 1, 2, 3 };
var query = numbers.Where(n => n > 1); // NOT executed yet

numbers.Add(4); // mutating the source before enumeration

foreach (var n in query) // executes now, sees the added 4
    Console.WriteLine(n); // prints 2, 3, 4

// First throws on empty; FirstOrDefault does not
var empty = new List<int>();
// empty.First();          // throws InvalidOperationException
int result = empty.FirstOrDefault(); // 0, no exception
Key points
  • Dictionary maps keys to values with average O(1) lookup; HashSet stores unique unordered items.
  • TryGetValue avoids both a KeyNotFoundException and a redundant lookup compared to checking ContainsKey first.
  • Queue and Stack provide strict FIFO/LIFO ordering when that's what an algorithm needs.
  • LINQ's fluent syntax chains operations like Where, Select, and OrderBy.
  • LINQ queries are lazily evaluated until enumerated with ToList, foreach, or similar — mutating the source beforehand affects the results.
  • First/Single throw on no match (or, for Single, more than one match); their OrDefault variants return a default instead.
  • Query syntax (from x in xs where ... select ...) is sugar over the same fluent methods, mostly used for joins.
