01 Zero stage

Syntax, variables, and types

C# · part of the free zero-to-hero guide

A C# program's entry point is a Main method, though modern top-level programs let you skip the surrounding class and method declarations entirely for small scripts — the compiler generates the boilerplate for you behind the scenes. C# is statically typed: every variable has a type known at compile time, whether declared explicitly (int age = 30;) or inferred with var. Static typing means the compiler catches a whole class of mistakes, like assigning a string to an int variable, before the program ever runs.

The built-in value types include int, double, bool, char, and decimal (preferred for money, since it avoids the binary floating-point rounding errors that double and float are prone to). Value types are stored inline — on the stack for local variables, or directly inside the containing object for fields — and assigning one variable to another copies the whole value.

Reference types like string, arrays, and your own classes are stored on the heap, and a variable of that type merely holds a reference (a pointer, conceptually) to the object. Assigning one reference-typed variable to another copies the reference, not the object, so both variables end up pointing at the same underlying data — a frequent source of confusion for beginners who expect copy semantics.

A subtlety worth internalizing early: string is a reference type but behaves as if it were immutable and value-like, because every string operation (concatenation, Substring, Replace) returns a brand-new string object rather than mutating the original. Building a string piece by piece in a loop with + therefore allocates a new string on every iteration; StringBuilder exists specifically to avoid that cost.

When a value type needs to be treated as an object (for example, passed to an old-style non-generic API), the runtime boxes it — copying the value onto the heap and wrapping it — and reading it back out is unboxing. Boxing is an easy-to-miss allocation cost, and it is one of the reasons generic collections like List of T are strongly preferred over their non-generic ancestors.

C# 8 introduced nullable reference types: when enabled (via #nullable enable or a project-wide setting), the compiler tracks whether a reference-typed variable is allowed to be null and warns when you dereference one that might be, catching a huge class of NullReferenceException bugs at compile time. This is purely a compile-time annotation system, though — it does not change runtime behavior, and a suppressed warning (using the ! null-forgiving operator) can still fail at runtime just like before.

Program.cs
int age = 30;
double price = 19.99;
bool active = true;
string name = "Yusuf";
var score = 95; // type inferred as int

Console.WriteLine($"{name} is {age} years old and scored {score}.");
ValueVsReference.cs
struct Point { public int X, Y; }
class Box { public int Value; }

Point p1 = new Point { X = 1, Y = 2 };
Point p2 = p1;      // copies the struct's fields
p2.X = 99;
Console.WriteLine(p1.X); // 1 -- p1 is untouched

Box b1 = new Box { Value = 1 };
Box b2 = b1;        // copies the reference, not the object
b2.Value = 99;
Console.WriteLine(b1.Value); // 99 -- same object as b2
BoxingPitfall.cs
// Boxing: the int is copied onto the heap and wrapped as an object
int number = 42;
object boxed = number;      // boxing (allocation!)
int unboxed = (int)boxed;   // unboxing

// Nullable value types use Nullable<T> under the hood
int? maybeAge = null;
if (maybeAge.HasValue)
    Console.WriteLine(maybeAge.Value);
else
    Console.WriteLine("No age set");
Key points
  • Top-level programs let small C# scripts skip the explicit class/Main boilerplate.
  • var infers a type at compile time; it is still statically typed, not dynamic.
  • decimal is preferred over double for currency to avoid rounding errors.
  • Value types copy their data on assignment; reference types copy the reference, sharing the same object.
  • Strings are immutable reference types — every modification produces a new object, so use StringBuilder for heavy concatenation.
  • Boxing copies a value type onto the heap when it's used as an object; it's an easy-to-miss allocation cost.
  • Nullable reference types are a compile-time warning system, not a runtime guarantee — the null-forgiving operator ! can still let a null through.
  • int? is shorthand for Nullable of T, a distinct mechanism from nullable reference types.
Try it yourself

Write a top-level C# program that declares an int, a decimal, and a string, then prints them together using string interpolation. Then add a small struct and a small class with the same shape (a single int field), copy each into a second variable, mutate the copy, and print both originals to demonstrate the difference between value and reference semantics.
