Performance and memory tuning

C# · part of the free zero-to-hero guide

.NET's garbage collector manages heap memory in generations: short-lived objects are collected cheaply and often from generation 0, while long-lived objects get promoted to generation 1 and 2, which are collected less frequently, based on the same "most objects die young" observation used across managed runtimes.

The Span of T and Memory of T types let you work with contiguous memory (arrays, strings, stack-allocated buffers) without extra allocations or copies, which matters a great deal in performance-sensitive parsing or I/O code.

Tools like dotnet-trace and Visual Studio's profiler measure real allocation and CPU hotspots; as with any language, the right first step in tuning is always profiling to find the actual bottleneck, not guessing.

terminal
$ dotnet-trace collect --process-id <pid>

# Span<T> avoids an allocation when slicing a string
ReadOnlySpan<char> span = "hello world".AsSpan();
ReadOnlySpan<char> word = span.Slice(0, 5);
Key points
  • The GC organizes the heap into generations, collecting short-lived objects far more often.
  • Span of T lets you slice and process memory without extra allocations.
  • Profile with tools like dotnet-trace before changing code for performance reasons.
  • Reducing allocations in hot paths is often the highest-leverage .NET performance win.
