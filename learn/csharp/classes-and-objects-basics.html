Classes and objects basics

C# · part of the free zero-to-hero guide

Builds on: Control flow and methods

A C# class groups fields and methods together, and objects are created from it with new. Properties (public string Name { get; set; }) are C#'s idiomatic way to expose state, offering the syntax of a field with the control of a method underneath — you can add validation logic in a custom set accessor without changing how callers use the property.

Constructors initialize an object's state when created, and a class can define several overloaded constructors for different initialization scenarios; one constructor can call another with : this(...) to avoid duplicating setup logic. C# also supports record types (record Person(string Name, int Age)), a concise syntax for immutable data-holding classes that automatically get value-based equality, a readable ToString, and a with expression for creating a modified copy.

The this keyword refers to the current instance, most often used inside a constructor to distinguish a field from a same-named parameter, but also usable to pass the current object to another method or to chain constructors.

Access modifiers control visibility: public members are visible everywhere, private (the default for fields) only within the same class, protected also to derived classes, and internal only within the same assembly. Choosing the narrowest modifier that still works is a core encapsulation habit — exposing a mutable field publicly instead of a property removes your ability to change the implementation later without breaking callers.

Auto-implemented properties can be read-only from outside the class using { get; private set; } or fully immutable using { get; init; }, the latter allowing the property to be set only during object initialization (including with object-initializer syntax), which is a lighter-weight alternative to a full record when you still want a class.

Static members (static fields and methods) belong to the type itself rather than any instance, and are shared across every use of the class — useful for utility methods or counters, but a source of hidden shared state and testing difficulty if overused.

Program.cs
public class Book
{
    public string Title { get; set; }
    public int Pages { get; set; }

    public Book(string title, int pages)
    {
        Title = title;
        Pages = pages;
    }

    public string Summary() => $"{Title} ({Pages} pages)";
}

var book = new Book("Clean Code", 464);
Console.WriteLine(book.Summary());
RecordsAndInit.cs
public record Person(string Name, int Age)
{
    public string Greet() => $"Hi, I'm {Name} and I'm {Age}.";
}

var alice = new Person("Alice", 30);
var olderAlice = alice with { Age = 31 }; // creates a modified copy
Console.WriteLine(alice.Greet());
Console.WriteLine(alice == olderAlice); // false -- value equality by field

public class Account
{
    public string Owner { get; init; } = "";
    public decimal Balance { get; private set; }

    public void Deposit(decimal amount) => Balance += amount;
}

var acc = new Account { Owner = "Yusuf" }; // init-only, settable here only
acc.Deposit(100);
ConstructorChaining.cs
public class Rectangle
{
    public double Width { get; }
    public double Height { get; }

    public Rectangle(double width, double height)
    {
        Width = width;
        Height = height;
    }

    // Chains to the main constructor to avoid duplicating logic
    public Rectangle(double side) : this(side, side) { }

    public double Area => Width * Height;
}

var square = new Rectangle(4);
Console.WriteLine(square.Area); // 16
Key points
  • Properties (get/set) are the standard way to expose an object's state in C#.
  • Record types give concise, immutable data classes with built-in value equality and a with expression for copies.
  • Constructors run automatically when an object is created with new, and can chain to each other with : this(...).
  • this disambiguates a field from a constructor parameter of the same name.
  • Prefer the narrowest access modifier that works — expose properties, not raw mutable fields.
  • { get; init; } allows a property to be set only during construction, a lightweight alternative to a full record.
  • Static members belong to the type, not an instance, and are shared everywhere the type is used.
Try it yourself

Write a Person class with Name and Age properties, a constructor, and a Greet() method, then create two instances and print their greetings. Then write a second version as a record, add a with-expression that creates an older copy of one person, and print whether the two records are equal.
