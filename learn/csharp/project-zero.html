01 Zero stage capstone

A console expense tracker with its own tiny query language

C# · ties together everything in the Zero stage

The five Zero-stage topics — syntax and types, control flow and methods, classes and objects, arrays and lists, and the .NET CLI — exist to get you comfortable with the smallest complete unit of a real C# program: one console app you build, run, and iterate on entirely from the command line. This project ties all five together by having you build an expense tracker that a person could actually use to log what they spent money on.

The tracker reads simple text commands from the console ("add", "list", "total", "delete") in a loop, storing each expense as an object with a description, an amount, and a category, held in a growable in-memory collection for the life of the program. There's no database and no file saving yet — that's deliberately out of scope until later stages — so the whole project has to earn its usefulness purely through clean control flow, a well-designed class, and correct use of a list.

The constraint that makes this a genuine test of the stage: every expense must be represented by a class you write yourself (not a loose bundle of variables), and every command must be handled through a method with a sensible signature, not one giant block of if-statements in Main.

Requirements
  • An Expense class with at least a description, a decimal amount, and a category, plus a method that returns a one-line formatted summary of itself.
  • A List of Expense that starts empty and grows as the user adds entries during the session — no fixed-size array.
  • A command loop that keeps prompting until the user types "quit", handling at minimum "add", "list", "total", and "delete" using a switch statement or switch expression.
  • The "add" command must validate its input: reject a negative or non-numeric amount and reprompt rather than crashing or silently storing garbage.
  • The "total" command must correctly sum all current expenses using decimal, never double, and print it formatted as currency.
  • The "delete" command must remove a specific expense by its position in the list without throwing when given an out-of-range number.
  • The project runs from a clean checkout with nothing but dotnet run — no manual setup steps.
Suggested approach
  1. Scaffold the project with dotnet new console and get a bare "Hello, World" running before writing any tracker logic.
  2. Write the Expense class first, in isolation, and prove it works by manually creating two or three instances and printing their summaries.
  3. Build the command loop around a hardcoded list of expenses before wiring up "add", so you can get "list", "total", and "delete" working against known data first.
  4. Add "add" last, since it's the command that needs the most input validation, and validation is easiest to get right once the rest of the loop already works.
  5. Do a final pass just on error cases: bad amounts, deleting an index that doesn't exist, listing when the tracker is empty — make sure none of them crash the program.
Stretch goals
  • Add an "edit" command that lets the user change an existing expense's amount or category by index.
  • Add a "summary" command that uses a Dictionary of string to decimal to print totals grouped by category, even though grouping isn't formally covered until the next stage.
  • Give categories a fixed, validated set of allowed values instead of accepting any free-text string.
