02 Learning stage capstone

A tiny web-based bookshelf you can actually save books to

C# · ties together everything in the Learning stage

This stage's project graduates the console tracker's idea into something with a real database and a browser front end: a personal "bookshelf" app where you can add a book you've read (title, author, rating), see the full list rendered as HTML, and have it persist across restarts. It's the first project in the roadmap where the data outlives the program's process, which is the whole point of the stage.

You'll build it as a minimal ASP.NET Core app, using an interface and at least one concrete class implementing it (satisfying the OOP topic), a Dictionary or a small in-memory collection queried with basic LINQ, exceptions handled instead of letting the app crash on bad input, and file-based storage so the bookshelf survives a restart. The through-line constraint: nothing in this project should hard-code a book list — the form submission has to be the only way data gets in.

This is also the first project where a bug in one layer can silently corrupt another (a malformed form submission reaching your storage code), which is exactly the scenario exception handling and validation exist to guard against.

  • OOP: inheritance, interfaces, polymorphism
  • Collections and basic LINQ queries
  • Exception handling
  • Working with files
  • Intro to ASP.NET Core
Requirements
  • An ASP.NET Core minimal API app with at least one GET route rendering an HTML page listing every saved book, and one POST route that accepts a new book from an HTML form.
  • A Book class or record with title, author, and a numeric rating, plus an IBookStore interface (or similar) with at least one concrete implementation the app depends on.
  • Books are persisted to a file (plain text or JSON) so restarting the app does not lose previously added books.
  • A LINQ query (e.g. OrderByDescending or Where) used to sort or filter the book list before it's displayed — not just a raw dump of the collection.
  • Submitting the form with a missing title or an out-of-range rating is caught and shown back to the user as a friendly message, never an unhandled exception or a blank crash page.
  • The rating displayed uses at least one string-formatting technique from the Zero/Learning stages (interpolation, not manual concatenation).
Suggested approach
  1. Start with the GET route rendering a hardcoded in-memory list of two or three books, so you can see HTML output before any storage logic exists.
  2. Introduce the IBookStore interface and an in-memory implementation next, and rewire the GET route to read through it instead of a hardcoded list.
  3. Add the POST route and the HTML form, keeping the store purely in-memory at first so you can test the add flow without worrying about file I/O bugs at the same time.
  4. Swap the in-memory implementation for a file-backed one last, wrapping the file reads and writes in try/catch so a missing or malformed file degrades gracefully instead of crashing the app on startup.
  5. Add the sorting/filtering LINQ query and the input validation as a final pass once the core add-and-list flow is solid.
Stretch goals
  • Add a second file-backed implementation of IBookStore using JSON via System.Text.Json instead of plain text, and switch between them with a single line in Program.cs.
  • Add a "delete" route and confirm it correctly rewrites the persisted file.
  • Add a simple search box that filters the displayed list by title substring using LINQ's Where.
