ASP.NET Core Web APIs

C# · part of the free zero-to-hero guide

Building a full REST API in ASP.NET Core typically uses [ApiController] classes with attribute routing: [HttpGet], [HttpPost], and similar attributes map methods to HTTP verbs and routes, and returned objects are automatically serialized to JSON via System.Text.Json by default. The [ApiController] attribute also turns on automatic model validation and forces route/query mismatches to return a 400 response instead of silently binding null.

Model binding automatically converts incoming JSON request bodies into C# objects via [FromBody], route segments via [FromRoute], and query string values via [FromQuery]; validation attributes like [Required], [Range], and [StringLength] on a model's properties are checked automatically before the action method even runs, and a failing model returns a 400 with the validation errors without you writing any explicit validation code.

Returning an IActionResult (or the generic ActionResult of T) lets a single action return different HTTP status codes — Ok(result), NotFound(), BadRequest(), CreatedAtAction(...) — depending on what happened, which maps the API's behavior onto proper REST semantics instead of always returning 200 with an error flag buried in the body.

Dependency injection is the standard way to reach a database or external service from a controller: services registered in Program.cs are supplied automatically to a controller's constructor, keeping the controller itself thin and easily testable by substituting a fake implementation of the injected interface in unit tests.

Cross-cutting concerns — authentication ([Authorize]), CORS, rate limiting, response caching — are typically applied via attributes on controllers/actions or configured once in the middleware pipeline, rather than duplicated in every action method, keeping the actual business logic focused on just the request at hand.

For discoverability, ASP.NET Core integrates with OpenAPI/Swagger tooling that generates interactive API documentation directly from your controllers, routes, and model types, which is invaluable both for other developers consuming the API and for catching accidental breaking changes to a contract.

ProductsController.cs
[ApiController]
[Route("api/[controller]")]
public class ProductsController : ControllerBase
{
    [HttpGet("{id}")]
    public ActionResult<Product> Get(int id)
    {
        var product = ProductRepository.Find(id);
        if (product is null) return NotFound();
        return Ok(product);
    }

    [HttpPost]
    public ActionResult<Product> Create([FromBody] Product product)
    {
        ProductRepository.Add(product);
        return CreatedAtAction(nameof(Get), new { id = product.Id }, product);
    }
}
ValidatedModelAndDI.cs
public class CreateProductRequest
{
    [Required, StringLength(100)]
    public string Name { get; set; } = "";

    [Range(0.01, 100000)]
    public decimal Price { get; set; }
}

[ApiController]
[Route("api/[controller]")]
public class ProductsController : ControllerBase
{
    private readonly IProductRepository _repository;

    // Injected automatically by the DI container
    public ProductsController(IProductRepository repository)
    {
        _repository = repository;
    }

    [HttpPost]
    public IActionResult Create(CreateProductRequest request)
    {
        // [ApiController] already returned 400 automatically if invalid
        var product = _repository.Add(request.Name, request.Price);
        return CreatedAtAction(nameof(Create), new { id = product.Id }, product);
    }
}
AuthorizeAndErrors.cs
[ApiController]
[Route("api/[controller]")]
[Authorize] // every action requires an authenticated caller
public class OrdersController : ControllerBase
{
    [HttpGet("{id}")]
    [AllowAnonymous] // overrides the class-level [Authorize] for this action
    public IActionResult Get(int id)
    {
        if (id <= 0) return BadRequest("id must be positive");
        var order = OrderRepository.Find(id);
        return order is null ? NotFound() : Ok(order);
    }
}
Key points
  • [ApiController] plus attribute routing maps HTTP verbs and routes directly to methods, and enables automatic 400s on invalid models.
  • [FromBody], [FromRoute], and [FromQuery] tell model binding where to pull each parameter from.
  • Data annotation attributes such as [Required] and [Range] drive automatic model validation before the action even runs.
  • ActionResult of T lets one method return varied HTTP responses like Ok, NotFound, or BadRequest.
  • Constructor-injected services keep controllers thin and easy to unit test with fake implementations.
  • [Authorize] and [AllowAnonymous] control access at the class or action level, overriding as needed.
  • OpenAPI/Swagger tooling generates interactive documentation straight from your controllers and models.
