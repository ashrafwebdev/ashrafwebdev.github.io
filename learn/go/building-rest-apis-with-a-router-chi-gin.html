Building REST APIs with a router (chi/gin)

Go · part of the free zero-to-hero guide

While net/http covers the basics, routers like chi and gin add convenient features on top: path parameters (/users/{id}), middleware chains, and route grouping, without straying far from idiomatic Go.

gin is a full-featured, high-performance framework with built-in JSON binding and validation, popular for its speed and low-friction API; chi is a lightweight, fully net/http-compatible router that stays closer to the standard library's interfaces.

Both let you group related routes and apply shared middleware (logging, authentication) to a whole group at once, which keeps route definitions readable as an API grows.

main.go
package main

import "github.com/gin-gonic/gin"

type Product struct {
	ID    int     `json:"id"`
	Name  string  `json:"name"`
	Price float64 `json:"price"`
}

func main() {
	r := gin.Default()
	r.GET("/products/:id", func(c *gin.Context) {
		id := c.Param("id")
		c.JSON(200, Product{ID: 1, Name: "Widget", Price: 9.99})
		_ = id
	})
	r.Run(":8080")
}
Key points
  • Routers like chi and gin add path parameters, middleware, and route grouping on top of net/http.
  • gin favors speed and built-in JSON binding; chi favors staying close to standard net/http interfaces.
  • Struct tags like json:"name" control how a struct serializes to and from JSON.
  • Middleware applied to a route group runs for every route inside that group automatically.
