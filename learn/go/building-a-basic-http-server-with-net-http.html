Building a basic HTTP server with net/http

Go · part of the free zero-to-hero guide

Builds on: Working with modules (go.mod)

Go's standard library includes a capable HTTP server in net/http, with no external framework required to get started. http.HandleFunc registers a handler function for a route on the default multiplexer, and http.ListenAndServe starts the server, blocking until it's stopped or a fatal error occurs.

A handler function receives an http.ResponseWriter to write the response and an *http.Request describing the incoming request; writing to the ResponseWriter and setting headers is how you control the response, with no separate response object to construct and return — the first call to w.Write (or anything that writes, like fmt.Fprintf(w, ...)) implicitly sends a 200 OK status unless you called w.WriteHeader(code) first.

Since Go 1.22, http.ServeMux (the router type behind http.HandleFunc) supports method-specific and wildcard patterns directly, like mux.HandleFunc("GET /users/{id}", handler), closing much of the gap that used to require a third-party router just to read a path parameter or restrict a route to one HTTP method.

Reading a JSON request body uses json.NewDecoder(r.Body).Decode(&target), and writing a JSON response uses json.NewEncoder(w).Encode(value) after setting w.Header().Set("Content-Type", "application/json") — both stream rather than buffer the whole payload in memory first, which matters for large payloads.

Production servers should almost always be constructed with an explicit http.Server value rather than the bare http.ListenAndServe shortcut, since that lets you set ReadTimeout, WriteTimeout, and IdleTimeout — without them, a slow or malicious client can hold a connection open indefinitely and exhaust server resources.

Because it's part of the standard library and reasonably fast out of the box, many small to medium Go services use net/http directly rather than reaching for a third-party web framework; middleware in this style is just a function that wraps a handler and returns a new one, requiring no special framework support.

main.go
package main

import (
	"fmt"
	"net/http"
)

func helloHandler(w http.ResponseWriter, r *http.Request) {
	name := r.URL.Query().Get("name")
	if name == "" {
		name = "world"
	}
	fmt.Fprintf(w, "Hello, %s!", name)
}

func main() {
	http.HandleFunc("/hello", helloHandler)
	http.ListenAndServe(":8080", nil)
}
json_and_server.go
package main

import (
	"encoding/json"
	"net/http"
	"time"
)

type User struct {
	Name string `json:"name"`
	Age  int    `json:"age"`
}

func createUser(w http.ResponseWriter, r *http.Request) {
	var u User
	if err := json.NewDecoder(r.Body).Decode(&u); err != nil {
		http.Error(w, "invalid JSON", http.StatusBadRequest)
		return
	}
	w.Header().Set("Content-Type", "application/json")
	json.NewEncoder(w).Encode(u)
}

func main() {
	mux := http.NewServeMux()
	mux.HandleFunc("POST /users", createUser)

	srv := &http.Server{
		Addr:         ":8080",
		Handler:      mux,
		ReadTimeout:  5 * time.Second,
		WriteTimeout: 10 * time.Second,
		IdleTimeout:  60 * time.Second,
	}
	srv.ListenAndServe()
}
middleware.go
package main

import (
	"log"
	"net/http"
	"time"
)

func logging(next http.Handler) http.Handler {
	return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		start := time.Now()
		next.ServeHTTP(w, r)
		log.Printf("%s %s took %v", r.Method, r.URL.Path, time.Since(start))
	})
}

func main() {
	mux := http.NewServeMux()
	mux.HandleFunc("GET /health", func(w http.ResponseWriter, r *http.Request) {
		w.Write([]byte("ok"))
	})
	http.ListenAndServe(":8080", logging(mux))
}
Key points
  • net/http provides a production-capable HTTP server with zero external dependencies.
  • Handlers take an http.ResponseWriter and *http.Request, writing the response directly; the first write implicitly sends a 200 unless you called WriteHeader first.
  • Since Go 1.22, http.ServeMux supports method-specific patterns like "GET /users/{id}" without a third-party router.
  • json.NewDecoder/json.NewEncoder stream JSON request and response bodies without buffering the whole payload.
  • Use an explicit http.Server with ReadTimeout/WriteTimeout/IdleTimeout set in production instead of the bare ListenAndServe shortcut.
  • Query parameters are read via r.URL.Query().Get(...).
  • Middleware is just a function wrapping one http.Handler to return another — no special framework support required.
Try it yourself

Write a net/http server with two routes: one returning a static JSON message and one that reads a query parameter and echoes it back in the response. Then add a logging middleware that wraps the whole mux and prints each request's method, path, and duration, and configure the server with explicit read/write timeouts instead of using the bare ListenAndServe shortcut.
