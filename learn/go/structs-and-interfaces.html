Structs and interfaces

Go · part of the free zero-to-hero guide

A Go struct groups named fields together, similar to a class's data but with no inheritance. Methods are attached to a struct by declaring a receiver: func (b Book) Summary() string defines a method on Book, and a pointer receiver (func (b *Book) SetTitle(...)) is used when the method needs to mutate the struct, or when the struct is large enough that copying it on every call would be wasteful.

Go interfaces are satisfied implicitly — a type automatically implements an interface simply by having the required methods, with no implements keyword needed. This is a defining feature of Go's type system and encourages small, focused interfaces defined at the point of use (often by the consumer of an interface, not its implementer), rather than large upfront interface hierarchies designed before any real usage exists.

Go supports composition over inheritance through embedding: including one struct (or interface) inside another as an unnamed field promotes its fields and methods to the outer type, so type Manager struct { Employee; Reports []Employee } lets you call m.Name or m.Employee.Name interchangeably. This is not inheritance — there's no polymorphic dispatch through the embedded type, just automatic field and method promotion.

Choosing between a value receiver and a pointer receiver has real consequences: a value receiver method operates on a copy of the struct, so mutations inside it are invisible to the caller, while a pointer receiver operates on the original. A common rule of thumb is that if any method on a type needs a pointer receiver, all methods on that type should use pointer receivers too, for consistency and to avoid confusing mixed behavior.

The empty interface interface{} (or its alias any, added in Go 1.18) can hold a value of any type, though modern Go increasingly prefers generics (covered in a later lesson) over any when the code needs to stay type-safe at compile time rather than relying on runtime type assertions.

A type assertion (v, ok := i.(SomeType)) extracts a concrete value out of an interface value, and a type switch (switch v := i.(type) { case int: ...; case string: ... }) branches on the concrete type stored inside an interface value — both are the mechanism for recovering specific behavior when you're holding a value only as its interface type.

main.go
package main

import "fmt"

type Shape interface {
	Area() float64
}

type Circle struct {
	Radius float64
}

func (c Circle) Area() float64 {
	return 3.14159 * c.Radius * c.Radius
}

func main() {
	var s Shape = Circle{Radius: 2}
	fmt.Println(s.Area())
}
embedding.go
package main

import "fmt"

type Employee struct {
	Name string
	ID   int
}

func (e Employee) Describe() string {
	return fmt.Sprintf("%s (#%d)", e.Name, e.ID)
}

type Manager struct {
	Employee        // embedded: promotes Name, ID, Describe()
	Reports []Employee
}

func main() {
	m := Manager{
		Employee: Employee{Name: "Sara", ID: 7},
		Reports:  []Employee{{Name: "Tom", ID: 12}},
	}
	fmt.Println(m.Describe())      // promoted method
	fmt.Println(m.Name, len(m.Reports))
}
type_switch.go
package main

import "fmt"

func describe(i any) string {
	switch v := i.(type) {
	case int:
		return fmt.Sprintf("int: %d", v)
	case string:
		return fmt.Sprintf("string of length %d", len(v))
	case Circle:
		return fmt.Sprintf("circle with area %.2f", v.Area())
	default:
		return "unknown type"
	}
}

type Circle struct{ Radius float64 }

func (c Circle) Area() float64 { return 3.14159 * c.Radius * c.Radius }

func main() {
	fmt.Println(describe(42))
	fmt.Println(describe("hello"))
	fmt.Println(describe(Circle{Radius: 3}))
}
Key points
  • Methods are declared with a receiver: value receivers operate on a copy, pointer receivers operate on and can mutate the original.
  • A type satisfies an interface implicitly just by implementing its methods — no declaration needed.
  • Small, focused interfaces defined where they're used are idiomatic Go, unlike large upfront interface hierarchies.
  • Embedding a struct or interface promotes its fields and methods to the outer type — composition, not inheritance.
  • If any method on a type needs a pointer receiver, it's conventional to make all its methods use pointer receivers.
  • any (alias for interface{}) can hold any value but sacrifices compile-time type safety.
  • A type assertion (v, ok := i.(T)) or type switch (switch v := i.(type)) recovers a concrete type from an interface value.
Try it yourself

Define a Shape interface with Area() and Perimeter(), implement it for a Rectangle struct, and write a function that prints both values for any Shape passed to it. Then create a Square struct that embeds Rectangle to reuse its methods, and write a type switch function that prints a different message depending on whether it receives a Rectangle or a Square.
