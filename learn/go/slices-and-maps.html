Slices and maps

Go · part of the free zero-to-hero guide

Builds on: Control flow and functions

A Go slice is a resizable, flexible view over an underlying array — the everyday collection type, created with []int{1, 2, 3} or grown dynamically with the built-in append function, which returns a (possibly reallocated) slice. Internally a slice is a small struct of a pointer, a length, and a capacity; len(s) gives the number of elements currently in use and cap(s) gives how many the underlying array can hold before a reallocation is needed.

Because a slice header is a lightweight value wrapping a pointer to shared backing storage, two slices can point at overlapping memory. Slicing an existing slice (s[1:3]) does not copy data — it shares the same backing array, so mutating an element through one slice is visible through the other until an append forces a reallocation, which is a common source of subtle bugs when code assumes slicing always copies.

A map (map[string]int) associates keys with values, similar to a dictionary or hash map in other languages, and must be created with make(map[K]V) or a map literal before use — a nil map can be read from safely (returning zero values) but writing to a nil map panics. Looking up a missing key returns the value type's zero value rather than an error, so Go's "comma ok" idiom (v, ok := m[key]) is used to distinguish a genuinely-zero value from a missing key.

Map iteration order is deliberately randomized by the Go runtime, specifically to prevent code from ever accidentally depending on a stable order — if you need sorted output, collect the keys into a slice and sort that slice explicitly with sort.Strings or sort.Slice before iterating.

Slices and maps are both reference-like: passing one to a function does not copy the underlying data, so mutations inside the function are visible to the caller, unlike Go's plain arrays or structs which are copied by value on assignment or when passed as arguments. This matters for performance too — passing a large slice around is cheap regardless of how many elements it contains, since only the small header is copied.

The built-in copy(dst, src) function copies elements between two slices (up to the shorter one's length) and is the standard way to make an independent, non-aliased duplicate of a slice's data when you specifically don't want sharing; delete(m, key) removes a key from a map, and is a no-op if the key isn't present.

main.go
package main

import "fmt"

func main() {
	scores := []int{88, 92, 75}
	scores = append(scores, 100)

	stock := map[string]int{"apples": 50, "bananas": 30}
	if qty, ok := stock["cherries"]; ok {
		fmt.Println("cherries:", qty)
	} else {
		fmt.Println("cherries not tracked")
	}

	fmt.Println(scores)
}
sorted_iteration.go
package main

import (
	"fmt"
	"sort"
)

func main() {
	stock := map[string]int{"cherries": 12, "apples": 50, "bananas": 30}

	keys := make([]string, 0, len(stock))
	for k := range stock {
		keys = append(keys, k)
	}
	sort.Strings(keys)

	for _, k := range keys {
		fmt.Printf("%s: %d\n", k, stock[k])
	}
}
aliasing_gotcha.go
package main

import "fmt"

func main() {
	original := []int{1, 2, 3, 4, 5}
	view := original[1:3] // shares backing array with original

	view[0] = 99 // mutates original[1] too
	fmt.Println(original) // [1 99 3 4 5]

	// to get an independent copy instead:
	independent := make([]int, len(view))
	copy(independent, view)
	independent[0] = -1
	fmt.Println(original) // unaffected: [1 99 3 4 5]
}
Key points
  • append grows a slice, possibly returning a new underlying array — always reassign its result.
  • A slice header is a pointer, length, and capacity; re-slicing shares the same backing array rather than copying.
  • The "comma ok" idiom (v, ok := m[key]) distinguishes a missing key from a genuine zero value.
  • A nil map can be read (returns zero values) but panics on write; always initialize with make or a literal first.
  • Map iteration order is intentionally randomized — sort the keys explicitly if you need deterministic output.
  • Slices and maps are reference-like; mutating them inside a function affects the caller's data too.
  • copy(dst, src) makes an independent duplicate of slice data when aliasing the backing array is undesirable.
  • Iterate either with for i, v := range slice or for k, v := range map.
