01 Zero stage capstone

atlas: a command-line world-facts lookup tool

Go · ties together everything in the Zero stage

The five Zero-stage topics — syntax and types, control flow and functions, slices and maps, packages and go build, and basic error handling — are all you need to write a genuinely useful CLI tool, as long as you resist reaching for anything fancier. This project asks you to build atlas: a command-line program that looks up facts about a country (capital, population, area) from a dataset you hardcode directly into the program, and prints them formatted nicely.

The real public-API version of this idea belongs to a later stage — talking to a live HTTP endpoint is Learning-stage material. Here the dataset lives entirely in a Go map inside your own package, which is deliberate: it forces the project to be a genuine workout for maps, slices, functions, and error handling instead of becoming a project about an HTTP client.

By the end you'll have a real multi-package Go module, built into a standalone binary with go build, that behaves like a small, well-mannered command-line tool: clear output on success, a clear error message (not a crash) on bad input, and a sorted listing mode.

  • Syntax, variables, and types
  • Control flow and functions
  • Slices and maps
  • Packages and go run/go build
  • Basic error handling (the Go way)
Requirements
  • A separate, importable package (for example atlas) holding the dataset as a map[string]... and an exported lookup function — main should only parse arguments and print, never touch the raw data structure directly.
  • The dataset covers at least 10 countries, each with a capital, a population (as an integer), and an area (as a float), printed with appropriate fmt.Printf verbs (%d, %.1f, etc.).
  • Running the program with a country name as a command-line argument (go run . france) prints that country's facts; running it with a name that isn't in the dataset prints a clear error message and exits with a non-zero status, without panicking.
  • A sentinel error (for example ErrCountryNotFound, built with errors.New) is wrapped with fmt.Errorf and %w when the lookup fails, and main uses errors.Is to detect that specific failure rather than comparing error strings.
  • A --list flag prints every country name in the dataset in alphabetical order, using sort.Strings on the collected map keys — never relying on map iteration order directly.
  • The whole program builds cleanly with go build into a single binary that runs with no further setup.
Suggested approach
  1. Start with the atlas package alone: define the dataset as a map literal and write the exported lookup function, and prove it works with a throwaway fmt.Println call before touching main.
  2. Add the error handling next: define the sentinel error, return it wrapped with context when a country isn't found, and get comfortable with what errors.Is sees on the other end.
  3. Wire up main.go to read os.Args, call into the atlas package, and format a successful result — get the happy path working before handling any failure case.
  4. Handle the not-found case in main: print the error and set a non-zero exit status, without a panic anywhere in the path.
  5. Add the --list flag last, since it's the one part of the program that needs sorted iteration over the map's keys.
Stretch goals
  • Add a second fact (currency, or timezone) per country, which will push you to reorganize the dataset — notice how much a single struct would simplify this, even though you haven't formally covered structs yet.
  • Add a --compare flag that takes two country names and prints which one has the larger population.
  • Write a short comment in your code explaining, in your own words, why the dataset lives in a Go map instead of being fetched from a real API at this stage — it's a good check that you understand the constraint, not just followed it.
