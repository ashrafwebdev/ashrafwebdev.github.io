Streams and buffers basics

Node.js · part of the free zero-to-hero guide

Builds on: Connecting to a database (MongoDB or PostgreSQL)

A stream processes data incrementally, in chunks, rather than loading an entire file or response into memory at once — essential for handling large files or long-lived connections efficiently, since a naive readFile on a multi-gigabyte file would try to hold the whole thing in memory.

A Buffer represents raw binary data — what you get, for instance, when reading a file without specifying a text encoding. Streams of data (like a file being read) emit Buffer chunks that you can process as they arrive, and Buffer.from()/Buffer.alloc() let you create buffers directly when working with binary protocols or encodings.

Node has four stream types: Readable (a source of data, like a file being read), Writable (a destination, like a file being written or an HTTP response), Duplex (both, like a TCP socket), and Transform (a duplex stream that modifies data as it passes through, like a gzip compressor). Most application code works with the first two.

.pipe() connects a readable stream directly to a writable one — reading a file and streaming it as an HTTP response, for example — and automatically manages backpressure: pausing the readable side when the writable side can't keep up, which prevents memory from ballooning if, say, a slow network connection can't consume data as fast as a fast local disk can produce it.

The modern, more robust alternative to chaining .pipe() calls manually is stream.pipeline() (or its promise version), which forwards errors from any stream in the chain and guarantees all streams are properly closed afterward — plain .pipe() notoriously does *not* automatically forward errors or clean up on failure, which is a common source of resource leaks in production code.

HTTP request/response objects in Node are themselves streams — this is how large file uploads and downloads are handled efficiently without buffering the entire body in memory first, and it's why frameworks like Express can support piping a file straight from disk into a response with res.sendFile() or a manual pipe.

streams.js
const fs = require("fs");

const readStream = fs.createReadStream("large-file.txt", "utf-8");

readStream.on("data", (chunk) => {
  console.log("Received chunk of size:", chunk.length);
});

readStream.on("end", () => console.log("Done reading"));
copy-with-pipeline.js
const { pipeline } = require("stream/promises");
const fs = require("fs");
const zlib = require("zlib");

async function compressFile(input, output) {
  await pipeline(
    fs.createReadStream(input),
    zlib.createGzip(),           // a Transform stream
    fs.createWriteStream(output)
  );
  // pipeline() forwards errors from any stage and cleans up all streams
}

compressFile("large-file.txt", "large-file.txt.gz")
  .then(() => console.log("Compressed successfully"))
  .catch((err) => console.error("Failed:", err));
buffers.js
const buf = Buffer.from("hello", "utf-8");
console.log(buf);            // <Buffer 68 65 6c 6c 6f>
console.log(buf.toString()); // "hello"
console.log(buf.length);     // 5 (bytes, not characters — matters for multi-byte text)

const empty = Buffer.alloc(4); // 4 zeroed bytes, useful as a fixed-size binary buffer
Key points
  • Streams process data in chunks, keeping memory usage low regardless of the total file/data size.
  • .pipe() connects a readable stream directly to a writable one and automatically manages backpressure.
  • A Buffer holds raw bytes; specify an encoding when you want text instead.
  • There are four stream types — Readable, Writable, Duplex, and Transform — most app code only needs the first two.
  • Plain .pipe() doesn't forward errors or guarantee cleanup — prefer stream.pipeline() (or its promise version) in real code.
  • HTTP request/response objects in Node are themselves streams — this is how large file uploads/downloads are handled efficiently.
  • Backpressure is the mechanism that prevents a fast producer from overwhelming a slow consumer's memory.
Try it yourself

Use fs.createReadStream and fs.createWriteStream together with stream.pipeline() (not raw .pipe()) to copy a large file without loading it entirely into memory. Then insert a zlib gzip Transform stream into the pipeline so the copy is compressed on the way through, and confirm errors (e.g. from a missing source file) are properly surfaced by the pipeline's promise rejection.
