01 Zero stage

Basic console-based programs

Node.js · part of the free zero-to-hero guide

Beyond one-off scripts, Node can build interactive command-line tools. The built-in readline module reads user input from the terminal line by line, similar to Python's input() but callback/event-based in its original form, with a Promise-friendly wrapper available via readline/promises.

process.argv gives access to command-line arguments passed when the script was invoked, letting a script behave differently based on flags or inputs — the foundation of any real CLI tool, from a simple script to something like the npm command itself.

For anything beyond a couple of positional arguments, hand-parsing process.argv gets unwieldy fast — distinguishing --flag value from --flag=value from a bare boolean flag, handling -h/--help, and giving useful error messages all add up. This is exactly what argument-parsing libraries like commander or yargs exist to handle.

process.exit(code) ends the script immediately with a given exit code — 0 for success, non-zero for failure — which matters because shell scripts and CI pipelines check that exit code to decide whether a command succeeded. Calling process.exit() abruptly can also cut off any pending asynchronous work (like a file write that hasn't finished), so it's best reserved for genuine, deliberate early termination.

Reading piped input (echo "data" | node script.js) is a different pattern from interactive readline prompting: you read from process.stdin as a stream, listening for data and end events, which lets a script work both interactively and as part of a Unix-style pipeline.

Color and formatting in terminal output (via ANSI escape codes, or a library like chalk or picocolors) makes CLI tools meaningfully more usable — highlighting errors in red or success in green — but should always degrade gracefully when output isn't a real terminal (e.g. when piped to a file), which most such libraries detect automatically.

cli.js
const readline = require("readline/promises");
const { stdin, stdout } = process;

const rl = readline.createInterface({ input: stdin, output: stdout });

async function main() {
  const name = await rl.question("What's your name? ");
  console.log(`Hello, ${name}!`);
  rl.close();
}

main();
args.js (manual flag parsing)
// node args.js --name Amina --verbose
const args = process.argv.slice(2);
const options = { verbose: false };

for (let i = 0; i < args.length; i++) {
  if (args[i] === "--name") options.name = args[++i];
  if (args[i] === "--verbose") options.verbose = true;
}

if (!options.name) {
  console.error("Usage: node args.js --name <name> [--verbose]");
  process.exit(1);
}

console.log(`Hello, ${options.name}!`);
if (options.verbose) console.log("Verbose mode on");
read-stdin.js (piped input)
let input = "";

process.stdin.on("data", (chunk) => {
  input += chunk;
});

process.stdin.on("end", () => {
  const lines = input.trim().split("\n");
  console.log(`Received ${lines.length} line(s)`);
});

// Usage: echo -e "a\nb\nc" | node read-stdin.js
Key points
  • readline/promises gives an async/await-friendly way to prompt for terminal input.
  • process.argv is an array; the actual arguments start at index 2 (indexes 0 and 1 are the node binary and script path).
  • process.exit(code) ends the script immediately with a given exit code — 0 for success, non-zero for failure.
  • Libraries like commander or yargs handle argument parsing for anything beyond the simplest CLI tool.
  • A script can also read piped input via the process.stdin stream's data/end events, not just interactive readline prompts.
  • Calling process.exit() too early can cut off pending async work — reserve it for deliberate, final termination.
  • Non-zero exit codes are how shell scripts and CI pipelines detect that your command failed — don't skip setting them on error paths.
  • Terminal color libraries (chalk, picocolors) typically detect non-terminal output automatically and disable color codes when piped to a file.
Try it yourself

Write a CLI script that asks the user for two numbers via readline and prints their sum. Then add support for passing the numbers directly as command-line flags (e.g. node calc.js --a 5 --b 3) so the script works both interactively and non-interactively, exiting with a non-zero code and a usage message if the flags are malformed.
