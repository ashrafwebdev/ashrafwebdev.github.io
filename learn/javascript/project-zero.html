Console Todo: a task manager that never touches the DOM

JavaScript · ties together everything in the Zero stage

Every Zero-stage JavaScript topic — variables, conditionals and loops, functions and parameters, arrays and objects, and console debugging — exists to build one core skill: modeling a piece of changing state with plain data, and writing functions that read and update it correctly. This project asks you to build a working to-do list manager entirely as a set of functions you call from the DevTools console, with no HTML page, no DOM, and no click handlers involved at all.

Removing the DOM is deliberate. It's tempting to think a to-do app is really about buttons and lists on a page, but the actual programming problem underneath — representing a task, adding one, marking one done, removing one, and reporting the current state — is pure JavaScript, and this stage is where you prove you can solve it with nothing but variables, control flow, functions, and data structures.

By the end you'll have a single .js file you can paste into the console (or run with node) that maintains a list of tasks in memory and exposes a handful of functions for working with it, all confirmed with console.log() and console.table() output rather than anything visual.

  • Variables (let/const), data types, and operators
  • Conditionals and loops
  • Functions and parameters
  • Arrays and objects basics
  • Console debugging
Requirements
  • Tasks are represented as an array of plain objects, each with at least an id, a text string, and a done boolean.
  • A working addTask(text) function that creates a new task object with a unique id (a simple counter is fine), appends it to the array, and does not overwrite the existing tasks.
  • Working completeTask(id) and removeTask(id) functions, each of which locates the right task by id using a loop or an array method you already know, not by hardcoding an index.
  • A listTasks() function that prints the current state using console.table(), so the whole list is readable at a glance after every change.
  • At least one for...of loop (or .forEach()) used somewhere instead of a manually indexed for loop.
  • Calling completeTask() or removeTask() with an id that doesn't exist does not crash the script — it prints a clear console.warn() message instead and leaves the task list unchanged.
  • Only let and const are used to declare variables — no var anywhere in the file.
Suggested approach
  1. Start by hand-writing an array of two or three sample task objects and a listTasks() function, so you have something real to check against before any other function exists.
  2. Add addTask(text) next, and confirm with listTasks() after every call that new tasks show up with the right shape and a unique id.
  3. Add completeTask(id) and removeTask(id) one at a time, including the not-found branch, testing each against both a valid id and a made-up one that doesn't exist.
  4. Once every function works individually, write a short block of calls at the bottom of the file that exercises all of them in sequence, so running the whole file end to end demonstrates the entire app.
  5. Read back through the file and replace any leftover indexed for loop with for...of where you're only using the value, not the index.
Stretch goals
  • Add a toggleTask(id) function that flips done regardless of its current value, and give listTasks() an optional parameter (defaulting to showing everything) that filters to only done or only pending tasks.
  • Write a small stats function that loops over the tasks and reports how many are done versus pending, without using any array method beyond what this stage covers.
  • Look ahead at how localStorage works and try saving the task array as a JSON string after every change, so the list would survive a page refresh if this were ever wired up to a real page.
