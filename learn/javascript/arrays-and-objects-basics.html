Arrays and objects basics

JavaScript · part of the free zero-to-hero guide

Arrays hold ordered lists of values, accessed by a numeric index starting at 0. Objects hold unordered key-value pairs, accessed by key. As a rule of thumb: reach for an array when order matters and the items are similar in shape (a list of users, a list of scores); reach for an object when you're modeling one specific 'thing' with named properties (a single user's name, age, and email).

Both are reference types and both are mutable by default, even when declared with const. This surprises beginners: const only prevents reassigning the variable itself to point at a different array or object — it does nothing to stop you from pushing to that array or setting a new property on that object, because the variable is still pointing at the same object in memory.

Objects can be accessed with dot notation (user.name) when the key is a valid identifier known ahead of time, or bracket notation (user["name"]) when the key is dynamic — stored in a variable, computed, or containing characters that aren't valid in dot notation, like a space or a hyphen.

Copying an array or object with a simple assignment (const b = a) does not create a new one — it just creates a second variable pointing at the exact same data in memory, so mutating through either variable affects both. To make an actual independent copy, use the spread operator ([...arr] or {...obj}) or methods like Array.from() — but note this only copies one level deep; nested arrays or objects inside are still shared references, a trap known as a shallow copy.

Nested structures — arrays of objects, objects containing arrays, objects containing other objects — are the normal shape of real-world data, especially anything coming back from an API as JSON. Getting comfortable reading and building nested structures, and knowing how to safely reach deep into them (optional chaining helps a lot here), is one of the most practically useful JavaScript skills.

Useful array checks and utilities worth knowing early: Array.isArray() is the correct way to test whether something is actually an array (typeof just says "object" for arrays too), .length gives the element count, and Object.keys()/Object.values()/Object.entries() let you turn an object's keys, values, or key-value pairs into arrays you can loop over or transform.

collections.js
const fruits = ["apple", "banana", "cherry"];
fruits.push("date"); // mutates the array, allowed even with const

const user = {
  name: "Yusuf",
  age: 30,
  isAdmin: false,
};
console.log(fruits[0], user.name, user["age"]);
copying-and-nesting.js
// Reference vs copy
const original = { name: "Amina", tags: ["admin"] };
const alias = original;      // same object, not a copy
const shallow = { ...original }; // new outer object, but...

alias.name = "Changed";
console.log(original.name);  // "Changed" — alias affected the original

shallow.tags.push("editor");
console.log(original.tags);  // ["admin", "editor"] — nested array still shared!

// A nested structure typical of real API data
const order = {
  id: 1042,
  customer: { name: "Yusuf", email: "yusuf@example.com" },
  items: [
    { sku: "MUG-1", qty: 2 },
    { sku: "PEN-3", qty: 5 },
  ],
};
console.log(order.customer.name, order.items[0].sku);
object-key-helpers.js
const inventory = { mugs: 12, pens: 40, notebooks: 7 };

console.log(Object.keys(inventory));   // ["mugs", "pens", "notebooks"]
console.log(Object.values(inventory)); // [12, 40, 7]
console.log(Object.entries(inventory));
// [["mugs", 12], ["pens", 40], ["notebooks", 7]]

for (const [item, count] of Object.entries(inventory)) {
  console.log(`${item}: ${count}`);
}
Key points
  • Arrays: ordered, indexed from 0, use .length to get the count; use Array.isArray() to test for one, not typeof.
  • Objects: unordered key-value pairs, accessed via dot notation (fixed keys) or bracket notation (dynamic or invalid-identifier keys).
  • const prevents reassignment, not mutation — const arr = []; arr.push(1); is perfectly valid.
  • Assigning an array or object to a new variable copies the reference, not the data — both variables point at the same underlying value.
  • Spread ({...obj} or [...arr]) creates a shallow copy — nested arrays/objects inside are still shared with the original.
  • Object.keys(), Object.values(), and Object.entries() convert an object into an array you can loop over, map, or filter.
  • Nested structures (arrays of objects, objects of objects) are the everyday shape of real data — practice reading and building them deliberately.
Try it yourself

Create an array of 3 objects, each representing a book with title and author properties, then log each book's title in a loop. Then write a small nested order object like the one above, and use Object.entries() together with a loop to print every top-level key alongside its value. Finally, demonstrate the shallow-copy trap by spreading an object with a nested array, mutating the nested array through the copy, and showing that the original changed too.
