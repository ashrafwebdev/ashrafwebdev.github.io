Conditionals and loops

JavaScript · part of the free zero-to-hero guide

Conditionals let a program take different paths depending on data. if/else if/else chains handle arbitrary boolean conditions, while switch is a more structured alternative when you're comparing a single value against several fixed possibilities — it reads more clearly than a long chain of else if checks once you have more than three or four branches.

JavaScript's notion of truthy and falsy matters constantly in conditionals. The only falsy values are false, 0, "" (empty string), null, undefined, and NaN — literally everything else, including an empty array and an empty object, is truthy. This trips people up: if ([]) runs the branch, because an empty array is a truthy object, even though it 'feels' empty.

There are several loop constructs, each suited to a different job. The classic for (let i = 0; i < n; i++) loop gives you full control over the index, useful when you need to skip elements or move backward. while repeats as long as a condition holds, useful when you don't know the iteration count in advance. for...of is the modern, readable way to iterate directly over the values of an array, string, Map, or Set. for...in iterates over an object's enumerable property keys — it is rarely what you want for arrays, since it iterates indices as strings and can pick up inherited properties.

Ternary expressions (condition ? valueIfTrue : valueIfFalse) are a compact alternative to a short if/else when you're producing a value rather than running a side effect. They're great for a single value assignment but become hard to read quickly once nested — nested ternaries are a common source of code review pushback for good reason.

break exits a loop (or a switch case) entirely, while continue skips just the current iteration and moves to the next one. Both work with labeled loops too, which lets you break or continue an outer loop from inside a nested one — a rarely-needed but occasionally invaluable escape hatch.

A classic infinite-loop bug is forgetting to change the variable a while condition depends on, or getting the loop's increment direction wrong. Always double-check that every path through the loop body eventually makes the exit condition true.

loops.js
const scores = [72, 88, 95, 60];

for (const score of scores) {
  if (score >= 90) {
    console.log(score, "— A");
  } else if (score >= 70) {
    console.log(score, "— B");
  } else {
    console.log(score, "— needs work");
  }
}
switch-and-labels.js
function describeDay(day) {
  switch (day) {
    case "Sat":
    case "Sun":
      return "Weekend";
    case "Mon":
    case "Tue":
    case "Wed":
    case "Thu":
    case "Fri":
      return "Weekday";
    default:
      return "Unknown";
  }
}

// Labeled break to escape a nested loop early
outer: for (let row = 0; row < 3; row++) {
  for (let col = 0; col < 3; col++) {
    if (row === 1 && col === 1) break outer;
    console.log(row, col);
  }
}
truthy-gotcha.js
// Common trap: an empty array/object is truthy, unlike an empty string or 0
function announce(items) {
  if (items) {
    console.log("Got items:", items.length); // still runs for []
  }
}
announce([]); // logs "Got items: 0" — probably not what was intended

// Better: check the actual condition you care about
function announceFixed(items) {
  if (items.length > 0) {
    console.log("Got items:", items.length);
  }
}
Key points
  • Prefer for...of over the classic indexed for loop when you just need each value, not the index.
  • for...in iterates object keys, not array values — avoid it for arrays; use for...of or .forEach() instead.
  • switch needs a break in each case, or execution 'falls through' into the next case — this is occasionally intentional (grouping cases) but often a bug.
  • The only falsy values are false, 0, "", null, undefined, and NaN — an empty array or object is truthy.
  • while loops can run forever if the condition never becomes false — always verify the exit path exists.
  • continue skips to the next iteration; break exits the loop entirely; labeled versions of both can target an outer loop.
  • Ternaries are great for a single value decision, but nested ternaries hurt readability — reach for if/else once logic gets complex.
