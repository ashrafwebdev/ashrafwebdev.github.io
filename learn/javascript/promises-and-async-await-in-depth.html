Promises and async/await in depth

JavaScript · part of the free zero-to-hero guide

A Promise represents a value that isn't available yet but will eventually either resolve (succeed, with a value) or reject (fail, with a reason, usually an Error). A Promise moves through exactly three states over its lifetime — pending, then fulfilled or rejected — and once it settles into fulfilled or rejected, it can never change state again; this immutability is what makes Promises reliable to reason about compared to older callback-based async patterns.

async/await is syntax sugar built directly on top of Promises: marking a function async makes it always return a Promise, and await inside it pauses that function's execution (without blocking the rest of the program) until the awaited Promise settles, unwrapping its resolved value or throwing its rejection as a regular exception. This lets asynchronous code read top-to-bottom like synchronous code, which is dramatically easier to follow than nested .then() callback chains.

await only works inside a function explicitly marked async (or, in modern module environments, at a module's top level). A common structural mistake is trying to use await inside a plain .forEach() callback — .forEach() doesn't wait for anything its callback returns, so an async operation inside it fires and is immediately abandoned rather than awaited in sequence; a plain for...of loop (which does respect await) or Promise.all() with .map() are the correct replacements.

Promise.all() runs an array of promises concurrently and resolves once every one of them has resolved, or rejects immediately as soon as any single one rejects. This is usually far faster than awaiting several independent requests one after another with sequential await calls, since sequential awaiting needlessly serializes work that has no actual dependency between the pieces.

Promise.allSettled() is the safer sibling of Promise.all() for situations where some requests are allowed to fail without cancelling or invalidating the others — it always resolves (never rejects) with an array describing each promise's individual outcome, either {status: "fulfilled", value} or {status: "rejected", reason}. Promise.race() and Promise.any() round out the family: race() settles as soon as the first promise settles at all (success or failure), while any() settles as soon as the first one succeeds, ignoring failures unless all of them fail.

Error handling around await deserves real care: wrap awaited code in try/catch, because an unhandled rejected promise can crash a Node.js process outright, and in a browser it fails silently unless you're specifically listening for unhandledrejection events — either way, a swallowed rejection is a bug that's painful to track down later. Also remember that a .then() callback that itself throws produces a rejected promise, not a synchronous exception the surrounding code can catch with a normal try/catch — chaining .catch() (or awaiting inside try/catch) is required either way.

async.js
async function loadDashboard(userId) {
  const [user, posts] = await Promise.all([
    fetch(`/api/users/${userId}`).then((r) => r.json()),
    fetch(`/api/users/${userId}/posts`).then((r) => r.json()),
  ]);
  return { user, posts };
}
allSettled-and-error-handling.js
async function notifyAllUsers(userIds) {
  const results = await Promise.allSettled(
    userIds.map((id) => sendNotification(id))
  );

  const failed = results.filter((r) => r.status === "rejected");
  if (failed.length > 0) {
    console.warn(`${failed.length} notification(s) failed`, failed);
  }
  return results.filter((r) => r.status === "fulfilled").length;
}

async function safeLoad(id) {
  try {
    const data = await fetchUser(id);
    return data;
  } catch (err) {
    console.error("Failed to load user", id, err);
    return null; // fail gracefully instead of crashing the caller
  }
}
common-mistake-forEach.js
// Bug: forEach does not wait for the async callback
async function processAllBroken(ids) {
  ids.forEach(async (id) => {
    await sendToServer(id); // fires, but processAllBroken doesn't wait
  });
  console.log("done"); // logs immediately, before any request finishes
}

// Fix 1: sequential, respects await, one request at a time
async function processAllSequential(ids) {
  for (const id of ids) {
    await sendToServer(id);
  }
  console.log("done");
}

// Fix 2: concurrent, independent requests in parallel
async function processAllConcurrent(ids) {
  await Promise.all(ids.map((id) => sendToServer(id)));
  console.log("done");
}
Key points
  • await only works inside an async function (or, in modern environments, at a module's top level).
  • A Promise settles exactly once, into fulfilled or rejected, and can never change state afterward — this immutability is what makes them predictable to compose.
  • Promise.all() runs promises concurrently and rejects as soon as any one fails; sequential await calls run one after another, unnecessarily slower when the work is independent.
  • Promise.allSettled() never rejects — it reports every promise's individual outcome, ideal when partial failures are acceptable.
  • .forEach() does not wait for an async callback — use a plain for...of loop for sequential awaiting, or Promise.all() with .map() for concurrent awaiting.
  • Always wrap awaited code in try/catch — an unhandled rejected promise can crash a Node process or fail silently in the browser.
  • Promise.race() settles on the first promise to settle at all; Promise.any() settles on the first to succeed, ignoring failures unless every one fails.
