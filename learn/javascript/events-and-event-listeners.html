Events and event listeners

JavaScript · part of the free zero-to-hero guide

Builds on: DOM selection and manipulation

Events are how a page responds to what happens — clicks, key presses, form submissions, scrolling, network responses finishing, and dozens more. element.addEventListener(type, handler) attaches a function that runs every time that event fires on that element, and unlike the older onclick = fn style, it lets you attach multiple independent handlers to the same event without one overwriting another.

The event object passed automatically to your handler carries useful details about what happened: event.target is the actual element the event originated on, event.currentTarget is the element the listener is attached to (these differ once you use event delegation), and for keyboard/mouse events there's event.key, event.clientX/clientY, and more depending on the event type.

For forms specifically, calling event.preventDefault() inside a submit handler stops the browser's default action — a full page navigation/reload — which is essential once you're handling the submission with JavaScript (validating it, sending it via fetch(), updating the page in place) instead of letting the browser do a traditional form post.

Events don't just fire on the exact element clicked — they bubble up through every ancestor element in the DOM tree, from the target outward to document. Event delegation exploits this: instead of attaching a listener to every individual item in a list (expensive, and broken for items added later), you attach one listener to a stable parent container and check event.target inside it to figure out which child was actually interacted with. This is both more efficient and automatically works for elements added to the DOM after the listener was attached.

Some events don't bubble by default (like focus and blur), but most do, and you can control the flow further with event.stopPropagation() (stops the event from bubbling further up) — though this should be used sparingly, since it can silently break other code (like an outer analytics listener) that expected to see the event.

Listeners you no longer need should be removed with removeEventListener(), which requires passing the exact same function reference used in addEventListener() — an inline arrow function can never be removed this way, since a new function object is created every time. In single-page applications where elements are frequently created and destroyed, forgetting to clean up listeners is one of the most common sources of memory leaks.

events.js
const form = document.querySelector("form");

form.addEventListener("submit", (event) => {
  event.preventDefault(); // stop the default page reload
  const email = form.querySelector("input[type=email]").value;
  console.log("Submitting:", email);
});
event-delegation.js
// One listener on the parent, instead of one per item —
// also automatically covers items added later.
const list = document.querySelector("#todo-list");

list.addEventListener("click", (event) => {
  if (event.target.matches(".delete-btn")) {
    const item = event.target.closest("li");
    item.remove();
  }
});

function addTodo(text) {
  const li = document.createElement("li");
  li.innerHTML = `${text} <button class="delete-btn">Delete</button>`;
  list.appendChild(li); // works with the delegated listener automatically
}
cleanup-mistake.js
// Bug: this can never be removed — a new function is created each call
function attachBroken() {
  window.addEventListener("scroll", () => console.log("scrolling"));
}

// Fix: keep a named reference so removeEventListener can find it
function attachFixed() {
  const onScroll = () => console.log("scrolling");
  window.addEventListener("scroll", onScroll);
  return () => window.removeEventListener("scroll", onScroll);
}
const cleanup = attachFixed();
// later, when this feature is torn down:
cleanup();
Key points
  • event.preventDefault() is essential for handling form submissions with JavaScript instead of a full page reload.
  • event.target is what was actually interacted with; event.currentTarget is the element the listener lives on — they differ under delegation.
  • Events bubble up from the target through every ancestor by default, which is what makes event delegation possible.
  • Event delegation (one listener on a parent, checking event.target) is more efficient than per-child listeners and automatically covers elements added later.
  • removeEventListener() requires the exact same function reference passed to addEventListener() — an inline arrow function can never be removed.
  • Always remove listeners you no longer need, especially in single-page apps, to avoid memory leaks from lingering references.
  • event.stopPropagation() stops bubbling, but use it sparingly — it can silently break other code that expected to observe the event.
Try it yourself

Build a form with an email input that logs the value to the console on submit, without reloading the page. Then build a small to-do list where each item has a delete button, using a single delegated click listener on the list container rather than one listener per button, and confirm newly added items are deletable without attaching any new listeners.
