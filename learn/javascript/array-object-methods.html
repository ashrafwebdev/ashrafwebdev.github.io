Array/object methods: map, filter, reduce, destructuring

JavaScript · part of the free zero-to-hero guide

map(), filter(), and reduce() are the three workhorses of working with arrays in modern JavaScript, and together they replace the vast majority of manual for-loops you'd otherwise write. map() transforms every item into something new, always returning a new array of exactly the same length. filter() keeps only the items for which a test function returns true, returning a new array that can be shorter (or the same length, or empty). reduce() is the most general of the three — it collapses an entire array down into a single accumulated value, which could be a sum, a new object, another array, or anything else.

None of these three methods mutate the array they're called on — they always return a brand new array (or, for reduce, whatever value you build), leaving the original untouched. This is a deliberate and important property: it makes code easier to reason about, since you never have to worry that calling .map() somewhere quietly changed data that other code still holds a reference to. Contrast this with mutating methods like .push(), .sort(), and .splice(), which change the array in place.

reduce(callback, initialValue) takes a callback of (accumulator, currentValue) => newAccumulator plus a starting value for the accumulator. Skipping the initial value is legal but risky — reduce will then use the array's first element as the starting accumulator and start iterating from the second element, which silently breaks (or behaves unexpectedly) on an empty array. Always pass an explicit initial value unless you have a specific reason not to.

Destructuring pulls values out of arrays or objects into named variables in a single expression, and it works almost anywhere a variable is normally assigned: in a plain assignment, in a function parameter list, and in a for...of loop. Array destructuring matches by position (const [first, second] = arr), while object destructuring matches by key name (const { name, age } = obj) and lets you rename or provide a default at the same time (const { name: userName = "Anonymous" } = obj).

Destructuring a function's parameters is an especially common and readable pattern — instead of a function taking a single options object and then manually pulling fields out of it line by line, you destructure directly in the parameter list, which also self-documents exactly which properties the function actually uses.

These methods are commonly chained: products.filter(...).map(...) reads naturally left to right, top to bottom, first narrowing down to the items you care about and then transforming them. For very large arrays, chaining several passes does mean iterating multiple times, so if performance in a hot path genuinely matters, a single reduce() (or a plain loop) that does everything in one pass can be faster — but readability should usually win unless profiling shows it's actually a bottleneck.

arrayMethods.js
const products = [
  { name: "Mug", price: 12 },
  { name: "Notebook", price: 5 },
  { name: "Pen", price: 2 },
];

const names = products.map((p) => p.name);
const affordable = products.filter((p) => p.price < 10);
const total = products.reduce((sum, p) => sum + p.price, 0);

const { name, price } = products[0]; // destructuring
reduce-building-an-object.js
// reduce isn't limited to summing numbers — it can build any shape
const products = [
  { name: "Mug", category: "kitchen", price: 12 },
  { name: "Pen", category: "office", price: 2 },
  { name: "Notebook", category: "office", price: 5 },
];

const byCategory = products.reduce((groups, product) => {
  const key = product.category;
  groups[key] = groups[key] || [];
  groups[key].push(product);
  return groups;
}, {});

console.log(byCategory.office.length); // 2

// Destructuring in a function parameter, with a default and a rename
function printProduct({ name, price, category: type = "misc" }) {
  console.log(`${name} ($${price}) — ${type}`);
}
printProduct(products[0]);
reduce-empty-array-gotcha.js
// Risky: no initial value, and the array happens to be empty
const totalRisky = [].reduce((sum, n) => sum + n);
// TypeError: Reduce of empty array with no initial value

// Safe: always pass an explicit initial value
const totalSafe = [].reduce((sum, n) => sum + n, 0);
console.log(totalSafe); // 0, no error
Key points
  • map always returns an array of the same length; filter can return fewer items; reduce can return anything at all.
  • None of these methods mutate the original array — they return a new one, unlike .push(), .sort(), or .splice().
  • Always pass an explicit initial value to reduce() — omitting it breaks on an empty array and can produce subtly wrong results otherwise.
  • Destructuring works on both arrays (const [a, b] = arr, matched by position) and objects (const { x, y } = obj, matched by key name).
  • Object destructuring can rename and default in one step: const { name: userName = "Anonymous" } = obj.
  • Destructuring directly in a function's parameter list both extracts values and documents exactly which fields the function uses.
  • Chaining is common and readable: products.filter(...).map(...) — but each link is a separate pass over the array, worth collapsing into one reduce() only if profiling shows it matters.
  • reduce() can build far more than a number — it's routinely used to build objects, group items, flatten nested arrays, or count occurrences.
Try it yourself

Given an array of product objects, use filter and reduce together to calculate the total price of only the items under $10. Then use reduce alone to group that same array of products by category into an object of arrays, and write a function that accepts a single destructured product argument (with a default for a missing category) and logs a formatted summary line.
