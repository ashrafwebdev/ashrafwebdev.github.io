ES6+ syntax: arrow functions, template literals, spread/rest

JavaScript · part of the free zero-to-hero guide

Template literals (backtick-delimited strings) let you embed expressions directly inside a string using ${...}, avoiding the awkward string concatenation of the past, and they support genuine multi-line strings without any special escape character — a plain newline inside the backticks becomes a newline in the resulting string.

Arrow functions offer terser syntax for short functions, and — more importantly than the brevity — they don't create their own this, arguments, or super binding, instead inheriting these from the surrounding lexical scope. This single property fixed one of the most common sources of bugs in pre-ES6 JavaScript: a callback losing track of the this its containing method expected.

The spread operator (...) expands an iterable (an array, a string, a Set, anything with an iterator) or the own enumerable properties of an object into individual elements, wherever a list of values or key-value pairs is expected — inside an array literal, an object literal, or a function call's argument list. It's the standard modern way to copy an array or object, merge several together, or turn a rest-collected set of arguments back into individual values for another call.

The rest parameter uses that exact same ... syntax but in the opposite direction, in a binding context (a function parameter list, or a destructuring pattern) rather than a value context — instead of expanding a collection into individual items, it collects multiple individual items into a single array. Which behavior you get depends entirely on where the ... appears, not on any different syntax.

Spread only performs a shallow copy: {...original} creates a genuinely new outer object, but any array or object nested inside as a property value is still the exact same reference as in the original — mutating that nested value through the copy also mutates it in the source, which is a routine source of subtle bugs when people assume spread gives a fully independent deep copy.

Tagged template literals are a lesser-known but powerful feature: prefixing a template literal with a function name (myTag`Hello ${name}`) calls that function with the literal's string pieces and interpolated values passed separately, which is exactly how libraries like styled-components implement CSS-in-JS, and how you'd build your own automatic HTML-escaping or internationalization helper.

es6.js
const name = "Amina";
console.log(`Hello, ${name}! Today is ${new Date().toDateString()}.`);

const original = { a: 1, b: 2 };
const copy = { ...original, c: 3 }; // spread: merge + add

const numbers = [1, 2, 3];
const moreNumbers = [...numbers, 4, 5]; // spread into a new array
rest-vs-spread.js
// Rest: collects individual arguments into an array (binding context)
function logAll(first, ...rest) {
  console.log("first:", first, "rest:", rest);
}
logAll(1, 2, 3, 4); // first: 1  rest: [2, 3, 4]

// Spread: expands an array into individual arguments (value context)
const nums = [5, 10, 15];
console.log(Math.max(...nums)); // same as Math.max(5, 10, 15)

// Destructuring with rest, on both arrays and objects
const [head, ...tail] = [1, 2, 3, 4];
const { id, ...otherFields } = { id: 1, name: "Mug", price: 12 };
console.log(head, tail, otherFields); // 1 [2,3,4] {name:"Mug", price:12}
shallow-copy-trap.js
const settings = { theme: "dark", advanced: { retries: 3 } };
const copy = { ...settings };

copy.theme = "light";           // fine, top-level, independent
copy.advanced.retries = 10;     // mutates the SHARED nested object

console.log(settings.theme);           // "dark" — unaffected
console.log(settings.advanced.retries); // 10 — affected! shallow copy
Key points
  • Template literals (backticks) support embedded expressions with ${} and genuine multi-line strings that plain quoted strings can't.
  • Arrow functions inherit this, arguments, and super from where they're defined, not how they're called.
  • Spread (...arr or ...obj) expands a collection into individual items; rest collects individual items into a collection — same syntax, opposite direction, distinguished by context.
  • Spread on objects ({...a, ...b}) is the standard way to merge objects immutably, with later spreads overriding earlier keys.
  • Spread and object/array destructuring both only copy one level deep — nested objects/arrays remain shared references between the original and the copy.
  • Rest parameters must be the last parameter in a function's argument list, and destructuring rest patterns must be the last item too.
  • Tagged template literals (tag`...`) pass the literal's pieces and interpolated values to a function separately, powering CSS-in-JS and escaping utilities.
Try it yourself

Write a function that merges two settings objects using spread, with the second object's values overriding the first's. Then demonstrate the shallow-copy trap directly: spread an object containing a nested object, mutate the nested value through the copy, and show the original was affected too. Finally write a small tagged template function that uppercases every interpolated value while leaving the surrounding string text unchanged.
