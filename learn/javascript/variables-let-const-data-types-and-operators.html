01 Zero stage

Variables (let/const), data types, and operators

JavaScript · part of the free zero-to-hero guide

JavaScript has three ways to declare a variable, but you should really only reach for two of them. let declares a variable that can be reassigned later; const declares one that can't be reassigned after its initial value is set. The older var is best avoided in new code — it scopes to the entire enclosing function rather than the block it's written in, which leads to variables leaking out of if-blocks and for-loops in ways that surprise almost everyone at least once.

Both let and const are block-scoped, meaning a variable declared inside a pair of curly braces (an if-block, a loop body, a function) simply does not exist outside of them. They also live in something called the temporal dead zone: the variable name is reserved from the top of its block, but accessing it before the declaration line throws a ReferenceError instead of silently returning undefined the way var would. This is a deliberate safety feature, not a bug.

JavaScript's primitive data types are number, string, boolean, null, undefined, and the less common bigint and symbol. Everything else — plain objects, arrays, functions, dates — is a reference type. The distinction matters constantly: primitives are compared and copied by value, while objects and arrays are compared and copied by reference, so two separately-created objects with identical contents are never === equal to each other.

Numbers in JavaScript are always 64-bit floating point, even when they look like integers, and that has real consequences. Adding 0.1 and 0.2 does not produce exactly 0.3 because of how binary floating point represents decimal fractions — it produces 0.30000000000000004. For money or anything requiring exact decimal precision, work in integer cents or use a dedicated decimal library rather than raw floats.

Operators fall into a few families worth knowing well: arithmetic (+ - * / % **), comparison (always prefer the strict === and !== over the loose == and !=, which perform surprising type coercion), logical (&& || !), and two newer additions that solve real pain points — the nullish coalescing operator ??, which falls back to a default only when the left side is null or undefined (not for other falsy values like 0 or an empty string), and optional chaining ?., which short-circuits to undefined instead of throwing when you access a property on something that might not exist.

A frequent source of confusion is that typeof null returns "object", which is a decades-old bug baked permanently into the language for backward compatibility, not a design choice you should imitate. To reliably check for null, compare directly against null rather than trusting typeof.

basics.js
const name = "Amina";
let age = 27;
age = 28; // let can be reassigned

const isAdult = age >= 18;
console.log(typeof name, typeof age, typeof isAdult);
coercion-and-defaults.js
// Loose equality performs surprising coercion — avoid it
console.log(0 == "0");     // true  (string coerced to number)
console.log(0 === "0");    // false (strict: different types)
console.log(null == undefined);  // true
console.log(null === undefined); // false

// Nullish coalescing vs plain OR: watch falsy values like 0
function getVolume(input) {
  const fallback = 50;
  return input ?? fallback; // only null/undefined trigger the fallback
}
console.log(getVolume(0));         // 0, not 50
console.log(getVolume(undefined)); // 50

// Optional chaining avoids manual null checks
const user = { profile: null };
console.log(user.profile?.bio ?? "No bio yet");
temporal-dead-zone.js
console.log(typeof neverDeclared); // "undefined", no error

Key points
  • Default to const; use let only when you know the value needs to change; avoid var entirely in new code.
  • let/const are block-scoped; var is function-scoped, which is the root of most of its bugs.
  • The temporal dead zone means accessing a let/const variable before its declaration line throws, rather than silently giving undefined.
  • Always use === and !==, not ==/!=, to avoid type coercion surprises.
  • Numbers are floating point — never compare decimal results for exact equality; round or compare within a small tolerance instead.
  • ?? only falls back on null/undefined, unlike ||, which also falls back on 0, an empty string, and false.
  • Objects and arrays are compared by reference, not by their contents, so two separately-built objects that look identical are never === equal.
  • typeof is handy for quick debugging, but remember its one famous quirk: typeof null is "object".
Try it yourself

Declare variables for your name, age, and favorite language using const/let appropriately, then log a sentence combining them using template literals. Then write a small function that takes a possibly-missing volume setting and returns it unchanged unless it is null or undefined, demonstrating why ?? is a better choice than || for that case.
