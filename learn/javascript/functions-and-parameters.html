Functions and parameters

JavaScript · part of the free zero-to-hero guide

Builds on: Conditionals and loops

A function packages up reusable logic so you don't repeat yourself. JavaScript offers several ways to define one: function declarations (function greet() {}), function expressions (const greet = function() {}), and arrow functions (const greet = () => {}). All three produce callable functions, but they differ in two important ways — hoisting behavior and how they handle this.

One quick note on the code example below: it builds its return value with a template literal, `Hello, ${name}!` — a backtick-delimited string that lets you embed a variable directly inside it with ${...} instead of stitching pieces together with +. That's a preview; template literals get a full explanation of their own in the upcoming ES6+ syntax lesson, but they're common enough in everyday code that it's worth recognizing the syntax now.

Function declarations are hoisted completely, meaning you can call one before its line in the file and it still works, because the whole function is set up before any code runs. Function expressions and arrow functions are not hoisted the same way — the variable holding them follows normal let/const rules, so calling one before its declaration throws.

Parameters can have default values (function greet(name = "friend")), which only kick in when the argument is undefined — passing null explicitly does not trigger the default. The rest parameter (...args) collects any number of trailing arguments into a real array, which is useful whenever a function needs to accept a variable number of inputs, like a sum or a logging helper.

JavaScript functions are values — they can be stored in variables, passed as arguments to other functions, and returned from other functions. This is what makes callbacks, .map()/.filter(), and higher-order functions possible. A function that takes another function as an argument, or returns one, is called a higher-order function, and they're everywhere in idiomatic JavaScript.

Arrow functions are more than shorthand — they deliberately do not create their own this, arguments object, or binding for super. They inherit all of those from the surrounding scope. This makes them ideal for short callbacks and for methods defined as class fields, but it also means an arrow function is the wrong tool when you actually need a dynamic this, such as certain object methods or constructor functions.

A function that doesn't explicitly return a value returns undefined — this is a common source of silent bugs, especially with .forEach() or .map() callbacks that use a block body with curly braces but forget the return keyword, silently producing an array full of undefined.

functions.js
function greet(name = "friend") {
  return `Hello, ${name}!`;
}

const add = (a, b) => a + b;

function sum(...numbers) {
  return numbers.reduce((total, n) => total + n, 0);
}

console.log(greet(), add(2, 3), sum(1, 2, 3, 4));
higher-order-functions.js
// Functions as values: passed in, returned out
function makeMultiplier(factor) {
  return function (n) {
    return n * factor;
  };
}

const double = makeMultiplier(2);
const triple = makeMultiplier(3);
console.log(double(5), triple(5)); // 10 15

// A function accepting a function: retry with a callback
async function retry(fn, attempts = 3) {
  for (let i = 0; i < attempts; i++) {
    try {
      return await fn();
    } catch (err) {
      if (i === attempts - 1) throw err;
    }
  }
}
common-mistake.js
// Forgetting `return` in a block-bodied arrow function
const doubled = [1, 2, 3].map((n) => {
  n * 2; // no return! result is undefined for every item
});
console.log(doubled); // [undefined, undefined, undefined]

// Fix: either add return, or drop the braces for an implicit return
const fixedA = [1, 2, 3].map((n) => {
  return n * 2;
});
const fixedB = [1, 2, 3].map((n) => n * 2); // implicit return, no braces
Key points
  • Arrow functions (=>) are shorter and don't create their own this, arguments, or super binding — they inherit these from the enclosing scope.
  • Function declarations are fully hoisted and callable before their line in the file; function expressions and arrow functions are not.
  • Default parameters (name = "friend") only apply when the argument is undefined, not when it's null.
  • The rest parameter (...args) must be the last parameter, and collects the remaining arguments into a real array.
  • A function without an explicit return returns undefined — a common silent bug with block-bodied arrow callbacks.
  • Arrow functions with a single expression and no braces have an implicit return; adding braces requires an explicit return.
  • Functions are first-class values in JavaScript — they can be stored, passed around, and returned like any other value, which is the basis of callbacks and higher-order functions.
Try it yourself

Write a function that takes any number of prices as arguments and returns their total using the rest parameter and reduce. Then write a makeMultiplier(factor) higher-order function that returns a new function multiplying its input by that factor, and demonstrate the forgotten-return bug with a block-bodied arrow function passed to map, followed by the fix.
