Colors, units (px, %, em, rem), and typography basics

CSS · part of the free zero-to-hero guide

Builds on: The box model: margin, border, padding, content

CSS colors can be named (red), hex (#1F4E44), or functional: rgb(31 78 68), hsl(165deg 43% 21%), or the newer oklch(), which is designed so that changing lightness doesn't accidentally shift perceived hue the way HSL sometimes does. All of the functional forms also accept an alpha channel, e.g. rgb(31 78 68 / 0.5), for transparency.

For sizing, px is an absolute unit (though it still scales if the user zooms); % is relative to some reference (usually the parent's size, though the exact reference varies by property); em is relative to the current element's own font size; rem is relative to the root (html) element's font size, wherever it's used in the document.

rem is usually the safer default for spacing and font sizes because it doesn't compound unpredictably the way nested em values can — three nested elements each set to 1.2em multiply on top of each other, while rem always resolves against the same root value no matter how deeply it's nested.

Viewport units (vw, vh) size relative to the browser window, useful for hero sections or full-bleed layouts, but risky for font sizes on their own since text can become unreadably small or huge at extreme widths — clamp(1rem, 2vw + 1rem, 2rem) combines a fixed floor, a fluid middle, and a fixed ceiling to get responsive type that never breaks.

line-height deserves special care: a unitless value like 1.6 scales proportionally with the element's own font size and is inherited as that raw ratio, which is almost always what you want. A value with a unit (24px) is inherited as a fixed pixel value instead, which can produce cramped or excessive spacing on child elements with a different font size.

Accessible body text is rarely set smaller than 16px (1rem at the default root size) — browsers, screen magnification, and low-vision users all rely on that baseline, and shrinking it below there is one of the most common accessibility mistakes in real sites.

styles.css
html { font-size: 16px; } /* 1rem = 16px by default */

h1 { font-size: 2.5rem; }   /* 40px, scales with root */
p  { font-size: 1rem; line-height: 1.6; color: #1A231F; }
.badge { padding: 0.5em 1em; } /* relative to the badge's own font size */
styles.css (fluid type with clamp)
h1 {
  /* min 1.75rem, ideal 4vw + 1rem, max 3rem — never too small or too huge */
  font-size: clamp(1.75rem, 4vw + 1rem, 3rem);
}

.panel {
  color: oklch(45% 0.08 165);          /* modern, perceptually uniform */
  background: rgb(31 78 68 / 0.08);    /* rgb() with alpha, space-separated syntax */
}
common mistake: nested em compounding
/* Each level multiplies on top of the last: 1.2 * 1.2 * 1.2 ≈ 1.73× the base */
ul { font-size: 1.2em; }
ul ul { font-size: 1.2em; }
ul ul ul { font-size: 1.2em; }

/* Fix: use rem so every level resolves against the same root size */
ul, ul ul, ul ul ul { font-size: 1.2rem; }
Key points
  • Prefer rem for font sizes and spacing; reach for em when you deliberately want sizing relative to the element itself (like padding on a badge).
  • line-height without a unit (e.g. 1.6) scales proportionally with font size and inherits cleanly — this is usually what you want.
  • Accessible body text is rarely smaller than 16px (1rem) by default.
  • clamp(min, ideal, max) gives you fluid sizing that still has a safe floor and ceiling.
  • Nested em values compound multiplicatively with each nesting level, which is a common source of runaway font sizes.
  • oklch() and hsl() colors are easier to reason about than hex when you need to tweak lightness or saturation predictably.
  • Functional color notations accept an alpha channel directly, e.g. rgb(0 0 0 / 0.5), without needing a separate opacity property.
Try it yourself

Build a small typographic scale (h1 through p) using only rem units, then change the root font-size and confirm everything scales together. Then convert the h1 to use clamp() for fluid sizing, and test it at three different viewport widths in DevTools' responsive mode.
