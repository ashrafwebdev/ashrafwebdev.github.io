02 Learning stage capstone

A fully responsive landing page, 320px to 1920px

CSS · ties together everything in the Learning stage

This project takes a single-page product or portfolio landing page — hero section, a row of feature cards, and a footer — and makes it work convincingly at every width from a small phone up through a large desktop monitor, using Flexbox, Grid, media queries, and CSS positioning together.

The test here isn't "does it look fine on my laptop" — it's whether the page holds up continuously as you resize the browser, not just at a couple of screenshot-friendly breakpoints. You'll build it mobile-first, adding complexity as space becomes available, rather than designing wide and cramming things down for small screens afterward.

You'll also add real interactivity for the first time — hover and focus transitions — and at least one element that behaves differently once you scroll past it, using position: sticky.

  • Flexbox for one-dimensional layout
  • CSS Grid for two-dimensional layout
  • Responsive design and media queries
  • Positioning: relative, absolute, fixed, sticky
  • Transitions and simple hover/focus states
Requirements
  • A mobile-first layout: base styles target a narrow viewport, and min-width media queries add complexity as the screen grows — not the reverse.
  • A hero section arranged with Flexbox (heading, subheading, and a call-to-action button aligned along one axis) that reflows sensibly from a stacked column on mobile to a row on wider screens.
  • A feature-card grid built with CSS Grid, using either explicit column counts with a media query or repeat(auto-fit, minmax(...)), that never lets a card shrink below a readable width.
  • A sticky header or sticky section label that stays visible while its section scrolls, verified working (not silently broken by an ancestor's overflow).
  • At least one hover and one :focus-visible transition on an interactive element (the CTA button, at minimum), using a short duration and naming the specific property being transitioned rather than all.
  • The <meta name="viewport"> tag present, and the layout tested at three distinct widths in DevTools' responsive mode: roughly 320px, 768px, and 1440px.
  • No horizontal scrollbar appears at any width in that range.
Suggested approach
  1. Build the content and structure first at a single, narrow width, with no media queries at all — get the page correct and readable before making it responsive.
  2. Convert the hero and card sections to Flexbox and Grid respectively while still only targeting the narrow layout, so you're not fighting two problems (layout system + responsiveness) at once.
  3. Add your first min-width media query once you can see, by actually resizing the browser, where the narrow layout starts to look sparse — not at a number you picked in advance.
  4. Add the sticky element and interaction states after the core layout is stable, since sticky positioning depends on the surrounding layout already being correct.
  5. Finish by sweeping continuously from 320px to 1920px in DevTools, watching for any point where content overlaps, overflows, or the horizontal scrollbar appears.
Stretch goals
  • Replace one of your fixed breakpoints with a fluid technique instead — swap a card grid's media query for repeat(auto-fit, minmax(...)), or a heading's breakpoint-based font size for clamp().
  • Add a prefers-reduced-motion media query that shortens or disables your transitions, and verify it using DevTools' rendering emulation.
  • Test the page with a real phone (not just DevTools emulation) on your home Wi-Fi and note anything that looks different from the emulator.
