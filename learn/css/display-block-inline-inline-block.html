01 Zero stage

display: block, inline, inline-block

CSS · part of the free zero-to-hero guide

The display property controls how an element behaves in the page's flow. block elements (like div, p, h1) take the full available width by default and always start on a new line. inline elements (like span, a, strong) flow within surrounding text and ignore any width/height you set on them.

inline-block is a hybrid: it flows inline like text (sitting next to other inline content, wrapping naturally), but respects width, height, and vertical padding/margin like a block does. It's less common today now that Flexbox and Grid exist for arranging groups of elements, but it's still genuinely useful for small standalone inline UI pieces like tags or badges that need a fixed size.

Inline and inline-block elements are sensitive to whitespace in your HTML source: a line break or space between two inline-block elements in the markup renders as a small visible gap between them, which surprises people expecting the CSS box model alone to control spacing. Common fixes are removing the whitespace in the markup, using font-size: 0 on the parent, or (better) switching to Flexbox with gap, which doesn't have this quirk at all.

Only horizontal margin and padding reliably affect layout on inline elements — vertical margin is ignored, and vertical padding is drawn but doesn't push surrounding lines apart, which can make an inline element visually overlap the line above or below it if you're not careful.

display: none removes an element from layout entirely, as if it were never in the document — no space is reserved for it, and it's inaccessible to screen readers by default. This is different from visibility: hidden, which keeps the element's space reserved but makes it invisible, and different again from opacity: 0, which keeps it visible to layout, screen readers, and even mouse clicks unless you also disable pointer events.

Modern CSS also has display: flex, display: grid, and multi-keyword forms like display: inline flex, which describe both how the element itself flows (its 'outer' display) and how its children are laid out (its 'inner' display) — the classic block/inline/inline-block trio only covers the outer half of that picture.

styles.css
span.tag {
  display: inline-block;
  padding: 4px 10px;
  background: #E7F0EA;
  border-radius: 12px;
}

div.section { display: block; } /* default for div anyway */
styles.css (the inline-block whitespace gap)
/* HTML has a newline between these spans, so a small gap appears
   between the rendered tags even with no margin set: */
/* <span class="tag">A</span>
   <span class="tag">B</span> */

.tag-row { font-size: 0; }      /* collapses the whitespace gap... */
.tag-row .tag { font-size: 14px; } /* ...then restore text size on the tags */

/* Usually simpler: skip inline-block for grouped items and use Flexbox */
.tag-row-flex { display: flex; gap: 8px; }
Key points
  • block: full width, new line, respects width/height/margin on all sides.
  • inline: flows with text, ignores width/height, only horizontal margin/padding reliably affects layout.
  • inline-block: flows with text but respects box-model sizing like a block, at the cost of whitespace-sensitive gaps between elements.
  • display: none removes the element from layout and the accessibility tree entirely — different from visibility: hidden (keeps space, hides visually) and opacity: 0 (fully present, just invisible).
  • Whitespace in the HTML source between inline-block elements renders as a visible gap; Flexbox with gap avoids this problem entirely.
  • Modern display values (flex, grid) describe both the element's own flow and its children's layout model, going beyond the classic block/inline/inline-block distinction.
Try it yourself

Take three span elements and set them to inline, then inline-block with fixed widths, and observe the layout difference in each case. Then reproduce the inline-block whitespace gap between two of them, fix it two different ways (removing markup whitespace, and switching the parent to flex with gap), and compare the results.
