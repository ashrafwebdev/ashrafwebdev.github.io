Subgrid and advanced Grid layouts

CSS · part of the free zero-to-hero guide

Builds on: Container queries and intrinsic responsive design

Normally, a nested grid can't align its tracks with its parent grid's tracks — each grid manages its own columns/rows independently, even if it happens to live inside a grid cell. subgrid lets a nested grid inherit its parent's track sizing directly, which is exactly what you need for things like aligned card rows where each card's internal title/body/footer should line up across every sibling, not just within itself.

To use it, set grid-template-columns: subgrid (or rows) on the nested grid instead of defining its own track sizes — it then shares the exact same column boundaries as the number of parent tracks it spans, so content in different child grids lines up pixel-for-pixel without any manual width matching.

Combined with named grid lines ([content-start], [content-end]) and grid-template-areas, Grid becomes powerful enough to express entire page layouts — header, sidebar, main, footer — in a single, readable declaration that reads almost like a diagram of the page.

minmax() combined with repeat() inside a track definition lets a single line express both a hard minimum and a flexible maximum per track, which is the backbone of responsive grids that never let a column shrink below a usable width.

Grid supports explicit placement (naming exact line numbers or areas) and implicit placement (letting auto-placement flow items into unnamed tracks) at the same time within one grid — grid-auto-flow: dense in particular back-fills gaps left by irregularly-sized items, which is useful for masonry-like galleries with mixed item sizes.

Subgrid support is what finally made 'align these cards' internal content across a row' solvable without JavaScript measurement hacks — before it, developers either accepted misaligned internal content or resorted to measuring the tallest element with JS and forcing everything else to match.

styles.css
.page {
  display: grid;
  grid-template-areas:
    "header header"
    "sidebar main"
    "footer footer";
  grid-template-columns: 240px 1fr;
}
.header { grid-area: header; }
.sidebar { grid-area: sidebar; }
.main { grid-area: main; }
styles.css (subgrid aligning cards' internal rows)
.card-row {
  display: grid;
  grid-template-columns: repeat(3, 1fr);
  gap: 16px;
}

.card {
  display: grid;
  grid-row: span 3;
  grid-template-rows: subgrid; /* inherits the row tracks the card spans */
}
/* Now every card's title, body, and footer row line up across the whole row,
   even if one card's title wraps to two lines and another's doesn't. */
styles.css (dense auto-flow for a mixed masonry-like gallery)
.gallery {
  display: grid;
  grid-template-columns: repeat(auto-fill, minmax(150px, 1fr));
  grid-auto-flow: dense; /* back-fills gaps left by wide/tall items */
  gap: 12px;
}
.gallery .wide { grid-column: span 2; }
.gallery .tall { grid-row: span 2; }
Key points
  • grid-template-columns: subgrid; on a nested grid inherits the parent's column tracks exactly.
  • grid-template-areas lets you sketch a layout visually in the CSS itself, which reads almost like ASCII art.
  • Named lines ([content-start]) make complex grids far more self-documenting than raw track numbers.
  • minmax() inside repeat() gives a track both a hard minimum and a flexible maximum in one declaration.
  • grid-auto-flow: dense back-fills layout gaps left by irregularly-sized items, useful for masonry-like galleries.
  • Subgrid is what finally made 'align these cards' internal content across a row' solvable without JavaScript measurement hacks.
  • A nested grid without subgrid manages its own tracks independently, even when it lives inside a parent grid's cell.
Try it yourself

Build a page layout (header/sidebar/main/footer) using grid-template-areas, then use subgrid to align a row of cards' internal title/body/footer across all cards. Deliberately give one card a longer title that wraps to two lines, and confirm the subgrid keeps every card's body and footer aligned despite that difference.
