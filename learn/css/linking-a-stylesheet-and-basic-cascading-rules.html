01 Zero stage

Linking a stylesheet and basic cascading rules

CSS · part of the free zero-to-hero guide

Builds on: display: block, inline, inline-block

CSS reaches a page one of three ways: an external stylesheet via <link rel="stylesheet"> in the head (best practice — cacheable across pages, keeps markup and styling separate), an inline <style> block inside the document (fine for a single page or a quick prototype), or a style attribute directly on an element (highest specificity of the three, hardest to maintain at scale, generally avoided except for values computed dynamically by JavaScript).

"Cascading" describes how CSS resolves conflicting declarations for the same property on the same element, combining several factors in order: origin and importance (browser defaults vs. your styles vs. !important rules), then specificity, and finally source order as the tiebreaker when the previous two are equal.

Browsers ship with a built-in stylesheet (user-agent styles) that gives elements like h1, ul, and button default margins, sizes, and appearances before any of your CSS runs. This is why a fresh HTML page already has visible spacing and styled buttons — and why many projects start with a small 'reset' or 'normalize' stylesheet to flatten those inconsistent defaults before building on top.

Multiple <link> stylesheets are applied in the order they appear in the document, and a later stylesheet's rule beats an earlier stylesheet's rule of equal specificity — so the order you list your <link> tags in the head genuinely matters, not just the order of rules within a single file.

CSS also cascades based on inheritance, separate from the conflict-resolution cascade above: some properties (like color, font-family, line-height) are inherited by default from parent to child unless overridden, while others (like margin, border, width) are not, because inheriting box-model properties would make layout unpredictable.

The @import rule lets one stylesheet pull in another, but it blocks parallel downloading (the browser can't start fetching the imported file until it's parsed the importing one) and is generally slower in production than simply adding another <link> tag in the HTML head.

index.html
<head>
  <link rel="stylesheet" href="reset.css">
  <link rel="stylesheet" href="styles.css">
</head>
styles.css (inheritance vs. no inheritance)
body {
  color: #1A231F;      /* inherited: every descendant text uses this unless overridden */
  font-family: sans-serif; /* inherited */
  border: 1px solid #ccc;  /* NOT inherited: only body itself gets a border */
}

/* Force inheritance on a property that normally wouldn't be inherited */
.themed-box * { border-color: inherit; }
Key points
  • External stylesheets (<link>) are cached by the browser and shared across pages — prefer this over inline styles or style blocks.
  • The cascade resolves conflicts in order: origin/importance, then specificity, then source order.
  • Browsers apply their own default (user-agent) stylesheet before yours — a CSS reset or normalize file flattens those inconsistencies.
  • Multiple <link> stylesheets apply in document order; a later one wins ties over an earlier one at equal specificity.
  • Some CSS properties (color, font-family) inherit from parent to child by default; box-model properties (margin, border, width) do not.
  • @import blocks parallel downloads and is usually slower than an additional <link> tag in production.
  • Rules lower in the same file override earlier rules of equal specificity.
Try it yourself

Create a separate styles.css file, link it from an HTML page, and confirm changes to the CSS file are picked up on refresh. Then add a second stylesheet with a conflicting rule of equal specificity, link it after the first, and confirm the second one's rule wins.
