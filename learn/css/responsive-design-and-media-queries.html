Responsive design and media queries

CSS · part of the free zero-to-hero guide

Builds on: CSS Grid for two-dimensional layout

Responsive design means a layout adapts to whatever screen it's viewed on, from a phone to a large monitor, using a mix of fluid layout techniques (Flexbox, Grid, relative units) and media queries for the cases that genuinely need different rules at different sizes rather than just different amounts of space.

Media queries are conditional CSS blocks that apply only when the viewport matches certain conditions, most commonly a maximum or minimum width, but also things like orientation, hover capability, or a user's reduced-motion preference — media queries aren't only about screen size.

The best practice is mobile-first: write your base styles for small screens, then use min-width media queries to add complexity as the screen grows. This tends to produce simpler CSS than desktop-first (max-width-based) because small-screen styles are usually the simpler baseline, and you're only adding rules, not constantly overriding a more complex starting point.

Common breakpoints (600px, 768px, 1024px) are guidelines borrowed from typical device sizes, not rules — the right place to break a layout is wherever your specific content starts to look cramped or overly sparse, which you find by actually resizing the browser and watching, not by copying someone else's numbers.

Always include <meta name="viewport" content="width=device-width, initial-scale=1.0"> in the HTML head. Without it, mobile browsers render the page at a desktop-width virtual viewport (typically 980px) and then zoom out to fit, which makes your media queries fire at the wrong effective widths and your text appear tiny.

Beyond media queries, modern responsive CSS increasingly relies on fluid techniques that need no breakpoints at all: clamp() for fluid type, minmax() and auto-fit in Grid, and flex-wrap in Flexbox — reach for a media query once those fluid tools genuinely can't express the change you need (e.g. hiding a whole section on small screens).

styles.css (mobile-first)
.cards { display: flex; flex-direction: column; gap: 16px; }

@media (min-width: 768px) {
  .cards { flex-direction: row; }
}
styles.css (non-size media features)
/* Only apply hover styles on devices that actually support hovering */
@media (hover: hover) {
  .card:hover { transform: translateY(-2px); }
}

/* Respect a user's OS-level reduced-motion preference */
@media (prefers-reduced-motion: reduce) {
  * { animation: none !important; transition: none !important; }
}
common mistake: missing viewport meta tag
<!-- Without this, mobile browsers render at ~980px and zoom out,
     so a 768px min-width media query never fires on a real phone -->
<meta name="viewport" content="width=device-width, initial-scale=1.0">
Key points
  • Mobile-first: base styles for small screens, min-width queries add complexity for larger ones.
  • Common breakpoints (600px, 768px, 1024px) are guidelines, not rules — let your content decide where it breaks.
  • Always include the viewport meta tag, or media queries won't behave correctly on real mobile devices.
  • Media queries can test more than width: hover, orientation, and prefers-reduced-motion are all valid features.
  • Prefer fluid techniques (clamp, auto-fit, flex-wrap) over breakpoints when the tool can express the change without one.
  • Test with real device widths in DevTools' responsive mode, not just by shrinking your desktop browser window freehand.
  • Desktop-first (max-width) media queries tend to produce more override-heavy CSS than mobile-first (min-width) ones.
Try it yourself

Take a layout you've built and add a mobile-first media query that changes it from a single column to a multi-column row at 768px. Then add a second media query using prefers-reduced-motion that disables any transitions or animations on the page, and verify it by enabling 'reduce motion' in DevTools' rendering emulation panel.
