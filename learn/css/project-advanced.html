03 Advanced stage capstone

A themeable component library with light and dark mode

CSS · ties together everything in the Advanced stage

You're building a small library of reusable UI components — buttons, cards, a form field, a badge — styled entirely through a layered set of CSS custom properties, with a working dark mode driven by prefers-color-scheme and no JavaScript required to switch themes automatically.

The real skill being tested is indirection: instead of hardcoding colors and spacing into each component, you route everything through variables, so that redefining a handful of values at the root is enough to reskin the entire library — light to dark, or brand color A to brand color B — without touching a single component rule.

You'll also pick one CSS architecture (BEM, utility-first, or CSS Modules-style naming conventions) and apply it consistently across every component, rather than mixing approaches, since consistency is the thing that actually keeps a component set maintainable as it grows.

  • Custom properties (CSS variables) and theming
  • Keyframe animations and transform performance
  • CSS architecture: BEM, utility-first (Tailwind-style), or CSS Modules
  • Sass/Less: nesting, mixins, functions
  • Dark mode with prefers-color-scheme
Requirements
  • A set of custom properties defined on :root covering at minimum: 2-3 brand colors, a text/background pair, a spacing scale (3-4 steps), and a border-radius value — every component reads its values through var(), with no hardcoded hex codes or pixel values inside a component rule.
  • At least four distinct components (e.g. button, card, badge, form field) each with at least one interactive state (hover and/or focus) using a transition on transform and/or a color property, never on all.
  • A working dark theme implemented entirely via @media (prefers-color-scheme: dark) redefining the same custom property names — no component rule is duplicated or rewritten for dark mode.
  • At least one component with a variant (e.g. a "danger" button, a "featured" card) that overrides just one custom property locally, demonstrating that the override doesn't leak outside its own subtree.
  • One consistent naming convention applied to every component (pick BEM, utility classes, or CSS-Modules-style scoped names) with no mixing of approaches within the library.
  • At least one component built with CSS Grid or Flexbox internally (e.g. a card with a header/body/footer arrangement) that still holds together correctly at a narrow width.
  • A single demo HTML page showing every component and its variants side by side, in both light and dark mode (toggle your OS setting or use DevTools' rendering emulation to confirm both render correctly).
Suggested approach
  1. Define your token set first — colors, spacing, radius — before writing a single component rule, so every component you build afterward has values to reach for immediately.
  2. Build one component completely (structure, states, responsive behavior) using only your tokens, and treat it as the template pattern for the rest.
  3. Build the remaining components next, reusing the same tokens and naming convention, resisting the temptation to add a one-off hardcoded value "just this once."
  4. Add the dark-mode media query only after every component is fully working in light mode, redefining just the root variables rather than touching component rules.
  5. Build the demo page last, and use it to actually spot inconsistencies — a color that snuck in as a hex code, a component that doesn't have a hover state its siblings all have.
Stretch goals
  • Add a manual light/dark/system toggle with a small amount of JavaScript that sets a data-theme attribute on <html>, overriding the media-query default.
  • Rebuild your token file in Sass using a map and an @each loop to generate the spacing-scale custom properties instead of writing each one by hand.
  • Run a contrast check on your text/background pairs in both themes and adjust any pair that fails WCAG AA, noting that a pair passing in light mode isn't guaranteed to pass in dark mode.
