01 Zero stage capstone

Your résumé page, styled by hand

CSS · ties together everything in the Zero stage

You already have a plain HTML résumé page from the HTML track — now you're going to give it fonts, color, and breathing room using only the five CSS ideas this stage covers: selectors and specificity, the box model, colors and units, the block/inline/inline-block display trio, and a linked external stylesheet. Nothing else is available to you yet, and that's the point.

The constraint that makes this a real test is: one external stylesheet, zero inline style attributes, zero <style> blocks in the HTML. Every visual decision has to be expressed as a selector in styles.css, which forces you to actually think about which class or element you're targeting and why, instead of reaching for the nearest tag to patch.

By the end, the same underlying HTML document should look like a page someone designed on purpose — consistent spacing, a readable type scale, a limited color palette — without you having touched Flexbox, Grid, or a single line of JavaScript.

  • Selectors and specificity
  • The box model: margin, border, padding, content
  • Colors, units (px, %, em, rem), and typography basics
  • display: block, inline, inline-block
  • Linking a stylesheet and basic cascading rules
Requirements
  • One external stylesheet linked from the <head> with <link rel="stylesheet"> — no inline style attributes and no <style> blocks anywhere in the HTML.
  • box-sizing: border-box set globally, and at least one deliberately styled box (a card or the page container) with visible padding, a border, and a margin, sized so the numbers behave the way you predicted.
  • A type scale using rem for every font size — headings, body text, and any small print — with body text no smaller than 1rem.
  • A limited, consistent color palette (2-4 colors total) applied via at least two different selector types: an element selector, a class selector, and one pseudo-class (a:hover at minimum).
  • At least one place where display: inline-block is used deliberately and correctly (for example, a small skill tag or badge next to your name) rather than left at its default.
  • No two rules in your stylesheet fight over the same property on the same element — if you find yourself needing !important anywhere, that's a sign to simplify the selector instead.
Suggested approach
  1. Start by linking an empty stylesheet and confirming a trivial change (like changing the page background) actually shows up — get the wiring right before styling anything real.
  2. Set box-sizing: border-box globally first, then style the overall page container's width, padding, and margin so you have a stable canvas to work inside.
  3. Build your type scale next: pick a root font size, then set heading and body sizes in rem before touching color at all.
  4. Add color last, applied through classes rather than bare tag selectors wherever a class already exists, so a future change to "body text color" doesn't require hunting through unrelated rules.
  5. Finish with the small details — the inline-block badge, the link hover state — and check every rule's specificity is no higher than it needs to be.
Stretch goals
  • Rebuild your color palette using hsl() instead of hex codes, and try shifting just the lightness value to generate a matching hover shade.
  • Add a print stylesheet using <link rel="stylesheet" media="print"> that hides anything irrelevant on paper (like a badge or decorative background).
  • Open DevTools' Computed panel on three different elements and, for each, identify exactly which rule in your stylesheet won and why.
