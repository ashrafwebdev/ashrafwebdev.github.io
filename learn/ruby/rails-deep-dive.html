Rails deep dive: associations, validations, callbacks

Ruby · part of the free zero-to-hero guide

Associations (has_many, belongs_to, has_and_belongs_to_many) declare relationships between models, letting ActiveRecord generate the methods and queries to navigate between related records naturally.

Validations run automatically before saving a record, rejecting invalid data before it hits the database. Callbacks (before_save, after_create) hook into a record's lifecycle to run code at specific points — useful, but easy to overuse into hidden, hard-to-trace behavior.

models/author.rb + book.rb
class Author < ApplicationRecord
  has_many :books
end

class Book < ApplicationRecord
  belongs_to :author
  validates :title, presence: true
  before_save :normalize_title

  private

  def normalize_title
    self.title = title.strip
  end
end
Key points
  • has_many/belongs_to pairs must be declared on both sides of a relationship to work correctly.
  • Validations run on save/create, not automatically on direct database writes that bypass ActiveRecord.
  • Callbacks run implicitly whenever their trigger occurs — overusing them can make it hard to trace what actually happens when a record saves.
  • N+1 queries from unoptimized association access are a common Rails performance trap — includes solves it by eager loading.
