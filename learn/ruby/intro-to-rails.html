Intro to Rails: MVC, routes, views

Ruby · part of the free zero-to-hero guide

Ruby on Rails is a full-stack web framework built around two guiding principles: convention over configuration, and don't repeat yourself. Following Rails' naming and folder conventions means far less explicit configuration than most other frameworks require — a model named Book, a table named books, and a controller named BooksController are all connected automatically, with no config file spelling out those relationships.

Rails structures an app as Model-View-Controller: models represent and validate data (backed by ActiveRecord), controllers receive an incoming request, coordinate whatever work is needed, and prepare data for a response, and views render that data into HTML (or JSON, or another format). This separation keeps business logic, request handling, and presentation from tangling together as an application grows.

Routes, declared in config/routes.rb, map incoming URLs and HTTP verbs to specific controller actions. resources :books is a single line that generates a full set of conventional RESTful routes — index, show, new, create, edit, update, destroy — covering the typical CRUD lifecycle for a resource, instead of requiring each route to be written out individually.

Instance variables set inside a controller action, like @books = Book.all, are automatically available inside the corresponding view without being passed explicitly — Rails wires this up by convention based on the controller and action name, which is convenient but also means it's easy to lose track of exactly which instance variables a given view depends on in a larger app.

Views are typically written in ERB (.html.erb), embedding Ruby inside HTML with <%= ... %> to output a value and <% ... %> to run Ruby logic without printing anything. Partial views (files prefixed with an underscore, like _book.html.erb) let you extract and reuse a repeated chunk of markup, such as a single book's display card, across multiple pages.

Running rails routes in the terminal lists every route the application currently defines, including the HTTP verb, URL pattern, and the controller action it maps to — an essential debugging tool the moment a request returns a routing error or hits an unexpected action.

config/routes.rb + a controller action
# config/routes.rb
Rails.application.routes.draw do
  resources :books
end

# app/controllers/books_controller.rb
class BooksController < ApplicationController
  def index
    @books = Book.all  # available to the view
  end
end
app/views/books/index.html.erb
<h1>Books</h1>

<ul>
  <% @books.each do |book| %>
    <li><%= book.title %> by <%= book.author %></li>
  <% end %>
</ul>

<%= link_to "New book", new_book_path %>
Terminal
$ rails routes | grep books
book_index GET    /books          books#index
           POST   /books          books#create
new_book   GET    /books/new      books#new
edit_book  GET    /books/:id/edit books#edit
book       GET    /books/:id      books#show
           PATCH  /books/:id      books#update
           DELETE /books/:id      books#destroy
Key points
  • resources :books generates a full set of RESTful routes (index, show, new, create, edit, update, destroy) in one line.
  • Instance variables set in a controller action (@books) are automatically available in the corresponding view.
  • Rails looks for a view file matching the controller action's name by convention -- app/views/books/index.html.erb for the index action.
  • rails routes in the terminal lists every route your app currently defines, which is the first place to check when a URL doesn't behave as expected.
  • ERB uses <%= %> to output a value into the page and <% %> to run logic silently.
  • Partial views (filenames starting with an underscore) let you reuse a chunk of markup across multiple pages.
  • Convention over configuration means the model name, table name, and controller name are linked automatically by naming alone, with no explicit wiring required.
Try it yourself

Generate a new Rails app, define a resourceful route for a single model, and confirm rails routes shows the expected RESTful routes. Then build out the index and show views with ERB, extract the repeated per-item markup into a partial, and add a link_to from the index page to each item's show page.
