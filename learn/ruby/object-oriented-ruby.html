Object-oriented Ruby: classes, modules, mixins

Ruby · part of the free zero-to-hero guide

Ruby classes use class Name ... end, with initialize serving as the constructor, invoked automatically whenever you call ClassName.new. Every class implicitly inherits from Object (which itself descends from BasicObject), and single inheritance works with class Dog < Animal, giving the subclass access to the parent's public and protected methods.

Instance variables (@name) are private to an object by default and are not accessible from outside without an explicit accessor method. attr_reader, attr_writer, and attr_accessor auto-generate those getter and setter methods for you, eliminating a large amount of otherwise-repetitive boilerplate that would exist in languages requiring explicit getters and setters for every field.

Modules group related methods and constants together, and — unlike classes — a module cannot be instantiated on its own; instead it can be 'mixed in' to one or many classes with include (adding instance methods) or extend (adding class-level methods), giving Ruby a clean, deliberate alternative to multiple inheritance called a mixin. A class can include as many modules as it likes, even though it can only subclass one other class.

When a module is included, Ruby inserts it into the class's method lookup chain, which you can inspect directly by calling SomeClass.ancestors — this reveals the actual order Ruby searches when resolving a method call, and it's the tool to reach for when two included modules define a method with the same name and the resolution order isn't obvious at a glance.

Method visibility comes in three levels: public (the default, callable from anywhere), private (callable only without an explicit receiver, essentially only from inside the same object), and protected (callable from other instances of the same class or its subclasses, useful for things like comparison methods that need to read another instance's internal state).

Ruby's built-in Comparable module is a good showcase of the mixin pattern in the standard library: a class only needs to implement the spaceship comparison method, and including Comparable automatically supplies working <, >, ==, <=, >=, and between? methods built on top of that one comparison, entirely for free.

classes.rb
module Greetable
  def greet
    "Hello, I'm #{name}"
  end
end

class Person
  include Greetable
  attr_reader :name

  def initialize(name)
    @name = name
  end
end

puts Person.new("Amina").greet
visibility_and_ancestors.rb
class Account
  def initialize(balance)
    @balance = balance
  end

  def richer_than?(other)
    balance > other.balance  # protected lets us read other's balance
  end

  protected

  attr_reader :balance
end

a = Account.new(100)
b = Account.new(50)
puts a.richer_than?(b)     # true
puts Account.ancestors.first(3).inspect
comparable_mixin.rb
class Money
  include Comparable
  attr_reader :cents

  def initialize(cents)
    @cents = cents
  end

  def <=>(other)
    cents <=> other.cents  # define ONE method...
  end
end

a, b = Money.new(500), Money.new(300)
puts a > b            # ...get <, >, ==, between? for free
puts [a, b].sort.map(&:cents).inspect
Key points
  • attr_reader/attr_writer/attr_accessor auto-generate getter/setter methods for instance variables, removing boilerplate.
  • include mixes a module's instance methods into a class; extend mixes them in as class-level methods instead.
  • Instance variables (@name) are private to an object by default, unlike local variables.
  • Ruby supports single class inheritance, but unlimited module mixins, which is how it approximates multiple inheritance's benefits without the ambiguity.
  • SomeClass.ancestors reveals the actual method lookup chain, which is essential when included modules could otherwise define conflicting method names.
  • private methods can't be called with an explicit receiver; protected methods can be called on other instances of the same class.
  • Including the built-in Comparable module and defining one comparison method gives you a whole family of comparison operators for free.
  • A module cannot be instantiated directly with .new -- it exists purely to be mixed in or used as a namespace.
Try it yourself

Create a Greetable module with a greet method, and mix it into two unrelated classes (like Person and Robot) that each define their own name. Then write a Temperature class that includes Comparable by implementing the spaceship comparison method, and demonstrate sorting an array of Temperature instances using the comparison operators that Comparable supplies automatically.
