04 Hero stage capstone

Extract and publish a real, tested RubyGem from RecipeBox

Ruby · ties together everything in the Hero stage

Somewhere inside RecipeBox is a piece of logic that doesn't actually depend on Rails or a database at all — the ingredient-list formatting module, the recipe-scaling math, or the comparison logic for sorting recipes by some derived score. This project asks you to find that piece, cut it free from the app, and turn it into a real, independently published RubyGem: a genuine artifact a stranger could install and use, with no idea RecipeBox ever existed.

This is the capstone of the whole Ruby track, and it's meant to feel like the real thing, not a simulation of it. You'll scaffold a proper gem structure, write a full RSpec suite against the extracted logic in isolation, document a public API a stranger could follow without asking you questions, and actually build and locally install the .gem file to prove it works outside your app's context. Publishing to RubyGems.org (even under a throwaway or clearly-marked-experimental name) is the final proof that the whole pipeline — from an idea inside a Rails app to an installable package anyone can pull down with gem install — genuinely works end to end.

The bar mirrors the rest of this roadmap's Hero-stage capstones: not "it works inside my app," but "a stranger could drop this into an unrelated project by reading the README, with no surprises and no hidden Rails dependency lurking underneath."

  • Building and publishing gems
  • Architecting large, multi-team Rails applications

Requirements
  • A logic module extracted from RecipeBox that has zero dependency on Rails, ActiveRecord, or a database — it should run and pass its tests in a bare Ruby process with nothing but the gem's own code loaded.
  • A gem scaffolded with bundle gem, with a correctly filled-out gemspec: name, version, summary, author, license, and an accurate file list that includes the library code and excludes test-only files.
  • A comparison-friendly object somewhere in the extracted logic that implements a spaceship comparison method and includes Ruby's Comparable module, giving it working comparison operators and sorting for free, exercised by at least one test that sorts a collection of the object.
  • A full RSpec suite for the gem, run and passing entirely outside of RecipeBox (a fresh clone or fresh directory with no Rails app around it), covering both the normal cases and at least one edge case per public method.
  • The gem built locally with gem build and installed with gem install from the resulting .gem file, then used successfully from a plain irb session started outside the RecipeBox project directory.
  • A README documenting installation, a quick-start usage example, and every public method's expected inputs and outputs, clear enough that someone unfamiliar with RecipeBox could use the gem correctly without reading its source.
  • Semantic versioning applied deliberately: the gemspec starts at 0.1.0, and if you make any change after your first successful local install, it's reflected in the version number using the correct MAJOR/MINOR/PATCH judgment for what actually changed.
Suggested approach
  1. Identify the logic to extract by asking which part of RecipeBox would still make sense if the Rails app disappeared entirely — that's your gem's real boundary.
  2. Scaffold the gem structure with bundle gem first, before moving any code, so you have a correct skeleton to move the extracted logic into rather than retrofitting one later.
  3. Move the logic over and get its RSpec suite fully green in the gem's own isolated environment before touching RecipeBox again — this is the point where you confirm the extraction was actually clean.
  4. Only after the gem's own tests pass, go back into RecipeBox and replace the original in-app code with a dependency on your new gem (via a local path source in the Gemfile while you're still iterating), confirming the app still works exactly as before.
  5. Write the README, build the gem, and do a real local install into a fresh, unrelated directory last — this final step is what actually proves the packaging is correct, since problems with the gemspec's file list often only show up once you try installing the packaged artifact rather than running the code straight from its source folder.
Stretch goals
  • Publish the gem for real to RubyGems.org under a clearly experimental name, and install it on a different machine (or a fresh container) purely from the published package, with no local path shortcuts.
  • Set up a minimal CI workflow (e.g. GitHub Actions) that runs the gem's RSpec suite automatically on every push, so the gem has the same kind of safety net a real open-source project would.
  • Go back to RecipeBox once the gem is published and switch its Gemfile from a local path source to the real published version pulled from RubyGems.org, closing the loop completely.
