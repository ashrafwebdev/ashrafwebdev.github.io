Arrays and hashes

Ruby · part of the free zero-to-hero guide

Builds on: Methods and blocks

Arrays hold ordered, indexable lists, created with []. Hashes map keys to values, created with {} — modern Ruby favors symbol keys (:name) over string keys, since symbols are immutable and interned, making them more memory-efficient and faster to compare than equivalent strings.

Both collections come with a huge library of built-in methods — map, select, reject, reduce, sort, group_by — that make manual loops for common transformations rarely necessary in idiomatic Ruby. Most of these methods are non-mutating by default: they return a new collection and leave the original untouched, unless you reach for the bang (!) variant explicitly.

Ruby's Enumerable module is what actually supplies most of these methods, and it's mixed into both Array and Hash (and many other classes), which is why the same method names — map, each, reduce — behave consistently across very different kinds of collections. Understanding Enumerable is often more valuable than memorizing Array-specific or Hash-specific method lists.

reduce (aliased inject) folds a collection down into a single value by repeatedly applying a block with an accumulator, and it's more general-purpose than it first appears — sums, products, building up a hash from an array, and flattening nested structures can all be expressed as a reduce once you're comfortable with the pattern.

Hashes preserve insertion order in modern Ruby (this has been guaranteed since Ruby 1.9), which many people don't expect coming from languages where hash/dictionary ordering is unspecified. Accessing a missing key returns nil by default rather than raising an error, though Hash.new(default) or Hash.new { |h, k| ... } can supply a default value or even compute one lazily on first access.

Ruby's range syntax integrates naturally with both collections: (1..5).to_a produces an array, and array[1..3] slices a subrange. The two-dot range (1..5) is inclusive of the end value, while the three-dot range (1...5) excludes it — a small syntactic difference that's easy to misread at a glance and worth double-checking in code review.

collections.rb
fruits = ["apple", "banana", "cherry"]
user = { name: "Amina", age: 27 }  # symbol keys

puts fruits.first
puts user[:name]

doubled = [1, 2, 3].map { |n| n * 2 }
puts doubled.inspect  # [2, 4, 6]
enumerable_toolkit.rb
orders = [
  { item: "Book", price: 12, qty: 2 },
  { item: "Pen",  price: 2,  qty: 5 },
]

total = orders.reduce(0) { |sum, o| sum + (o[:price] * o[:qty]) }
puts total  # 34

by_expensive = orders.sort_by { |o| -o[:price] }
cheap, pricey = orders.partition { |o| o[:price] < 5 }
grouped = orders.group_by { |o| o[:price] > 5 ? :expensive : :cheap }
puts grouped.keys.inspect  # [:cheap, :expensive]
hash_defaults.rb
counts = Hash.new(0)  # default value 0 for any missing key

"mississippi".each_char { |c| counts[c] += 1 }
puts counts.inspect  # {"m"=>1, "i"=>4, "s"=>4, "p"=>2}

plain = {}
puts plain[:missing].inspect  # nil, no error raised
Key points
  • Symbol keys (name: / :name) are the idiomatic default for hash keys in modern Ruby.
  • .map, .select, .reduce return new collections — they don't mutate the original by default (methods ending in ! do).
  • The Enumerable module is the actual source of most collection methods and is shared by Array, Hash, Range, and more.
  • reduce/inject folds a collection into a single accumulated value and can express sums, groupings, and transformations alike.
  • Hashes preserve insertion order since Ruby 1.9, unlike hash/dictionary types in some other languages.
  • A missing hash key returns nil by default, but Hash.new(default) lets you supply a fallback value instead.
  • .inspect (or p instead of puts) shows a debug-friendly representation, useful for arrays and hashes.
  • A two-dot range (1..5) is inclusive of the endpoint; a three-dot range (1...5) excludes it.
Try it yourself

Create a hash representing a book (title, author, year) and an array of three such hashes, then print each title using map. Then use reduce to compute the average publication year across all three books, and use group_by to split the books into two groups based on whether they were published before or after 2000.
