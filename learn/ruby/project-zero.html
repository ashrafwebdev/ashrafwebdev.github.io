01 Zero stage capstone

A command-line trivia quiz that keeps score

Ruby · ties together everything in the Zero stage

This project ties together everything from the Zero stage — variables, control flow, methods and blocks, arrays and hashes, string manipulation, and irb-driven experimentation — into a single running program: a trivia quiz that asks the player a series of questions in the terminal, checks each answer, and reports a final score at the end.

The interesting constraint is that the whole quiz has to run as a plain Ruby script with no external libraries and no persistence beyond the current run. That forces you to actually reach for Ruby's core building blocks — arrays of hashes for questions, string methods for cleaning up user input, and blocks for iterating and scoring — rather than leaning on a gem to do the work for you.

By the time it's done, you'll have a small but genuinely complete program: it takes input, makes decisions, loops, tracks state, and prints a result, which is the shape of almost every program you'll ever write, just in miniature.

  • Syntax, variables, and control flow
  • Methods and blocks
  • Arrays and hashes
  • String manipulation
  • irb for interactive experimentation
Requirements
  • A collection of at least eight quiz questions, each stored as a hash with a question string, an array of possible answers, and the correct answer.
  • The quiz asks each question in turn, reads the player's answer from the terminal, and checks it in a way that tolerates extra whitespace and mismatched case (so "Paris", " paris ", and "PARIS" all count as correct).
  • A running score is tracked as the quiz progresses and printed after every question (e.g. "Score: 3/5 so far").
  • At the end, the script prints a final score out of the total, plus a different closing message depending on the score range (e.g. under half, over half, perfect) using a case/when or if/elsif chain.
  • At least one method exists that takes a block, used somewhere in the scoring or question-asking logic rather than writing the same loop body inline more than once.
  • The player can answer "quit" at any point to end the quiz early and still see their score for the questions answered so far.
  • The whole program lives in a single .rb file and runs correctly with a plain ruby quiz.rb, no setup step required.
Suggested approach
  1. Start by hardcoding one question and getting the basic ask-answer-check loop working end to end before adding the rest of the questions.
  2. Move the questions into an array of hashes next, and rewrite the loop to iterate over that array with each rather than repeating code per question.
  3. Add score tracking and the running score message, testing with a mix of correct and incorrect answers to make sure counting is accurate.
  4. Handle the messy edge cases — trimming whitespace, normalizing case, and the "quit" early-exit path — since these are the parts most likely to have a subtle bug.
  5. Write the final score message last, using irb on the side to experiment with exactly how you want to phrase each score-range message before wiring it into the script.
Stretch goals
  • Shuffle the question order (and the order of multiple-choice options) each time the quiz runs, using Array's shuffle method.
  • Add a lightweight timer per question using Ruby's Time class, and reward faster correct answers with bonus points.
  • Let the player choose a difficulty level at the start, which filters the question set down to only questions tagged with that difficulty.
