RecipeBox: a Rails app for saving and organizing recipes

Ruby · ties together everything in the Learning stage

RecipeBox is a small but real Rails CRUD application: users can add a recipe with a title, ingredients, and instructions, view a list of all their saved recipes, open one to see the full detail, edit it, and delete it. It's the natural next step after the Zero-stage quiz script, moving from a single script into a structured, database-backed web application built the Rails way.

The project deliberately covers the full Learning-stage syllabus: object-oriented Ruby for the model logic, a Gemfile managed with Bundler, at least one place where you read from or write to a plain file, and the MVC pieces Rails itself provides — routes, controllers, ActiveRecord-backed views. The goal isn't a polished product; it's proof you can wire a complete, working slice of a real Rails app together yourself.

Keep the scope narrow on purpose: one primary model, standard Rails CRUD conventions, and no authentication yet. A project that tries to do too much at this stage usually ends up half-finished; a small one you actually complete teaches far more.

  • Object-oriented Ruby: classes, modules, mixins
  • Gems and Bundler
  • File I/O
  • Intro to Rails: MVC, routes, views
  • ActiveRecord basics
Requirements
  • A Rails app generated with rails new, using a Recipe model with at least title, ingredients, and instructions attributes, created and modified through real migrations.
  • A RecipeController with the conventional index, show, new, create, edit, update, and destroy actions, wired up with resources :recipes in routes.rb.
  • At least one model-level validation (e.g. presence on title) that prevents an invalid recipe from being saved, with the validation error shown back to the user on the form.
  • A working index view listing every saved recipe with a link to its show page, and a show view rendering the recipe's full detail using ERB.
  • At least one small piece of logic pulled out into a plain Ruby module or class mixed into the Recipe model (for example, a module that formats a recipe's ingredient list as a bulleted string) — not just default ActiveRecord behavior.
  • A Gemfile with at least one added gem beyond the Rails defaults, installed and used through Bundler.
  • A rake task or small script that reads recipes from a plain text or CSV file on disk and creates matching Recipe records, demonstrating real file I/O feeding into the database.
Suggested approach
  1. Generate the app and the Recipe model with its migration first, and confirm you can create and inspect a record from the Rails console before writing any controller code.
  2. Build the index and show views before new/edit/create/update — reading and displaying data is simpler than handling form submissions and validation errors.
  3. Add the create and update flow next, including the validation and its error display, testing by deliberately submitting an invalid form.
  4. Pull the ingredient-formatting logic out into its own module once the basic CRUD works, so you're refactoring working code rather than trying to design it perfectly up front.
  5. Write the file-import rake task last, once the model and validations are stable, so you have something real to import into.
Stretch goals
  • Add a search box on the index page that filters recipes by title using ActiveRecord's where with a partial match.
  • Add a second model (like Ingredient or Category) with a has_many/belongs_to association to a Recipe, and show related recipes on a category page.
  • Style the app with a small amount of CSS and add flash messages confirming a successful create, update, or delete.
