01 Zero stage

String manipulation

Ruby · part of the free zero-to-hero guide

Ruby strings come with an extensive built-in method set: .upcase, .downcase, .strip, .split, .gsub (global substitute), and dozens more — most common text tasks are a single method call away, which is a big part of why Ruby feels pleasant for scripting and text processing.

Strings are mutable in Ruby by default (unlike Python or Java), so methods ending in ! like .upcase! modify the string object in place and return nil if nothing actually changed, while the non-bang version always returns a new string and leaves the original untouched. That nil-on-no-change behavior of bang methods is a subtle trap: chaining off a bang method's result can blow up if the string was already in the target state.

Interpolation (#{...}) inside double-quoted strings is the everyday way to build formatted output, but Ruby also supports %-based and format/sprintf-style formatting for printf-style control over things like padding, decimal precision, and zero-fill, which interpolation alone can't easily express.

Ruby strings support regular expressions as first-class citizens through the =~ match operator, .match, .scan, and .gsub with a regex pattern instead of a plain string. .scan in particular is underused but powerful — it returns every non-overlapping match in a string as an array in one call, which is handy for pulling all numbers, emails, or hashtags out of a block of text.

Single-quoted and double-quoted strings are not just a style choice: single-quoted strings do not interpolate and only recognize two escape sequences (\' and \\), while double-quoted strings interpolate and support the full range of escapes like \n and \t. Many style guides recommend single quotes by default and double quotes only when interpolation or an escape sequence is actually needed, as a small signal to readers about what a given string is doing.

Strings can be built incrementally with << (append, mutating in place) or + (concatenate, returning a new string), and repeatedly using += in a loop is noticeably less efficient than << or building an array of pieces and joining them once, because each += allocates a brand-new string object.

strings.rb
message = "  Hello, World!  "

puts message.strip.downcase          # "hello, world!"
puts message.gsub("World", "Ruby")   # "  Hello, Ruby!  "
puts "a,b,c".split(",").inspect       # ["a", "b", "c"]
formatting_and_regex.rb
price = 4.5
puts format("$%.2f", price)              # "$4.50"

text = "Contact: amina@example.com, yusuf@example.org"
emails = text.scan(/[\w.]+@[\w.]+/)
puts emails.inspect                       # ["amina@example.com", "yusuf@example.org"]

puts "hello world".sub(/o/, "0")          # "hell0 world" -- only first match
bang_gotcha.rb -- a common mistake
name = "Amina"

# BUG: upcase! returns nil when the string was already unchanged
result = name.upcase!  # "AMINA" the first time -- fine
result2 = name.upcase! # already all caps -> returns nil, not "AMINA"!
puts result2.inspect   # nil

# Safer when you just want the transformed value:
puts name.upcase       # always returns a string, never nil
Key points
  • Bang methods (!) mutate the string in place and return nil if nothing changed; their non-bang counterparts always return a new string.
  • .gsub(pattern, replacement) replaces every match; .sub replaces only the first.
  • Double-quoted strings interpolate with #{} and support full escape sequences; single-quoted strings do neither, and are the leaner default when you need neither feature.
  • format/sprintf gives printf-style control (padding, decimal precision) that plain interpolation can't express.
  • .scan(regex) returns every match in a string as an array in one call, which is often cleaner than a manual loop over matches.
  • Building a string with repeated += in a loop is less efficient than << or joining an array of parts, because each += allocates a new string.
  • Ruby strings support regular expressions directly through methods like .match and the =~ operator.

Then extend it to use a regular expression with scan to extract every word longer than four characters from the normalized string, and print the count of matches found.
