01 Zero stage

irb for interactive experimentation

Ruby · part of the free zero-to-hero guide

Builds on: String manipulation

irb (Interactive Ruby) is a REPL that comes bundled with every Ruby install — type an expression, see the result immediately, without writing or running a file. It's the fastest way to check how a method behaves or test a small idea before committing it to real code.

Modern irb (Ruby 3.x) includes multi-line editing, syntax highlighting, and a built-in autocomplete that shows available methods as you type, which makes it noticeably friendlier than the bare-bones REPL Ruby shipped with in older versions. It also keeps a history across sessions, so pressing the up arrow can recall commands from a previous irb session, not just the current one.

irb evaluates each line as a full Ruby expression and echoes its return value prefixed with =>, which is genuinely useful for building intuition about return values — many Ruby methods have return values that are surprising until you've actually seen them printed, like the fact that puts itself always returns nil.

Beyond one-off checks, irb is a real part of the Ruby learning workflow: loading an existing file's code into a session with irb -r ./myfile.rb lets you poke at your own methods interactively, calling them with different arguments and inspecting return values, without adding temporary puts statements to the file itself. (The next stage introduces classes -- once you've written one, this same trick works just as well for instantiating it and calling its methods interactively.)

pry is a popular, more feature-rich alternative REPL that many Ruby developers install as their default, offering better introspection (like show-method to view a method's source, or cd to step into an object's context) and, critically, a binding.pry call you can drop directly into running code to pause execution and inspect the exact state at that point — genuinely one of the most useful Ruby debugging techniques there is.

Because irb evaluates arbitrary Ruby, it doubles as a lightweight calculator, a place to sanity-check a regular expression against sample strings, or a scratchpad for sketching out an algorithm's logic in small pieces before writing the final version in a file — all without the overhead of setting up a project or a test file.

Terminal
$ irb
irb(main):001> [1, 2, 3].sum
=> 6
irb(main):002> "hello".reverse
=> "olleh"
Terminal -- loading your own file
$ irb -r ./calculator.rb
irb(main):001> add(2, 3)
=> 5
irb(main):002> add(10, -4)
=> 6
irb(main):003> history
=> [[2, 3, 5], [10, -4, 6]]
Terminal -- pry's binding.pry in context
# somewhere in your code:
def process(order)
  binding.pry  # execution pauses here, drops into a live session
  total = order[:price] * order[:qty]
  total
end

# in the paused session you can inspect `order` exactly as it
# exists at that point in the real running program
Key points
  • irb evaluates each line immediately and prints its return value with =>.
  • It's the fastest way to check exactly how an unfamiliar method behaves before committing to it in real code.
  • Modern irb supports multi-line editing, syntax highlighting, and autocomplete, and its history persists across sessions.
  • pry is a popular, more feature-rich alternative REPL many Ruby developers install as their default.
  • binding.pry pauses a real running program at that exact line, letting you inspect live state -- a core debugging technique in the Ruby ecosystem.
  • You can load a whole file's code into an irb session for interactive exploration with irb -r ./myfile.rb.
  • Remember that puts always returns nil -- irb makes surprises like this visible immediately.
Try it yourself

Open irb and experiment with five different Array methods you haven't used before (like rotate, sample, or each_slice), reading each result. Then write a couple of small methods in a file, load it into irb with the -r flag, and call them interactively with different arguments to observe how the return values change.
