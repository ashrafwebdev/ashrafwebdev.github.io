01 Zero stage

Syntax, variables, and control flow

Ruby · part of the free zero-to-hero guide

Ruby was designed for programmer happiness, and its syntax reflects that goal directly — it reads close to plain English wherever possible. Variables need no type declaration or keyword: name = "Amina" just works, and Ruby infers the type from whatever value gets assigned. By convention, local variables and method names use snake_case, while constants (which Ruby only warns about, rather than prevents, reassigning) start with an uppercase letter.

Blocks of code — the bodies of methods, classes, if statements, and loops — are almost always closed with the keyword end rather than curly braces or significant indentation. This is one of Ruby's most visually distinctive choices, and it means indentation is a style convention (enforced by tools like RuboCop) rather than something the language itself requires for the code to run correctly.

Ruby offers the usual if/elsif/else, but also unless as a readable inverse of a negated if, and case/when for clean multi-branch logic that can match against classes, ranges, and regular expressions, not just exact equality. A distinctly Ruby feature is the modifier form: puts "adult" if age >= 18 lets a simple one-line conditional read as a single sentence instead of a full multi-line block.

Truthiness has one famous gotcha for people arriving from other languages: only nil and false are falsy in Ruby. The number 0, an empty string "", and an empty array [] are all truthy, unlike in JavaScript, Python, or C. Forgetting this is a real source of bugs when someone checks whether a count is 'empty' with a plain if count instead of an explicit if count.zero? or if count > 0.

For repetition, Ruby has while and until loops, but idiomatic code leans heavily on iterator methods that take a block instead: 5.times, array.each, and range iteration are far more common in real Ruby than a counting loop. A traditional for loop does exist, but it's rarely used idiomatically, partly because its loop variable leaks into the surrounding scope after the loop finishes, rather than being scoped to the loop body the way a block's variables are.

Every value in Ruby is an object, including integers, strings, and even nil — there are no separate 'primitive' types the way there are in Java or C. This is precisely why a number can respond to a method call like 5.times or (-3).abs, and it's one of the ideas that most shapes how idiomatic Ruby ends up looking, favoring method calls chained off a value over free-standing functions or purely symbolic operators.

basics.rb
name = "Amina"
age = 27

if age >= 18
  puts "#{name} is an adult."
else
  puts "#{name} is a minor."
end

puts "Welcome!" if age >= 18  # modifier form
control_flow.rb
score = 82

grade = case score
        when 90..100 then "A"
        when 80...90 then "B"
        when 70...80 then "C"
        else "F"
        end
puts grade  # "B" -- note the exclusive range (...) for 80..89

puts "no access" unless age = 15 and age >= 18

3.times { |i| puts "iteration #{i}" }  # 0, 1, 2
gotchas.rb -- a couple of classic traps
count = 0

# BUG: 0 is truthy in Ruby, so this branch always runs
if count
  puts "has items"  # prints even though count is zero!
end

# Correct:
puts "has items" if count.positive?

# for loops leak their variable outside the loop body
for n in 1..3
end
puts n  # 3 -- still accessible, unlike a block-scoped `each`
Key points
  • String interpolation uses #{...} inside double-quoted strings; single-quoted strings do not interpolate.
  • Blocks typically end with end, not a closing brace — one of Ruby's most distinctive syntax choices.
  • The modifier form (statement if condition) is idiomatic Ruby for simple one-line conditionals.
  • Only nil and false are falsy — 0, "", and [] are all truthy, a frequent gotcha for newcomers.
  • unless reads more naturally than if !condition for a single negative check.
  • case/when can match ranges, classes, and regular expressions, not just literal equality.
  • A traditional for loop leaks its variable into the enclosing scope; each with a block does not, which is one reason each is preferred idiomatically.
  • Almost everything in Ruby is an object, including numbers and nil — this is why methods like 5.times work at all.
Try it yourself

Write a script with variables for a name and age, printing a different greeting depending on whether the age is above or below 18, using both a full if/else block and the modifier form. Then add a case/when statement that buckets the age into "minor", "young adult", or "adult", and deliberately trigger the truthiness gotcha with a variable holding 0 to see it firsthand before fixing it.
