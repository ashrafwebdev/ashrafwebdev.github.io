File I/O

Ruby · part of the free zero-to-hero guide

Ruby's File class reads and writes files. File.open with a block automatically closes the file afterward, even if an error occurs partway through — the idiomatic pattern, similar in spirit to Python's with statement, and much safer than manually calling .open and .close yourself, since a raised exception between them would otherwise leak an open file handle.

For simple cases, File.read and File.write handle the whole open/read-or-write/close cycle in a single call, when you don't need fine-grained control over how the file is processed. File.readlines similarly reads a file directly into an array of lines in one step, which is convenient for smaller files but loads the entire file into memory at once.

For genuinely large files, reading line-by-line with File.foreach or File.open(path).each_line avoids loading the whole file into memory, processing it lazily one line at a time instead — a meaningful difference when working with logs or datasets too large to comfortably hold in RAM all at once.

The second argument to File.open controls the file mode: "r" for reading (the default), "w" for writing (which truncates and overwrites any existing content), "a" for appending to the end without erasing what's already there, and "r+"/"w+" for combined read-and-write access. Choosing "w" when you meant "a" is a classic, data-destroying mistake worth double-checking.

Ruby's Dir class complements File for working with the filesystem itself — listing a directory's contents with Dir.glob or Dir.children, checking whether a path exists and what kind of entry it is, and creating or removing directories. File.exist?(path) is the standard guard to check for a file's presence before attempting to read it, avoiding an Errno::ENOENT exception.

Beyond plain text, Ruby's standard library includes CSV for structured tabular files and JSON for JSON documents, both of which parse directly into familiar Ruby arrays and hashes — for most everyday scripting tasks these are a better fit than hand-rolling your own parsing logic on top of raw File reads.

files.rb
File.write("note.txt", "Hello, file system!")

File.open("note.txt") do |file|
  puts file.read
end  # file is automatically closed here
lines_and_modes.rb
File.open("log.txt", "w") do |file|
  %w[first second third].each { |line| file.puts(line) }
end

File.open("log.txt", "a") do |file|
  file.puts("fourth")  # appended, not overwritten
end

File.foreach("log.txt").with_index(1) do |line, num|
  puts "#{num}: #{line.chomp}"
end
csv_and_json.rb
require "csv"
require "json"

CSV.open("people.csv", "w") do |csv|
  csv << ["name", "age"]
  csv << ["Amina", 27]
end

rows = CSV.read("people.csv", headers: true)
puts rows.first["name"]              # "Amina"

File.write("data.json", { name: "Amina" }.to_json)
parsed = JSON.parse(File.read("data.json"))
puts parsed["name"]                  # "Amina"
Key points
  • File.open(path) do |file| ... end guarantees the file is closed even if the block raises an error.
  • File.read/File.write are shorthand for simple, one-shot reads and writes; File.readlines loads a whole file into an array of lines.
  • File.foreach processes a file line-by-line without loading it entirely into memory, important for large files.
  • The file mode argument matters: "w" truncates existing content, while "a" appends -- mixing these up is a classic data-loss mistake.
  • Use File.exist?(path) to check for a file's presence before attempting to read it, avoiding an unhandled exception.
  • Dir.glob and related Dir methods handle listing and pattern-matching filesystem entries.
  • The standard library's CSV and JSON modules are usually a better fit than hand-parsing structured files with raw File reads.
Try it yourself

Write a script that writes several lines to a file, then reads it back and prints each line with its line number. Then extend it to append three more lines without erasing the original content, and finally write the same data out as both a CSV file and a JSON file, confirming both can be read back correctly.
