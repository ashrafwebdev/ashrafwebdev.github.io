Type narrowing and type guards

TypeScript · part of the free zero-to-hero guide

When a value has a union type, TypeScript needs to figure out which specific member of the union you're dealing with before letting you use type-specific properties or methods — this process is called narrowing, and it happens through checks like typeof, instanceof, the in operator, or comparing a discriminant property against a specific literal value.

Narrowing only applies within the scope where the check was actually performed — it doesn't persist across a function boundary (calling a separate helper function to do the check doesn't narrow the caller's variable, unless that helper is itself written as a type guard), and reassigning a narrowed variable to a new value of the wider union type widens it right back.

A custom type guard is a function whose return type is written as value is Type instead of a plain boolean — it still returns an actual boolean at runtime, but that special return type annotation teaches TypeScript to narrow the checked value based on your own custom logic, wherever the function is called as an if condition, beyond what built-in checks alone could express.

Discriminated unions (a shared literal kind or type field across every member) are the single most robust narrowing pattern for object unions, because switching or branching on that one field narrows the entire object correctly in each branch, in a way that checking individual properties one at a time generally can't replicate as cleanly, especially once a union has more than two or three members.

The in operator is a lesser-known but genuinely useful narrowing tool for object unions that don't share a discriminant field: "radius" in shape narrows a union down to whichever member actually declares a radius property, which is handy when you're narrowing types you don't control and can't retroactively add a discriminant field to.

Assertion functions are a close cousin of type guards, written with a return type of asserts value is Type instead of value is Type — rather than returning a boolean you check in an if, they narrow by throwing when the check fails, which is a common pattern for validating function arguments up front and then working with the narrowed type for the rest of the function body.

narrowing.ts
function printId(id: string | number) {
  if (typeof id === "string") {
    console.log(id.toUpperCase()); // narrowed to string here
  } else {
    console.log(id.toFixed(2));    // narrowed to number here
  }
}

function isString(value: unknown): value is string {
  return typeof value === "string";
}
in-operator-and-discriminated-union.ts
interface Circle { kind: "circle"; radius: number; }
interface Square { kind: "square"; side: number; }

function area(shape: Circle | Square): number {
  if (shape.kind === "circle") {
    return Math.PI * shape.radius ** 2; // narrowed via discriminant
  }
  return shape.side ** 2;
}

// Without a discriminant, the `in` operator narrows instead:
type LegacyShape = { radius: number } | { side: number };
function legacyArea(shape: LegacyShape): number {
  if ("radius" in shape) return Math.PI * shape.radius ** 2;
  return shape.side ** 2;
}
assertion-function.ts
function assertIsNumber(value: unknown): asserts value is number {
  if (typeof value !== "number") {
    throw new Error("Expected a number");
  }
}

function double(value: unknown) {
  assertIsNumber(value);
  return value * 2; // narrowed to number for the rest of the function
}
Key points
  • typeof narrows primitives; instanceof narrows classes; a discriminant property narrows tagged unions; in narrows by property presence.
  • Custom type guards (value is Type) let you teach TypeScript about narrowing logic it can't infer from built-in checks on its own.
  • Narrowing only applies within the scope where the check was performed — it doesn't persist across a function boundary or after reassignment.
  • Discriminated unions (a shared 'kind' or 'type' field) are the most robust pattern for narrowing complex object unions with several members.
  • The in operator narrows object unions by property presence, useful when the members don't share a common discriminant field.
  • Assertion functions (asserts value is Type) narrow by throwing on failure instead of returning a boolean to check in an if.
  • A helper function that performs a check without being written as a type guard does not narrow the caller's variable, even if the logic is correct.
