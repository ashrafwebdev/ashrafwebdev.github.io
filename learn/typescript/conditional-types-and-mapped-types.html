Conditional types and mapped types

TypeScript · part of the free zero-to-hero guide

Conditional types let a type depend on a check, using syntax that mirrors a ternary expression: T extends U ? X : Y. This enables types that adapt based on what's passed to them, computed entirely at compile time — the check itself is really asking 'is T assignable to U', not a strict equality test, which matters for how these types behave with unions and subtypes.

Mapped types transform every property of an existing type using one consistent rule, written with a syntax like { [K in keyof T]: ... } that iterates over every key of T and produces a new property for each — this is literally how the built-in utilities like Partial and Readonly are implemented internally, not a separate special-cased compiler feature.

Conditional types distribute automatically over a union when the type being checked is a bare type parameter — passing a union like string | number into a conditional type effectively runs the check separately for each union member and unions the results back together, which is usually exactly what you want, but occasionally surprises people expecting the union to be checked as a single whole.

The infer keyword inside a conditional type lets you extract and name a piece of a type you're checking against, rather than merely testing whether it matches — this is how utility types like ReturnType pull the return type out of a function type, or Awaited pulls the resolved value type out of a Promise, without you needing to know or write out the underlying type structure explicitly yourself.

Mapped types support modifiers beyond adding readonly: prefixing a modifier with - (as in -readonly or -?) removes it instead of adding it, which is how the built-in Required utility strips optionality that Partial added, and how Mutable-style helper types (not built in, but easy to write) strip readonly-ness from a type.

These features are genuinely what makes TypeScript's type system Turing-complete in a formal sense — powerful enough to express real computation at the type level — but that power is easy to overuse into deeply nested, unreadable type gymnastics; using conditional and mapped types for real, recurring problems (as most utility types do) is very different from reaching for them reflexively wherever a simpler union or interface would do the job just as well.

conditionalTypes.ts
type IsString<T> = T extends string ? true : false;
type A = IsString<"hello">; // true
type B = IsString<42>;      // false

// A simplified reimplementation of Readonly<T>
type MyReadonly<T> = {
  readonly [K in keyof T]: T[K];
};
infer-and-distribution.ts
// A simplified reimplementation of the built-in ReturnType utility
type MyReturnType<T> = T extends (...args: any[]) => infer R ? R : never;

function greet(): string { return "hi"; }
type Greeting = MyReturnType<typeof greet>; // string

// Conditional types distribute over unions automatically:
type ToArray<T> = T extends any ? T[] : never;
type Result = ToArray<string | number>; // string[] | number[], not (string | number)[]
removing-modifiers.ts
// A simplified reimplementation of the built-in Required utility
type MyRequired<T> = {
  [K in keyof T]-?: T[K]; // the '-?' strips optionality instead of adding it
};

interface Draft { title?: string; }
type Published = MyRequired<Draft>; // { title: string }
Key points
  • Conditional types (T extends U ? X : Y) compute a different resulting type based on a compile-time assignability check.
  • Mapped types ({ [K in keyof T]: ... }) transform every property of a type using one consistent rule.
  • Built-in utility types like Partial, Readonly, and Record are themselves just mapped/conditional types, not special compiler features.
  • A conditional type checking a bare type parameter automatically distributes over a union, checking and combining each member separately.
  • The infer keyword lets a conditional type extract and name a piece of the type it's checking, as used internally by ReturnType and Awaited.
  • Prefixing a mapped type modifier with - (like -readonly or -?) removes that modifier instead of adding it.
  • These features make the type system genuinely Turing-complete, but that power is easy to overuse into unreadable, deeply nested type expressions.
