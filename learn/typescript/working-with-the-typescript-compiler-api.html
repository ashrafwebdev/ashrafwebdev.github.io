Working with the TypeScript Compiler API

TypeScript · part of the free zero-to-hero guide

Builds on: Contributing types to DefinitelyTyped

The TypeScript compiler itself is available as a programmatic API, published as the typescript package on npm, letting you parse source code into an Abstract Syntax Tree (AST), analyze it, and even generate or transform TypeScript and JavaScript code directly — this is how linters, formatters, codemods, and higher-level tools like ts-morph are actually built underneath.

An AST represents source code as a tree of nodes, each one describing a specific syntactic construct (a variable declaration, a function call, a binary expression) and its position in the original source — walking that tree with a function like forEachChild, recursively, is the fundamental operation nearly every tool built on the Compiler API performs in some form.

Beyond just parsing syntax, the Compiler API also exposes the actual type checker used internally by tsc and by your editor's IntelliSense — creating a Program from a set of source files and asking its type checker for the type of a given node gives you the exact same type information the compiler itself would use to report an error, which is a meaningfully more powerful (and more involved) capability than syntax-only AST analysis alone.

Working directly with the Compiler API is genuinely low-level and verbose: navigating raw AST nodes by hand for anything beyond a simple read-only analysis quickly becomes tedious, and outputting correctly-formatted modified code from a mutated AST requires its own dedicated printer step, since the AST alone doesn't preserve exact original formatting like whitespace and comments the way a naive text-based approach would.

Libraries like ts-morph wrap the raw Compiler API with a much friendlier, more object-oriented interface for common tasks — 'find every usage of this function across a project and rename it', 'add a new method to every class implementing this interface' — trading some of the Compiler API's raw flexibility for an interface that's dramatically faster to actually get real refactoring work done in.

This is genuinely advanced tooling work, and most day-to-day application TypeScript never touches the Compiler API directly at all — it's the domain of people building linters, codemods, editor extensions, or framework-specific build tooling, rather than something an application developer reaches for while building ordinary product features.

A minimal AST walk
import ts from "typescript";

const code = "const x: number = 5;";
const sourceFile = ts.createSourceFile("temp.ts", code, ts.ScriptTarget.Latest);

ts.forEachChild(sourceFile, (node) => {
  console.log(ts.SyntaxKind[node.kind]);
});
using-the-real-type-checker.ts
import ts from "typescript";

const program = ts.createProgram(["src/index.ts"], {});
const checker = program.getTypeChecker();
const sourceFile = program.getSourceFile("src/index.ts");

ts.forEachChild(sourceFile!, (node) => {
  if (ts.isVariableDeclaration(node) && node.name) {
    const type = checker.getTypeAtLocation(node);
    console.log(node.name.getText(), "->", checker.typeToString(type));
  }
});
ts-morph-for-a-simple-refactor.ts
import { Project } from "ts-morph";

const project = new Project();
project.addSourceFilesAtPaths("src/**/*.ts");

for (const sourceFile of project.getSourceFiles()) {
  for (const fn of sourceFile.getFunctions()) {
    if (fn.getName() === "oldFunctionName") {
      fn.rename("newFunctionName"); // updates every usage too
    }
  }
}
project.saveSync();
Key points
  • The Compiler API exposes the same parser and type checker that powers tsc itself and your editor's IntelliSense.
  • An AST (Abstract Syntax Tree) represents code as a tree of nodes — the foundation of linters, formatters, and codemods.
  • Beyond parsing, a Program's type checker gives you the exact type information the real compiler would use, not just syntax structure.
  • Modifying an AST directly and getting correctly-formatted output back typically requires a dedicated printer step, since raw ASTs don't preserve original formatting.
  • ts-morph wraps the raw Compiler API with a much friendlier interface for common refactoring tasks, like project-wide renames.
  • This is genuinely advanced tooling work — most day-to-day application TypeScript never touches the Compiler API directly.
  • The Compiler API is the foundation most editor extensions, codemods, and framework-specific build tools are actually built on top of.
Try it yourself

Use the TypeScript Compiler API to parse a small code snippet and log the SyntaxKind of every top-level node in the file. Then extend the example to create a full Program and use its type checker to print the inferred type of each top-level variable declaration, rather than just its syntax kind.
