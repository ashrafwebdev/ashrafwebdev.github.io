03 Advanced stage capstone

Type declarations for an npm package that doesn't have any

TypeScript · ties together everything in the Advanced stage

Advanced-stage TypeScript is largely about typing code you don't control — constrained generics, conditional and mapped types, and hand-written declaration files all exist because real projects are full of dependencies that were never written in TypeScript to begin with. This project puts that squarely to the test: find a small, real npm package with no bundled types and no existing @types package, and write a genuine .d.ts for it from scratch.

The constraint that makes this Advanced rather than a repeat of the Zero-stage interfaces exercise: your declaration file has to use at least one constrained generic and at least one mapped or conditional type of your own, describing real behavior the package actually has — a flat list of plain interfaces alone won't cut it here.

You'll also build a small file that actually consumes your new types, because a declaration file nobody has tried using is really just an unverified guess about the package's real shape.

  • Advanced generics and constraints
  • Conditional types and mapped types
  • Declaration files (.d.ts) for untyped libraries
  • Decorators
  • Strict mode and gradually typing a large codebase
Requirements
  • A complete .d.ts file for a real or realistic small untyped package, covering at least three distinct exports (functions, a class, or constants), with no bare any anywhere in your declarations.
  • At least one exported function typed with a constrained generic parameter — for example a parameter restricted with an extends clause requiring an id property — that preserves the caller's exact input type in its return type rather than widening it to the constraint itself.
  • At least one mapped or conditional type you write yourself inside the declaration file — for instance, deriving an options type as your own hand-written partial version of a full config type, rather than reaching for the built-in Partial.
  • A small consuming .ts file that imports from the untyped package through your own declare module block and exercises every function or class your declarations describe, compiling cleanly under strict mode.
  • At least one deliberate negative test: a commented-out call using an argument of the wrong type against your own declarations, with a note confirming tsc actually flags it as an error.
  • A short written note — in a comment or a short README — describing one specific place your hand-written declaration could plausibly drift from the package's real behavior, and how you'd notice if it ever did.
Suggested approach
  1. Read the real package's actual JavaScript source or documentation before writing a single type — you're describing what it really does, not an idealized guess.
  2. Start with the simplest exports (plain constants, non-generic functions) and get those compiling and usable from your consuming file before tackling anything generic.
  3. Add the constrained generic function next, and test it against at least two different concrete input types to confirm the return type tracks the specific input correctly each time, rather than collapsing to the constraint.
  4. Write your own mapped or conditional type only once you hit a concrete, repeated shape it would simplify — don't add one purely to prove you can.
  5. Write the consuming file last, and treat every error it surfaces as a signal that your declaration is incomplete or wrong — not that the consuming code is wrong.
Stretch goals
  • Publish your .d.ts as a small local package (via npm link or a local file dependency) and consume it for real from a second, separate project.
  • Add a class decorator to one exported class in your declarations, and note in a comment which decorator implementation — the older experimentalDecorators style or the newer standardized one — your typing actually assumes.
  • Turn on additional strict flags one at a time (noUnusedLocals, noImplicitReturns) on your consuming project, and note which extra issues each individually surfaces.
