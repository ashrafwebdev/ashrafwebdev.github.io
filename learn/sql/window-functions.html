Window functions

SQL · part of the free zero-to-hero guide

A window function computes a value across a set of related rows (the "window") without collapsing them into a single row the way GROUP BY does, so you keep every original row while adding a computed column alongside it — ideal for running totals, rankings, or comparisons against neighboring rows.

ROW_NUMBER(), RANK(), and DENSE_RANK() number rows within a window, differing in how they handle ties: ROW_NUMBER() always assigns distinct sequential numbers even to tied rows (in an arbitrary but consistent order), RANK() gives tied rows the same number and then skips the next rank accordingly (1, 2, 2, 4), while DENSE_RANK() gives tied rows the same number without leaving a gap afterward (1, 2, 2, 3).

OVER (PARTITION BY column ORDER BY column) defines the window: PARTITION BY splits rows into independently-numbered groups (similar in spirit to GROUP BY, but without collapsing rows), and ORDER BY inside the OVER clause determines the sequence used for ranking or running calculations within each partition.

Aggregate functions like SUM and AVG can also be used as window functions with OVER (...), commonly used for running totals (SUM(amount) OVER (ORDER BY date)) that accumulate as you move through the ordered rows, or for comparing each row against its partition's overall average without a separate self-join.

LAG() and LEAD() look at a preceding or following row within the same window without any join at all, which makes computing something like "the change since the previous day's total" or "tomorrow's scheduled value" a single expression instead of a self-join with an offset condition.

Window functions logically execute after WHERE, GROUP BY, and HAVING but before the final ORDER BY, which means you cannot reference a window function's result directly in the same query's WHERE clause — filtering on a computed rank typically requires wrapping the windowed query in a subquery or common table expression and filtering the outer query instead.

query.sql
SELECT
    customer_id,
    order_date,
    total,
    RANK() OVER (PARTITION BY customer_id ORDER BY total DESC) AS rank_by_amount,
    SUM(total) OVER (PARTITION BY customer_id ORDER BY order_date) AS running_total
FROM orders;
lag_lead.sql
SELECT
    order_date,
    daily_total,
    LAG(daily_total) OVER (ORDER BY order_date) AS previous_day_total,
    daily_total - LAG(daily_total) OVER (ORDER BY order_date) AS change_from_previous
FROM daily_order_totals
ORDER BY order_date;
filter_on_rank.sql
-- Can't filter on rank_num directly in WHERE, so wrap it in a CTE
WITH ranked AS (
    SELECT product_id, category, price,
           RANK() OVER (PARTITION BY category ORDER BY price DESC) AS rank_num
    FROM products
)
SELECT * FROM ranked WHERE rank_num <= 3;
Key points
  • Window functions add a computed column per row without collapsing rows like GROUP BY does.
  • ROW_NUMBER, RANK, and DENSE_RANK differ in how they number and handle tied rows.
  • PARTITION BY splits the window into independently-numbered groups; ORDER BY sets the sequence within each.
  • Aggregate functions used with OVER(...) compute running totals and moving statistics.
  • LAG and LEAD read a neighboring row's value directly, avoiding a manual self-join.
  • Window functions run after WHERE/GROUP BY/HAVING, so their results can't be filtered in the same query's WHERE.
  • Filtering on a window function's result requires wrapping it in a subquery or CTE and filtering the outer layer.
