Filtering with AND/OR/IN/LIKE

SQL · part of the free zero-to-hero guide

Builds on: SELECT, WHERE, ORDER BY

Multiple conditions in a WHERE clause combine with AND (all must be true) and OR (at least one must be true); when mixing both, parentheses make evaluation order explicit and avoid subtle logic bugs, since AND binds tighter than OR by default and a missing parenthesis can silently change which rows match.

IN checks a column against a list of values in one concise expression, replacing what would otherwise be a long chain of OR comparisons on the same column. Its counterpart NOT IN excludes those values, but it deserves caution: if the list contains a NULL, NOT IN can unexpectedly return zero rows for the entire query, because comparing anything to that NULL yields unknown rather than true or false.

BETWEEN tests whether a value falls within an inclusive range, and WHERE price BETWEEN 10 AND 20 is equivalent to combining a greater-or-equal and a less-or-equal check with AND, just more compact to read and write.

LIKE performs pattern matching on text, using % to match any sequence of characters (including zero characters) and _ to match exactly one character. A pattern that starts with %, such as matching anything ending in a suffix, generally cannot use a standard index efficiently, since the database can no longer narrow the search from the left edge of the indexed values.

IS NULL and IS NOT NULL are technically filters too, and combine naturally with the others: a condition like matching a category list and also requiring a non-missing description is written by joining an IN check with an IS NOT NULL check using AND.

Case sensitivity of LIKE depends on the database engine and the column's collation; PostgreSQL's LIKE is case-sensitive by default (its ILIKE variant is not), while MySQL's default collation often makes LIKE case-insensitive, so behavior that looks identical in development can differ once deployed against a different engine or configuration.

query.sql
SELECT name, category, price
FROM products
WHERE category IN ('books', 'electronics')
  AND (price < 10 OR name LIKE 'Deluxe%');
between_and_pattern.sql
SELECT name, price
FROM products
WHERE price BETWEEN 10 AND 50
  AND name LIKE '%Pro%'
  AND description IS NOT NULL;
not_in_null_trap.sql
-- If discontinued_ids contains a NULL, this returns zero rows entirely
SELECT * FROM products
WHERE id NOT IN (SELECT product_id FROM discontinued_ids);

-- Safer: filter NULLs out of the subquery first
SELECT * FROM products
WHERE id NOT IN (SELECT product_id FROM discontinued_ids WHERE product_id IS NOT NULL);
Key points
  • AND requires every condition true; OR requires at least one; parentheses make precedence explicit.
  • IN checks a column against a list of values, replacing a long chain of OR comparisons.
  • NOT IN silently returns zero rows for the whole query if its list contains a NULL.
  • BETWEEN expresses an inclusive range concisely; it's equivalent to two combined comparisons.
  • LIKE performs pattern matching, with % for any sequence and _ for a single character.
  • A leading % in a LIKE pattern usually prevents a standard index from being used efficiently.
  • Case sensitivity of LIKE depends on the database engine and column collation.
Try it yourself

Write a query selecting all products whose category is either 'toys' or 'games' and whose name starts with the letter 'S'. Then add a BETWEEN condition to keep only prices from $5 to $25, and explain why you'd prefer NOT IN with caution around NULLs versus a NOT EXISTS subquery in production code.
