JOINs: inner, left, right

SQL · part of the free zero-to-hero guide

A JOIN combines rows from two or more tables based on a related column, most commonly a foreign key referencing another table's primary key. INNER JOIN (the default kind of JOIN, and what plain JOIN means if unqualified) returns only rows that have a match in both tables, silently dropping anything on either side without a partner.

LEFT JOIN returns every row from the left table, with matching columns from the right table filled in where available and NULL where there's no match — useful for questions like "every customer, including those with zero orders". Filtering a left-joined column's NULLs afterward in the WHERE clause accidentally turns a LEFT JOIN back into an INNER JOIN, a common and confusing mistake, so any such filter belongs in the ON clause or an explicit IS NULL check instead.

RIGHT JOIN is the mirror image of LEFT JOIN, keeping every row from the right table instead; in practice, most developers write every join as a LEFT JOIN by simply swapping table order, so RIGHT JOIN shows up far less often in real code and some style guides ban it outright for consistency.

A FULL OUTER JOIN keeps every row from both tables, matching where possible and filling NULLs on whichever side lacks a match — less common than LEFT or INNER, but useful for reconciliation queries such as finding all mismatches between two related datasets in either direction.

You can join more than two tables in a single query by chaining additional JOIN clauses, each with its own ON condition; the order rarely matters for correctness with INNER JOINs, but it can matter a great deal for LEFT JOIN chains, since each step's NULLs propagate into the next join.

The ON clause specifies exactly which columns relate the two tables, and is distinct from WHERE: conditions in ON affect which rows get matched during the join itself (and matter enormously for LEFT JOIN), while conditions in WHERE filter the already-joined result afterward.

query.sql
SELECT customers.name, orders.id AS order_id, orders.total
FROM customers
LEFT JOIN orders ON orders.customer_id = customers.id
ORDER BY customers.name;
three_table_join.sql
SELECT o.id AS order_id, c.name AS customer_name, p.name AS product_name, oi.quantity
FROM orders o
INNER JOIN customers c ON c.id = o.customer_id
INNER JOIN order_items oi ON oi.order_id = o.id
INNER JOIN products p ON p.id = oi.product_id
ORDER BY o.id;
left_join_mistake.sql
-- Mistake: this WHERE condition silently turns the LEFT JOIN into an INNER JOIN
SELECT c.name, o.id
FROM customers c
LEFT JOIN orders o ON o.customer_id = c.id
WHERE o.total > 50;

-- Fix: move the condition into ON to still keep customers with no orders
SELECT c.name, o.id
FROM customers c
LEFT JOIN orders o ON o.customer_id = c.id AND o.total > 50;
Key points
  • INNER JOIN returns only rows with a match in both tables.
  • LEFT JOIN keeps every row from the left table, filling unmatched right-side columns with NULL.
  • A WHERE filter on the right-hand table can silently convert a LEFT JOIN into an INNER JOIN.
  • RIGHT JOIN mirrors LEFT JOIN; most developers just swap table order and always write LEFT JOIN.
  • FULL OUTER JOIN keeps every row from both tables, useful for reconciliation-style queries.
  • Chaining multiple JOINs lets you combine three or more related tables in one query.
  • The ON clause controls matching during the join; WHERE filters the result afterward.
Try it yourself

Write a LEFT JOIN query that lists every customer alongside their order count, including customers who have placed zero orders. Then extend it to a three-table join that also brings in product names for each order line, and explain in one sentence why putting a right-table condition in WHERE instead of ON can silently drop unmatched rows.
