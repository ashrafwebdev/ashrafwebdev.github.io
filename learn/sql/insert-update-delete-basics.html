01 Zero stage

INSERT, UPDATE, DELETE basics

SQL · part of the free zero-to-hero guide

INSERT INTO table (col1, col2) VALUES (v1, v2); adds a new row, and listing column names explicitly (rather than relying on column order) protects the statement from breaking if the table's schema changes later, such as a new column being added in between existing ones.

Most engines also support inserting several rows in a single statement by listing multiple value tuples separated by commas, which is both faster and more atomic than issuing one INSERT per row, since the whole batch either succeeds or fails together rather than leaving the table in a partially-written state.

UPDATE table SET col = value WHERE condition; modifies existing rows matching the condition, and can set several columns at once separated by commas. Omitting the WHERE clause updates every single row in the table, which is one of the most common and costly SQL mistakes in production.

DELETE FROM table WHERE condition; removes matching rows, and carries the exact same danger — a DELETE with no WHERE clause empties the entire table. Testing the equivalent SELECT with the same WHERE clause first, and checking the row count it would affect, is a common safety habit before running an UPDATE or DELETE.

Many engines support an UPDATE ... RETURNING or DELETE ... RETURNING clause (PostgreSQL) that hands back the affected rows' values in the same statement, which avoids a separate round-trip query when the application needs to know exactly what changed.

TRUNCATE TABLE is a faster alternative to DELETE with no WHERE clause for wiping an entire table — it skips per-row logging and cannot be filtered with a condition, and in many databases it also resets any auto-incrementing ID counter, which a plain DELETE does not.

query.sql
INSERT INTO products (name, price, category)
VALUES ('Wireless Mouse', 24.99, 'electronics');

UPDATE products
SET price = 19.99
WHERE name = 'Wireless Mouse';

DELETE FROM products
WHERE category = 'discontinued';
batch_and_returning.sql
INSERT INTO products (name, price, category) VALUES
    ('USB Cable', 8.99, 'electronics'),
    ('Notebook', 3.50, 'office'),
    ('Desk Lamp', 22.00, 'office');

UPDATE products
SET price = price * 0.9
WHERE category = 'office'
RETURNING id, name, price;
unsafe_mistake.sql
-- DANGER: no WHERE clause updates every row in the table
UPDATE products SET price = 0;

-- Always test the condition as a SELECT first
SELECT count(*) FROM products WHERE price = 0;
Key points
  • Always list explicit column names in INSERT to protect against future schema changes.
  • A single INSERT can add several rows at once using comma-separated value tuples.
  • UPDATE and DELETE without a WHERE clause affect every row in the table.
  • Test the WHERE clause with a SELECT COUNT first before running a destructive UPDATE or DELETE.
  • RETURNING hands back affected rows' values without a separate follow-up query.
  • TRUNCATE clears an entire table faster than DELETE but cannot be filtered with a WHERE clause.
  • Most databases support wrapping these statements in a transaction to allow rolling back mistakes.
Try it yourself

Write an INSERT for a new product, an UPDATE that changes its price, and a DELETE that removes it, each using explicit column names and a safe WHERE clause. Then rewrite the INSERT to add three products in one statement, and add a RETURNING clause to the UPDATE so it hands back the updated id and new price.
