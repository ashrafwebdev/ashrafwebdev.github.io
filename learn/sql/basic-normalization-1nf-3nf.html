Basic normalization (1NF–3NF)

SQL · part of the free zero-to-hero guide

Normalization is the process of structuring tables to minimize data duplication and avoid certain kinds of update anomalies. First normal form (1NF) requires every column to hold a single, atomic value — no comma-separated lists crammed into one text column.

Second normal form (2NF) requires that every non-key column depend on the entire primary key, not just part of it, which mostly matters for tables with composite (multi-column) primary keys. Third normal form (3NF) requires that non-key columns depend only on the primary key, not on each other — storing a customer's city and zip code together on an orders table, where zip determines city, would violate 3NF.

In practice, most well-designed application databases target 3NF by default, and deliberately denormalize only specific tables afterward for performance reasons, once profiling shows the normalized structure is genuinely a bottleneck.

schema.sql
-- Violates 1NF: multiple values crammed into one column
-- tags VARCHAR: 'electronics,sale,new'

-- Normalized: a separate table with one row per tag
CREATE TABLE product_tags (
    product_id INTEGER REFERENCES products(id),
    tag VARCHAR(50) NOT NULL,
    PRIMARY KEY (product_id, tag)
);
Key points
  • 1NF requires atomic column values, with no lists packed into a single field.
  • 2NF requires non-key columns to depend on the whole primary key, relevant for composite keys.
  • 3NF requires non-key columns to depend only on the primary key, not on each other.
  • Denormalize deliberately, and only after profiling shows normalization is an actual bottleneck.
