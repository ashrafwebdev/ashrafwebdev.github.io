GROUP BY and aggregate functions

SQL · part of the free zero-to-hero guide

Builds on: JOINs: inner, left, right

GROUP BY collapses rows sharing the same value in specified columns into a single summary row, typically paired with an aggregate function like COUNT, SUM, AVG, MIN, or MAX to compute something across each group.

Every column in the SELECT list must either be included in the GROUP BY clause or wrapped in an aggregate function — SQL enforces this because a non-aggregated, non-grouped column would have multiple different values within a single summary row, which is ambiguous. Some engines (notably older MySQL configurations) historically allowed violating this rule and silently picked an arbitrary value, which is a trap rather than a feature.

COUNT(*) counts every row in a group including ones with NULLs, while COUNT(column) counts only rows where that specific column is not NULL — the difference matters whenever the counted column can itself be missing, and mixing them up produces a subtly wrong count that's easy to miss in review.

HAVING filters groups after aggregation, unlike WHERE which filters individual rows before grouping happens — use HAVING COUNT(*) > 5 to keep only groups with more than five rows, something WHERE cannot express, since WHERE runs before the aggregate values even exist.

You can group by multiple columns at once, which produces one summary row per unique combination of those columns rather than one row per single column's value — grouping by both category and year, for example, gives yearly totals broken out per category.

It's worth remembering the logical order these clauses actually run in, even though they're written in a fixed textual order: FROM and JOIN first, then WHERE, then GROUP BY, then HAVING, then SELECT, then ORDER BY. That's exactly why WHERE can't reference an aggregate and HAVING can — by the time HAVING runs, the aggregates already exist.

query.sql
SELECT category, COUNT(*) AS product_count, AVG(price) AS avg_price
FROM products
GROUP BY category
HAVING COUNT(*) > 5
ORDER BY avg_price DESC;
multi_column_group.sql
SELECT category, EXTRACT(YEAR FROM sold_at) AS sale_year, SUM(quantity) AS units_sold
FROM sales
WHERE sold_at >= '2023-01-01'
GROUP BY category, EXTRACT(YEAR FROM sold_at)
HAVING SUM(quantity) > 100
ORDER BY sale_year, units_sold DESC;
count_star_vs_column.sql
-- Counts every row, including rows where discount is NULL
SELECT category, COUNT(*) AS total_rows FROM products GROUP BY category;

-- Counts only rows where discount actually has a value
SELECT category, COUNT(discount) AS rows_with_discount FROM products GROUP BY category;
Key points
  • GROUP BY collapses rows sharing a value into one summary row per group.
  • COUNT, SUM, AVG, MIN, and MAX are the core aggregate functions.
  • COUNT(*) counts all rows in a group; COUNT(column) skips rows where that column is NULL.
  • Every selected column must be grouped or aggregated, since ungrouped columns would be ambiguous.
  • HAVING filters groups after aggregation; WHERE filters rows before grouping.
  • Grouping by multiple columns produces one row per unique combination of those columns.
  • Logical execution order is FROM/JOIN, WHERE, GROUP BY, HAVING, SELECT, ORDER BY, regardless of writing order.
