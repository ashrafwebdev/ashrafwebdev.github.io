Object-oriented PHP: classes, interfaces

PHP · part of the free zero-to-hero guide

PHP classes look similar to Java or C#: class Name { }, with properties, a __construct() method (PHP's constructor), and regular methods. $this refers to the current instance inside a non-static method, giving access to that specific object's properties and other methods.

Interfaces define a contract — a set of methods a class promises to implement — without providing any implementation themselves, useful for writing code that depends on behavior rather than a specific concrete class. A single class can implement several interfaces at once, but can only extend one parent class, since PHP does not support multiple inheritance of implementation.

Constructor property promotion (private float $radius directly in the constructor signature) removes a lot of PHP class boilerplate in modern versions — before this feature, you had to declare each property separately above the constructor and then manually assign $this->radius = $radius; for every parameter.

public, protected, and private control visibility of properties and methods: public is accessible from anywhere, protected only from inside the class and its subclasses, and private only from inside the exact class it's declared in — not even a subclass can touch a parent's private members directly.

Abstract classes (abstract class) sit between interfaces and regular classes — they can declare abstract methods (signature only, forcing subclasses to implement them) while also providing real, shared implementation for other methods, which plain interfaces cannot do. Traits offer a different kind of code reuse: a trait's methods can be pulled into multiple unrelated classes with use TraitName;, which is useful when several classes need the same behavior but don't share a natural inheritance relationship.

Static properties and methods (public static function make()) belong to the class itself rather than to any instance, and are called with ClassName::method(). A subtle gotcha is that self:: inside a static method always refers to the class where the method is literally defined, while static:: ("late static binding") refers to whichever class was actually called at runtime — this matters when a subclass overrides a static factory method and you want the parent's shared logic to still return an instance of the correct subclass.

classes.php
<?php
interface Shape {
    public function area(): float;
}

class Circle implements Shape {
    public function __construct(private float $radius) {}

    public function area(): float {
        return pi() * $this->radius ** 2;
    }
}

$c = new Circle(3);
echo $c->area();
?>
abstract_and_traits.php
<?php
trait Loggable {
    public function log(string $message): void {
        echo "[" . static::class . "] $message\n";
    }
}

abstract class Shape {
    use Loggable;

    abstract public function area(): float;

    public function describe(): string {
        return "This shape has area " . $this->area(); // shared implementation
    }
}

class Square extends Shape {
    public function __construct(private float $side) {}

    public function area(): float {
        return $this->side ** 2;
    }
}

$sq = new Square(4);
echo $sq->describe();
$sq->log("created a square"); // method comes from the trait
?>
static_vs_self.php (late static binding gotcha)
<?php
class Model {
    public static function create(): static {
        // static:: resolves to the CALLED class, not always Model
        return new static();
    }
}

class User extends Model {}

$user = User::create();
echo get_class($user); // "User" — thanks to late static binding
// If create() had used `new self()` instead of `new static()`,
// this would incorrectly return a Model instance instead of a User.
?>
Key points
  • Constructor property promotion (private float $radius directly in the constructor signature) removes a lot of PHP class boilerplate in modern versions.
  • A class can implement multiple interfaces but extend only one parent class.
  • public, protected, and private control visibility of properties and methods, same concepts as most OOP languages.
  • Abstract classes (abstract class) can provide partial implementation, unlike interfaces which provide none.
  • Traits let unrelated classes share the same method implementations via use TraitName;, without needing a common parent class.
  • Static members belong to the class, not an instance, and are called with ClassName::method().
  • self:: always refers to the class where the code is written; static:: refers to the class actually called at runtime — this distinction is late static binding.
  • A private property or method declared in a parent class is invisible to subclasses; use protected instead if subclasses need access.
Try it yourself

Define a Shape interface with an area() method, then Circle and Rectangle classes implementing it, and print both areas.
