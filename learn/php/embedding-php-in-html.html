Embedding PHP in HTML

PHP · part of the free zero-to-hero guide

Builds on: Superglobals: $_GET, $_POST, $_SESSION

PHP was designed to mix directly with HTML — you can drop in and out of <?php ... ?> tags anywhere in a file, using PHP only for the dynamic parts and letting the rest remain plain HTML. There's no limit to how many times a single file switches between the two modes; a template file often opens and closes PHP tags dozens of times around small dynamic fragments.

The short echo tag <?= $value ?> is shorthand for <?php echo $value; ?>, and is common in template-style files that are mostly HTML with small dynamic pieces sprinkled in. Unlike the old short open tag <? ?> (which required a php.ini setting and is best avoided entirely), the short echo tag is always available regardless of configuration.

PHP offers an alternative syntax for control structures specifically meant for use inside HTML templates: if (...): ... endif;, foreach (...): ... endforeach;, and similarly for while and for. This colon-and-keyword form avoids a wall of nested curly braces interleaved with HTML tags, which gets visually confusing fast in a mixed file.

A subtle whitespace gotcha: a newline immediately after a closing ?> tag is consumed automatically by PHP so it doesn't leak an extra blank line into the output, but this rule only applies to that one specific newline — extra blank lines or stray output before the first <?php tag (for example a byte-order-mark or trailing whitespace after a closing tag in an included file) will be sent to the browser and can break things like header() calls, which must run before any output.

Keeping business logic out of files that also contain HTML is a discipline worth enforcing even without a framework: a mixed file should ideally only reference variables that were already computed and validated earlier in the request, using PHP purely to output and loop over that prepared data rather than to fetch it from a database or run validation inline.

Modern PHP projects, especially anything built on Laravel (Blade) or Symfony (Twig), typically use a dedicated templating engine instead of raw embedded PHP tags for larger views — templating engines add features like template inheritance, automatic escaping by default, and a syntax that's harder to accidentally break out of into arbitrary PHP.

page.php
<!DOCTYPE html>
<html>
<body>
  <h1>Welcome, <?= htmlspecialchars($name) ?>!</h1>
  <ul>
    <?php foreach ($items as $item): ?>
      <li><?= htmlspecialchars($item) ?></li>
    <?php endforeach; ?>
  </ul>
</body>
</html>
alt_syntax.php
<?php $cart = ['apple' => 2, 'bread' => 1]; ?>
<!DOCTYPE html>
<html>
<body>
  <?php if (empty($cart)): ?>
    <p>Your cart is empty.</p>
  <?php else: ?>
    <ul>
      <?php foreach ($cart as $product => $qty): ?>
        <li><?= htmlspecialchars($product) ?> x <?= (int) $qty ?></li>
      <?php endforeach; ?>
    </ul>
  <?php endif; ?>
</body>
</html>
common_mistake.php (output before header())
  <!-- A stray blank line or space BEFORE the opening <?php tag,
       or here after a closing ?> tag in an included file,
       counts as output already sent to the browser. -->
<?php
require 'includes/header_fragment.php'; // if that file has trailing
                                          // whitespace after its closing ?>,
                                          // this next line will fail:
header('Location: /dashboard.php'); // Warning: headers already sent
exit;
?>
Key points
  • The alternative syntax (foreach (...): ... endforeach;) is common specifically in templates mixing PHP with HTML — more readable than nested braces in that context.
  • Always escape dynamic values with htmlspecialchars() when echoing them into HTML.
  • A file can switch between PHP and HTML mode as many times as needed with <?php ?> tags.
  • <?= $value ?> is always available and is shorthand for <?php echo $value; ?> — prefer it over the old, configuration-dependent short open tag.
  • Output sent before a header() call — even a single stray blank line or space outside PHP tags — causes a "headers already sent" error.
  • Keep templates focused on displaying already-prepared data; fetching and validating data belongs earlier in the request, not inside the HTML file.
  • Modern PHP projects generally reach for a templating engine (Blade, Twig) rather than raw embedded PHP once a view grows past something trivial.
  • PHP automatically swallows exactly one newline right after a closing ?> tag, but not any other stray whitespace.
Try it yourself

Build a page.php file that loops over a PHP array of items and displays them as an HTML list, safely escaping each item. Then rewrite the same loop using the alternative colon syntax (foreach/endforeach) instead of curly braces, and add a conditional block using if/endif that shows a "no items" message when the array is empty.
