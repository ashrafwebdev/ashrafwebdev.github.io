01 Zero stage

Functions and basic form handling

PHP · part of the free zero-to-hero guide

Builds on: Syntax, variables, and control structures

PHP functions are defined with function name(params) { }. Modern PHP supports optional type hints on parameters and return values, which catch mistakes early without giving up PHP's flexibility. Parameters can also have default values, letting callers omit arguments for the common case: function greet($name = "friend").

PHP was built from the ground up for handling HTML forms — submitted form data arrives automatically in PHP's superglobal arrays ($_GET, $_POST), ready to read without any extra parsing step. A typical form-handling function accepts that raw array data, validates it, and returns either a clean value or an error to show the user.

Functions can accept a variable number of arguments using the variadic operator, function sum(...$numbers), which collects any number of trailing arguments into a single array inside the function body. The same ... spread syntax can expand an array back out into individual arguments when calling a function.

By default, arguments are passed by value — a copy is made, so modifying a parameter inside a function does not affect the caller's variable. Prefixing a parameter with an ampersand (function increment(&$value)) passes it by reference instead, letting the function mutate the caller's original variable directly; this is used sparingly since it can make code harder to reason about.

Anonymous functions (closures) let you define a function inline and assign it to a variable or pass it directly as an argument: $double = function ($x) { return $x * 2; };. Closures don't automatically see variables from the enclosing scope — you must explicitly import them with use (&$total) (with an ampersand if you need to modify the outer variable).

The arrow function syntax, fn($x) => $x * 2, introduced in PHP 7.4, is shorthand for a single-expression closure that automatically captures outer variables by value — much less boilerplate than use() for simple callbacks passed to functions like array_map() or array_filter().

functions.php
<?php
function calculateTotal(float $price, int $quantity): float {
    return $price * $quantity;
}

echo calculateTotal(9.99, 3);
?>
form_handler.php
<?php
function validateAge(array $formData): int|string {
    $age = trim($formData['age'] ?? '');
    if ($age === '' || !ctype_digit($age)) {
        return "Please enter a valid whole number for age.";
    }
    return (int) $age;
}

$result = validateAge($_POST);
if (is_string($result)) {
    echo "Error: $result";
} else {
    echo "Age accepted: $result";
}
?>
closures.php
<?php
$prices = [9.99, 19.99, 4.50];

// Arrow function: implicitly captures $taxRate by value
$taxRate = 0.08;
$withTax = array_map(fn($p) => round($p * (1 + $taxRate), 2), $prices);
print_r($withTax);

// Traditional closure that mutates an outer variable by reference
$total = 0;
$addToTotal = function (float $amount) use (&$total) {
    $total += $amount;
};
array_map($addToTotal, $prices);
echo $total;
?>
Key points
  • Type hints (float $price) are optional but recommended — they catch type mistakes early and document intent.
  • PHP functions can have default parameter values, just like many other languages: function greet($name = "friend").
  • A function without an explicit return returns NULL.
  • Declare strict_types=1 at the top of a file to disable PHP's automatic type coercion for stricter type safety.
  • Variadic parameters (...$args) let a function accept any number of trailing arguments as an array.
  • Arguments pass by value by default; use &$param to pass by reference and let a function modify the caller's variable.
  • Closures need explicit use (...) to access outer-scope variables; arrow functions (fn() =>) capture automatically by value.
  • Union return types like int|string (PHP 8+) let a function honestly declare that it can return more than one type, which the caller must then check.
Try it yourself

Write a typed PHP function that calculates a total with tax, given a price and a tax rate, and echo the result. Then write a second function that validates a submitted form field (like an email or age) from an array such as $_POST, returning either a cleaned value or an error string, and call it with both valid and invalid sample data to show both paths.
