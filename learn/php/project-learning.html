02 Learning stage capstone

A hand-rolled blog engine with real logins and comments

PHP · ties together everything in the Learning stage

This project moves you from a single mysqli script to a small, genuinely object-oriented application: a blog with real user accounts, posts only logged-in users can write, and comments anyone can leave. It's the first time you'll organize PHP into models, a router, and views instead of one file doing everything, and the first time you'll manage a dependency with Composer instead of hand-rolling it yourself.

The constraint: no framework. You write the front controller, the models, and the views yourself, using plain PDO for persistence and Composer only for your own class autoloading plus one real third-party package. That's deliberate — feeling what a router and an ORM-ish model layer actually do by building a small one is what makes reaching for Laravel or Symfony later feel like less magic.

Real accounts mean real security discipline: hashed passwords, session regeneration on login, and a logout that actually clears everything — not just "if logged in, show the write-post link."

  • Object-oriented PHP: classes, interfaces
  • Working with MySQL via PDO
  • Sessions, cookies, and basic auth
  • Composer and package management
  • Basic MVC structure
Requirements
  • A Composer-managed project with a composer.json declaring PSR-4 autoloading for your own namespace (e.g. App\), so your classes load with no manual require statements.
  • At least three classes with real behavior — a Post model, a Comment model, and a User model — each using PDO prepared statements internally for its own persistence, not a controller reaching directly into the database.
  • A minimal front controller (index.php) that routes at least four distinct paths — the post list, a single post with its comments, login, and create-post — to the right controller logic.
  • A login flow: passwords hashed with password_hash() and checked with password_verify(), a session started and session_regenerate_id(true) called right after a successful login, and a logout route that clears both the session data and the session cookie.
  • Only a logged-in user can reach the create-post route; anyone, including guests, can leave a comment on a post through its own form.
  • Post bodies are written in Markdown and rendered to HTML using a real third-party Composer package (for example league/commonmark), pulled in with composer require and used through the autoloader — not a hand-rolled parser.
  • Every place user-supplied text is echoed into HTML is escaped, and no SQL statement anywhere in the project concatenates user input directly into the query string.
Suggested approach
  1. Run composer init, set up the PSR-4 mapping to src/, and get one trivial autoloaded class working end to end before writing any real logic.
  2. Build the PDO connection and the three models first, exercising each model's methods directly from a throwaway script — no routing yet — to confirm persistence actually works.
  3. Build the front controller and wire up the post-list and single-post-with-comments routes before touching login, so most of the app works while still fully public.
  4. Add login and logout, then gate the create-post route behind a logged-in check.
  5. Pull in the Markdown package last and swap raw post bodies for rendered ones — it only touches display, so it can't destabilize anything that's already working.
Stretch goals
  • Let a logged-in author edit or delete only their own posts, enforced by comparing the session's user id against the post's owner id server-side, not just hiding the button in the view.
  • Add a separate "remember me" cookie that logs a returning visitor back in automatically, distinct from the session cookie itself.
  • Add simple pagination to the post list once you have more than a handful of posts to page through.
