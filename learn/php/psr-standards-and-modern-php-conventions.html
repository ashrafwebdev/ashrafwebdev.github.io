PSR standards and modern PHP conventions

PHP · part of the free zero-to-hero guide

PSRs (PHP Standards Recommendations) are community-agreed conventions maintained by the PHP-FIG group — PSR-1/PSR-12 cover coding style, PSR-4 covers autoloading, and PSR-7 covers HTTP message interfaces, among others.

Following PSR standards means your code looks familiar to any PHP developer, and your classes autoload correctly with Composer and interoperate cleanly with other PSR-compliant libraries.

PSR-4 autoloading in composer.json
{
  "autoload": {
    "psr-4": {
      "App\\": "src/"
    }
  }
}
Key points
  • PSR-12 defines coding style (indentation, brace placement, naming) — tools like PHP_CodeSniffer or PHP-CS-Fixer enforce it automatically.
  • PSR-4 maps namespaces to directory structure, which is what makes Composer's autoloader able to find your classes.
  • Following PSRs makes it far easier for libraries and frameworks from different authors to work together.
  • Most modern frameworks (Laravel, Symfony) are themselves PSR-compliant by default.
Try it yourself

Set up PSR-4 autoloading in a composer.json for a src/ folder, create a namespaced class inside it, and instantiate it from an entry file using only the autoloader.
