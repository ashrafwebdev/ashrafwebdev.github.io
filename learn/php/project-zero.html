01 Zero stage capstone

A guestbook that actually remembers your name

PHP · ties together everything in the Zero stage

The five Zero-stage PHP topics — syntax and control structures, functions and form handling, the superglobals, embedding PHP in HTML, and basic MySQL queries — exist to get you to one milestone: a page that reads and writes real data instead of just echoing static text. This project is a classic guestbook, the oldest kind of dynamic web page there is, and it forces you to use every one of those five topics together on a single, small feature.

The constraint that makes this a genuine test: no classes, no PDO, no Composer, no framework. Just a couple of plain .php files talking to MySQL through mysqli and prepared statements, the way the Zero-stage lessons taught it. Everything you reach for has to come from what you've actually learned so far.

By the end you'll have a page that lists every message anyone has ever left, lets a new visitor add their own, remembers that visitor's name for next time using $_SESSION, and never once trusts user input without checking or escaping it first.

  • Syntax, variables, and control structures
  • Functions and basic form handling
  • Superglobals: $_GET, $_POST, $_SESSION
  • Embedding PHP in HTML
  • Basic MySQL queries
Requirements
  • A MySQL table you create yourself with an auto-incrementing primary key id, plus name, message, and created_at columns.
  • A page that connects with mysqli, runs a prepared SELECT, and loops over every saved entry with foreach to display them — every value echoed into HTML must be escaped with htmlspecialchars().
  • A form on the same page that submits a name and a message; the handler uses a prepared INSERT with bind_param() to save it — string-concatenated SQL anywhere in the file is an automatic fail.
  • A dedicated function (not inline code in the middle of the handler) that validates the submitted name and message aren't empty, returning either a cleaned value or an error string.
  • When validation fails, the page shows the error and re-displays whatever the visitor already typed, instead of clearing the form and making them start over.
  • The guestbook remembers the last name a visitor submitted using $_SESSION, and pre-fills the name field with it on their next visit.
  • At least one place in the page uses the short echo tag <?= ?> or the alternative colon syntax (foreach (...): ... endforeach;) instead of a full brace block, the way the embedding-PHP-in-HTML lesson recommends for template-style files.
Suggested approach
  1. Design and create the table first, directly in SQL, before writing any PHP — decide your columns and types up front.
  2. Build the read-only listing half first: connect, run the prepared SELECT, loop and display. Insert a couple of test rows by hand and confirm the page renders correctly before touching the form.
  3. Add the submission form and a separate validation function, then wire it to a prepared INSERT once validation passes.
  4. Add the error/redisplay path so an invalid submission doesn't throw away what the visitor typed.
  5. Add the $_SESSION name-remembering last, since it only matters once the form itself is already working correctly.
Stretch goals
  • Add pagination with LIMIT and OFFSET so only the most recent 10 entries show at once, with a "load more" link.
  • Add a hidden honeypot field to the form that silently rejects the submission if it's filled in, catching basic spam bots without any external library.
  • Add a simple admin-only view, gated by a hardcoded password check, that can delete a single message by id.
