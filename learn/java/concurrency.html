Concurrency: threads and the executor framework

Java · part of the free zero-to-hero guide

Java has built-in support for concurrency: a Thread represents an independent path of execution, created either by extending Thread or, more commonly, by passing a Runnable to a new Thread and calling start().

Creating raw threads by hand does not scale well, so the executor framework (java.util.concurrent) provides thread pools via Executors.newFixedThreadPool(n), letting you submit many tasks that get run across a bounded, reusable set of worker threads.

Shared mutable state accessed from multiple threads needs coordination to avoid race conditions; tools like the synchronized keyword, java.util.concurrent.atomic classes, and concurrent collections such as ConcurrentHashMap exist specifically to make that coordination safe.

PoolDemo.java
import java.util.concurrent.*;

public class PoolDemo {
    public static void main(String[] args) throws InterruptedException {
        ExecutorService pool = Executors.newFixedThreadPool(3);

        for (int i = 1; i <= 5; i++) {
            int taskId = i;
            pool.submit(() -> {
                System.out.println("Running task " + taskId +
                    " on " + Thread.currentThread().getName());
            });
        }

        pool.shutdown();
        pool.awaitTermination(5, TimeUnit.SECONDS);
    }
}
Key points
  • A Thread runs a Runnable's code independently of the main program flow.
  • The executor framework manages a pool of reusable threads instead of creating one thread per task.
  • Shared mutable state across threads requires synchronization to avoid race conditions.
  • ConcurrentHashMap and the atomic package offer thread-safe alternatives to plain collections and counters.

Write a program that submits 10 tasks to a fixed thread pool of size 4, where each task prints its task number and the current thread's name, then shuts the pool down cleanly.
