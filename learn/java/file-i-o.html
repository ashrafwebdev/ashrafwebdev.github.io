File I/O

Java · part of the free zero-to-hero guide

Java's modern file API lives in java.nio.file, centered on the Path and Files classes. Simple operations, like reading an entire text file into memory, take a single line with Files.readString or Files.readAllLines; these are convenient but load the whole file into memory, so they're only appropriate for files you know are reasonably small.

For larger files or streaming reads, BufferedReader combined with a FileReader (or Files.newBufferedReader) lets you process a file line by line without loading it all into memory at once, using readLine() in a loop until it returns null. Writing works symmetrically with Files.writeString or a BufferedWriter.

Because file operations can fail (missing file, no permission, disk full, another process holding a lock), most methods in this API throw a checked IOException, so file code is almost always paired with try-with-resources or a try/catch block; this is one of the clearest real-world examples of why Java's checked exceptions exist.

Files also provides methods for inspecting and manipulating the filesystem beyond reading and writing content: Files.exists, Files.createDirectories, Files.delete, Files.copy, and Files.list (which returns a lazily-populated Stream of the entries in a directory) cover most everyday filesystem tasks without needing the older, clunkier java.io.File class.

When working with binary data rather than text, Files.readAllBytes and Files.write(path, byte[]) read and write raw bytes directly; for text, always be conscious of character encoding — the overloads that don't take a Charset argument use UTF-8 by default in modern Java, but explicitly passing StandardCharsets.UTF_8 makes that assumption visible in the code rather than implicit.

Relative paths are resolved against the JVM's current working directory, which can be a source of confusing bugs when a program is launched from a different directory than expected; Path.of("notes.txt").toAbsolutePath() is a handy way to see exactly where a relative path actually resolves to at runtime.

FileDemo.java
import java.nio.file.*;
import java.io.IOException;
import java.util.List;

public class FileDemo {
    public static void main(String[] args) throws IOException {
        Path path = Path.of("notes.txt");
        Files.writeString(path, "First line\nSecond line\n");

        List<String> lines = Files.readAllLines(path);
        for (String line : lines) {
            System.out.println("> " + line);
        }
    }
}
StreamingRead.java
import java.io.*;
import java.nio.charset.StandardCharsets;
import java.nio.file.*;

public class StreamingRead {
    public static void main(String[] args) throws IOException {
        Path log = Path.of("large_log.txt");
        if (!Files.exists(log)) {
            Files.createFile(log);
        }

        long errorCount = 0;
        try (BufferedReader reader = Files.newBufferedReader(log, StandardCharsets.UTF_8)) {
            String line;
            while ((line = reader.readLine()) != null) {
                if (line.contains("ERROR")) errorCount++;
            }
        } // reader.close() is called automatically, even if an exception is thrown

        System.out.println("Error lines: " + errorCount);
        System.out.println("Resolved to: " + log.toAbsolutePath());
    }
}
Key points
  • java.nio.file.Files and Path are the modern, preferred file API over the older java.io.File.
  • Files.readString/readAllLines are convenient for small files; BufferedReader suits large files processed line by line.
  • Most file operations throw the checked IOException, which callers must handle or declare.
  • Try-with-resources ensures streams and readers are closed even when an error occurs mid-read.
  • Files also handles directory and metadata operations: exists, createDirectories, delete, copy, list.
  • Be explicit about character encoding with StandardCharsets.UTF_8 rather than relying on implicit defaults.
  • Relative paths resolve against the JVM's working directory; toAbsolutePath() reveals exactly where that is.
Try it yourself

Write a program that writes a small list of names to a file, one per line, then reads the file back and prints each name in uppercase. Then extend it to stream a larger file line by line with BufferedReader, count how many lines contain a given keyword, and print the file's absolute path using toAbsolutePath() so you can confirm exactly which file was read.
