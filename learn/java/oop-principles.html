OOP principles: inheritance, polymorphism, interfaces

Java · part of the free zero-to-hero guide

Builds on: Compiling and running with javac/java

Inheritance lets one class (a subclass) extend another (a superclass) with extends, inheriting its fields and methods while adding or overriding its own. Java only allows single inheritance of classes — a class can extend exactly one superclass — which avoids the diamond-inheritance ambiguity that multiple class inheritance can cause in other languages.

Polymorphism means a variable declared with a supertype can hold any subtype object, and calling an overridden method invokes the subtype's version automatically at runtime; this is called dynamic dispatch. It's what lets code written against a Shape reference correctly call Circle.area() or Square.area() without ever knowing which concrete subtype it's holding.

Overriding a method requires the same signature as the superclass version and is best marked with @Override, which isn't strictly required but causes the compiler to catch typos (a misspelled method name silently creates a new, unrelated method instead of overriding, and @Override turns that mistake into a compile error).

An interface defines a contract of method signatures without implementation (though it can include default methods with a body, and static methods). A class implements an interface, promising to provide those methods, and unlike class inheritance a single class can implement many interfaces, which is how Java achieves a form of multiple inheritance of behavior.

The keyword super lets a subclass call its superclass's constructor (super(args), must be the first statement) or an overridden method's original implementation (super.methodName()), which is useful when you want to extend rather than completely replace inherited behavior.

Favoring interfaces (or composition) over deep inheritance hierarchies is a widely followed Java design principle: deep hierarchies tend to become fragile, where a change to a base class ripples unpredictably into many subclasses, while interfaces keep classes flexible and easier to test, since code can depend on a contract rather than a specific implementation.

Shapes.java
interface Shape {
    double area();
    default String describe() { return "A shape with area " + area(); }
}

class Circle implements Shape {
    private double radius;
    Circle(double radius) { this.radius = radius; }
    public double area() { return Math.PI * radius * radius; }
}

class Square implements Shape {
    private double side;
    Square(double side) { this.side = side; }
    public double area() { return side * side; }
}

public class Shapes {
    public static void main(String[] args) {
        Shape[] shapes = { new Circle(2), new Square(3) };
        for (Shape s : shapes) {
            System.out.println(s.getClass().getSimpleName() + ": " + s.describe());
        }
    }
}
Employees.java
class Employee {
    protected String name;
    protected double baseSalary;

    Employee(String name, double baseSalary) {
        this.name = name;
        this.baseSalary = baseSalary;
    }

    double totalPay() { return baseSalary; }
}

class Manager extends Employee {
    private double bonus;

    Manager(String name, double baseSalary, double bonus) {
        super(name, baseSalary); // must be the first statement
        this.bonus = bonus;
    }

    @Override
    double totalPay() {
        return super.totalPay() + bonus; // extend, don't fully replace
    }
}

public class Employees {
    public static void main(String[] args) {
        Employee e = new Manager("Karim", 60000, 8000);
        System.out.println(e.totalPay()); // dynamic dispatch calls Manager's version
    }
}
Key points
  • extends creates a subclass (single inheritance only); implements fulfills an interface contract (multiple allowed).
  • Polymorphism lets a supertype reference invoke the correct overridden method at runtime via dynamic dispatch.
  • Always mark overrides with @Override so the compiler catches signature mismatches instead of silently creating a new method.
  • Interfaces describe capabilities without dictating how they are implemented, and may include default and static methods.
  • super(args) must be the first statement in a subclass constructor; super.method() calls the parent's original implementation.
  • Programming against interfaces rather than concrete classes improves flexibility and testability.
  • Deep inheritance hierarchies tend to be fragile; prefer shallow hierarchies or composition where possible.
Try it yourself

Define a Payable interface with an amountDue() method, implement it in two classes (Invoice and Subscription), then loop over an array of Payable and print each amount due. Then create a PastDueInvoice subclass of Invoice that overrides amountDue() to add a late fee using super.amountDue(), and confirm via the polymorphic loop that the correct overridden value is used.
