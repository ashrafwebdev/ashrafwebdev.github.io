Streams and lambda expressions

Java · part of the free zero-to-hero guide

A lambda expression is a compact, anonymous function, written as (parameters) -> expression, that can be passed around as a value wherever a matching functional interface (an interface with a single abstract method, like Comparator or Runnable) is expected. Behind the scenes a lambda is compiled to an implementation of that interface, not to some special new language construct.

The java.util.function package defines the common functional interface shapes you'll reach for constantly: Function<T,R> (takes a T, returns an R), Predicate<T> (takes a T, returns boolean), Consumer<T> (takes a T, returns nothing), and Supplier<T> (takes nothing, returns a T) cover the vast majority of use cases without needing to write your own interface.

The Stream API, introduced in Java 8, lets you express collection processing as a pipeline of operations — filter, map, sorted, collect — rather than hand-written loops, often making the intent of the code clearer by naming each transformation instead of burying it inside loop bodies and mutable accumulator variables.

Streams are lazy: intermediate operations like filter and map don't run until a terminal operation like collect, forEach, or reduce pulls the results through the pipeline. This laziness lets the stream fuse operations and process elements one at a time through the whole chain rather than materializing an intermediate list after every step.

A stream can only be consumed once: calling a terminal operation on it a second time throws IllegalStateException, because a stream models a single pass over a data source rather than a reusable collection. If you need to run multiple pipelines over the same data, start a fresh stream from the source collection each time.

Collectors offers more than just gathering results into a List: Collectors.groupingBy partitions elements into a Map keyed by some derived property, Collectors.joining concatenates strings with an optional delimiter, and Collectors.toMap builds a Map directly from a stream, which together cover most of the aggregation logic that used to require manual loop-and-accumulate code.

Names.java
import java.util.*;
import java.util.stream.*;

public class Names {
    public static void main(String[] args) {
        List<String> names = List.of("Amina", "Bilal", "Omar", "Aisha");

        List<String> result = names.stream()
            .filter(n -> n.startsWith("A"))
            .map(String::toUpperCase)
            .sorted()
            .collect(Collectors.toList());

        System.out.println(result);
    }
}
Grouping.java
import java.util.*;
import java.util.function.*;
import java.util.stream.*;

record Employee(String name, String department, double salary) {}

public class Grouping {
    public static void main(String[] args) {
        List<Employee> staff = List.of(
            new Employee("Amina", "Engineering", 95000),
            new Employee("Bilal", "Sales", 60000),
            new Employee("Omar", "Engineering", 88000)
        );

        Map<String, List<String>> byDept = staff.stream()
            .collect(Collectors.groupingBy(
                Employee::department,
                Collectors.mapping(Employee::name, Collectors.toList())));
        System.out.println(byDept);

        double totalPayroll = staff.stream()
            .mapToDouble(Employee::salary)
            .sum();
        System.out.println("Total payroll: " + totalPayroll);

        Predicate<Employee> isHighEarner = e -> e.salary() > 90000;
        String names = staff.stream()
            .filter(isHighEarner)
            .map(Employee::name)
            .collect(Collectors.joining(", "));
        System.out.println("High earners: " + names);
    }
}
Key points
  • Lambdas provide a concise syntax for implementing single-method functional interfaces inline.
  • java.util.function's Function, Predicate, Consumer, and Supplier cover most common lambda shapes without custom interfaces.
  • method::reference is shorthand for a lambda that just calls an existing method.
  • Stream pipelines chain filter, map, and sorted, ending in a terminal operation like collect, forEach, or reduce.
  • Streams are lazily evaluated: nothing runs until a terminal operation is invoked.
  • A stream can only be traversed once; reusing a consumed stream throws IllegalStateException.
  • Collectors.groupingBy, joining, and toMap handle common aggregation patterns without manual loops.
Try it yourself

Given a List of Integer, use a stream to filter out odd numbers, square the remaining values, and collect the results into a new List. Then, given a List of a small record type with a category field, use Collectors.groupingBy to build a Map from category to a count of items in that category, and add a Predicate variable used inside the filter step instead of an inline lambda.
