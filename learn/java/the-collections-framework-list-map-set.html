The Collections framework (List, Map, Set)

Java · part of the free zero-to-hero guide

The java.util Collections framework provides ready-made, resizable data structures. List (usually ArrayList) preserves insertion order and allows duplicates; Set (usually HashSet) stores unique elements with no defined order; Map (usually HashMap) stores key-value pairs with fast average-case lookup by key.

Since Java 5, generics let you parameterize a collection with the type it holds, such as a List of String, so the compiler catches type mistakes at compile time instead of throwing a ClassCastException later when you pull an element back out and cast it to the wrong type.

Each interface has multiple implementations with different performance trade-offs. ArrayList gives constant-time indexed access but linear-time insertion/removal in the middle; LinkedList gives constant-time insertion at the ends but linear-time indexed access; HashMap and HashSet average constant-time operations but give no ordering guarantee; TreeMap and TreeSet keep keys sorted at the cost of logarithmic-time operations; LinkedHashMap preserves insertion order while keeping hash-map-like performance.

For HashMap and HashSet to work correctly, keys must have consistent equals and hashCode implementations — using a mutable object as a key and then changing a field that hashCode depends on will effectively "lose" the entry, since the map can no longer find the bucket it was originally stored in.

Since Java 9, the factory methods List.of(...), Set.of(...), and Map.of(...) create small, convenient immutable collections; calling add, remove, or put on one of these throws UnsupportedOperationException, which is a useful safety net when you want to guarantee a collection never changes after creation.

Iterating a Map is most efficient through entrySet() when you need both the key and the value together, since keySet() followed by a separate get(key) call per entry does a second lookup for every element.

Inventory.java
import java.util.*;

public class Inventory {
    public static void main(String[] args) {
        Map<String, Integer> stock = new HashMap<>();
        stock.put("apples", 50);
        stock.put("bananas", 30);

        List<String> names = new ArrayList<>(stock.keySet());
        Set<String> lowStock = new HashSet<>();

        for (String name : names) {
            if (stock.get(name) < 40) lowStock.add(name);
        }
        System.out.println("Low stock: " + lowStock);
    }
}
EntrySetVsKeySet.java
import java.util.*;

public class EntrySetVsKeySet {
    public static void main(String[] args) {
        Map<String, Double> prices = new LinkedHashMap<>(); // preserves insertion order
        prices.put("apples", 1.20);
        prices.put("bananas", 0.60);
        prices.put("cherries", 4.50);

        // Preferred: one lookup per entry via entrySet()
        for (Map.Entry<String, Double> entry : prices.entrySet()) {
            System.out.printf("%s: $%.2f%n", entry.getKey(), entry.getValue());
        }

        // Immutable collection: mutating it throws UnsupportedOperationException
        List<String> fixed = List.of("a", "b", "c");
        try {
            fixed.add("d");
        } catch (UnsupportedOperationException e) {
            System.out.println("Cannot modify an immutable List.of(...) result");
        }
    }
}
Key points
  • List keeps order and duplicates; Set guarantees uniqueness; Map pairs keys with values.
  • Generics like a List of String catch type errors at compile time instead of a runtime ClassCastException.
  • ArrayList, LinkedList, HashMap, TreeMap, and LinkedHashMap trade off speed and ordering differently by operation.
  • Hash-based collections require consistent equals/hashCode; mutating a key's hash-relevant fields after insertion can make an entry unreachable.
  • List.of, Set.of, and Map.of create small immutable collections that throw on any modification attempt.
  • Prefer iterating entrySet() over keySet() plus get() when you need both key and value, to avoid a redundant lookup.
  • Choosing the right collection depends on how the data will be accessed: indexed, sorted, unique, or insertion-ordered.
Try it yourself

Build a HashMap of product name to price, use a List to keep the names sorted, and print each product with its price formatted to two decimal places. Then convert the map to a TreeMap to get keys automatically sorted, wrap the final result with Map.of or Collections.unmodifiableMap, and confirm attempting to modify it throws UnsupportedOperationException.
