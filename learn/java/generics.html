Generics

Java · part of the free zero-to-hero guide

Builds on: Build tools: Maven or Gradle basics

Generics let a class or method be written once and work with any type, while still giving the compiler enough information to catch type errors. A generic class like Box<T> declares a type parameter T that gets filled in when the class is used, such as Box<String>; by convention type parameters use single uppercase letters like T (type), E (element), K/V (key/value).

Generic methods can declare their own type parameter independent of the class they live in, written before the return type (static <E> void printAll(...)), such as a method that swaps two elements in an array of any type; the type parameter is often inferred from the arguments, so callers rarely need to specify it explicitly.

Bounded type parameters, written as T extends Number, restrict what a generic can be used with, letting you call methods defined on that bound (like doubleValue()) while still working across any matching subtype such as Integer or Double. Multiple bounds are possible with T extends Comparable<T> & Serializable.

Wildcards handle situations where you don't need a specific type, only a relationship: List<? extends Number> accepts a List of any Number subtype for reading elements out (producer), while List<? super Integer> accepts any list that can hold an Integer or its supertypes for writing elements in (consumer) — this pattern is often summarized as PECS, "producer extends, consumer super".

Generics in Java are implemented via type erasure: the compiler checks and enforces generic types at compile time, but strips that information out of the compiled bytecode, so at runtime a List<String> and a raw List are the exact same class. This is why you cannot create an array of a generic type directly, cannot use instanceof against a parameterized type, and why generic type information is unavailable via reflection at runtime.

Using a raw type — a generic class without its type parameter, like plain List instead of List<String> — compiles (for backward compatibility with pre-Java-5 code) but disables the compiler's type checking for that variable, silently reintroducing the exact ClassCastException risk generics were designed to eliminate; modern code should essentially never use raw types deliberately.

Box.java
public class Box<T> {
    private T contents;

    public void set(T contents) { this.contents = contents; }
    public T get() { return contents; }

    public static <E> void printAll(java.util.List<E> items) {
        for (E item : items) System.out.println(item);
    }

    public static void main(String[] args) {
        Box<String> box = new Box<>();
        box.set("hello generics");
        System.out.println(box.get());
    }
}
Wildcards.java
import java.util.*;

public class Wildcards {
    // Producer: we only read Numbers out, so 'extends' is safe
    static double sumAll(List<? extends Number> numbers) {
        double total = 0;
        for (Number n : numbers) total += n.doubleValue();
        return total;
    }

    // Consumer: we only write Integers in, so 'super' is safe
    static void fillWithOnes(List<? super Integer> list, int count) {
        for (int i = 0; i < count; i++) list.add(1);
    }

    static <T extends Comparable<T>> T max(T a, T b) {
        return a.compareTo(b) >= 0 ? a : b;
    }

    public static void main(String[] args) {
        List<Integer> ints = List.of(1, 2, 3);
        List<Double> doubles = List.of(1.5, 2.5);
        System.out.println(sumAll(ints) + sumAll(doubles));

        List<Number> numberBucket = new ArrayList<>();
        fillWithOnes(numberBucket, 3);
        System.out.println(numberBucket);

        System.out.println(max(3, 7));
    }
}
Key points
  • A type parameter such as T is a placeholder filled in with a real type when the generic is used.
  • Generics move type-mismatch errors from runtime to compile time.
  • Bounded type parameters (T extends Number) restrict a generic to types with certain capabilities.
  • Wildcards express producer/consumer relationships: extends for reading, super for writing (PECS).
  • Generic methods can introduce their own type parameter separate from the enclosing class.
  • Type erasure means generic type information is discarded at compile time; you cannot create generic arrays or use instanceof against a parameterized type.
  • Raw types (a generic class used without its type argument) compile but disable compile-time type checking; avoid them in new code.
Try it yourself

Write a generic Pair class holding two values of possibly different types, with a method swapped() that returns a new Pair with the values reversed. Then write a generic method findMax that takes a List of a type bounded by Comparable and returns the largest element, and a second method that accepts a List of a wildcard extending Number to compute an average, explaining in a comment why extends rather than super is the correct wildcard there.
