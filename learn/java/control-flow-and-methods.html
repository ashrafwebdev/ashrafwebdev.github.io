Control flow and methods

Java · part of the free zero-to-hero guide

Builds on: Syntax, variables, and types

Java supports the familiar if/else, for, while, and do-while loops, plus switch. Since Java 14, switch can also be written as an expression that directly returns a value using arrow syntax (case 1 -> ...), which avoids the classic fall-through bugs of the older colon-based form where forgetting a break silently runs the next case too.

A method is declared with a return type, a name, and a parameter list, and it lives inside a class. Methods marked static belong to the class itself and can be called without creating an object (ClassName.method()); methods without static belong to individual instances and can access that instance's fields via an implicit this.

Method overloading — declaring multiple methods with the same name but different parameter lists — lets you offer several convenient entry points into the same logic, and the compiler picks the right one based on the number and types of arguments you pass, resolved entirely at compile time. This is different from overriding, which happens between a superclass and subclass at runtime.

break exits a loop or switch entirely; continue skips the rest of the current iteration and jumps to the next one. Labeled versions of both (break outer;) let you control an outer loop from inside a nested one, which is occasionally the cleanest way to escape deeply nested iteration without extra flag variables.

Traditional switch statements also support pattern matching as of recent Java versions, where a case can test an object's runtime type directly (case String s ->), binding a typed variable in the same line — this removes a lot of the boilerplate that used to require instanceof checks followed by manual casting.

Java has no goto and no function pointers in the C sense; instead, complex control flow is expressed through methods, recursion, and (as covered in a later lesson) lambda expressions passed as arguments, which keeps control flow readable and keeps the type system involved at every step.

Grade.java
public class Grade {
    static String letterFor(int score) {
        return switch (score / 10) {
            case 10, 9 -> "A";
            case 8 -> "B";
            case 7 -> "C";
            default -> "F";
        };
    }

    public static void main(String[] args) {
        for (int score = 60; score <= 100; score += 20) {
            System.out.println(score + " -> " + letterFor(score));
        }
    }
}
Overloads.java
public class Overloads {
    static int total(int a, int b) { return a + b; }
    static int total(int a, int b, int c) { return a + b + c; }
    static double total(double a, double b) { return a + b; }

    public static void main(String[] args) {
        System.out.println(total(2, 3));        // uses (int, int)
        System.out.println(total(2, 3, 4));      // uses (int, int, int)
        System.out.println(total(2.5, 3.5));     // uses (double, double)

        outer:
        for (int row = 0; row < 3; row++) {
            for (int col = 0; col < 3; col++) {
                if (row == 1 && col == 1) continue outer; // skip rest of row 1
                if (row == 2 && col == 0) break outer;    // stop everything
                System.out.println(row + "," + col);
            }
        }
    }
}
Key points
  • Arrow-form switch expressions return a value directly and do not fall through to the next case.
  • static methods belong to the class; instance methods belong to an object and can use an implicit this.
  • Method overloading is resolved at compile time based on the number and static types of the arguments.
  • A traditional for loop can count through any numeric range; a shorter for-each form for iterating arrays and collections directly is introduced once those topics arrive.
  • Labeled break and continue let you control an outer loop from inside a nested one.
  • Pattern-matching switch cases can test and bind a runtime type in a single case label, avoiding manual instanceof-and-cast boilerplate.
  • Java has no goto; recursion, methods, and lambdas are the idiomatic replacements for that kind of jump.
Try it yourself

Write a static method categorize(int temperature) that uses a switch expression to return "cold", "mild", or "hot", then call it in a for loop that counts through a range of sample temperatures (for example, 0 to 100 in steps of 10). Add an overloaded categorize(double temperature, String unit) that first converts Fahrenheit to Celsius when unit is "F", and use a labeled loop to skip printing any reading below freezing.
