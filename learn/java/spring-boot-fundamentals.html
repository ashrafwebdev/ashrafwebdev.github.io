Spring Boot fundamentals

Java · part of the free zero-to-hero guide

Builds on: Concurrency: threads and the executor framework

Spring Boot is the dominant framework for building Java web applications and REST APIs, built on top of the wider Spring ecosystem. It emphasizes convention over configuration: a minimal Spring Boot project can start an embedded web server (Tomcat by default) and expose an endpoint with only a few annotations, with no external application server to install or configure separately.

The core idea underneath Spring is dependency injection: instead of a class constructing its own collaborators with new, Spring constructs and wires objects (called beans) together automatically based on annotations like @Component, @Service, and @Repository, injecting them wherever they're needed — typically via constructor parameters, which is the recommended style since it makes required dependencies explicit and the class easy to test outside of Spring entirely.

@RestController marks a class whose methods handle HTTP requests and return data (typically serialized to JSON automatically via an embedded Jackson mapper), while @GetMapping, @PostMapping, @PutMapping, and @DeleteMapping map HTTP routes and verbs to specific methods; @RequestBody deserializes an incoming JSON body into a Java object, and @PathVariable/@RequestParam pull values out of the URL path or query string.

Configuration in Spring Boot is typically externalized into an application.properties or application.yml file (database URLs, server port, logging levels), and Spring Boot's auto-configuration mechanism inspects what's on the classpath and configures sensible defaults automatically — adding the Spring Data JPA dependency, for instance, is enough to get a working database connection pool and repository infrastructure without writing that plumbing by hand.

Spring Data JPA layers on top of this to remove most boilerplate database code: declaring an interface that extends JpaRepository<Entity, IdType> automatically gives you working save, findById, findAll, and delete methods, and following a naming convention like findByEmail(String email) generates the corresponding query without writing any SQL at all.

Testing a Spring Boot application doesn't require starting the full application context for every test: @WebMvcTest loads only the web layer for testing a controller in isolation with mocked dependencies, while @SpringBootTest loads the complete application context for true end-to-end integration tests, letting you choose the right trade-off between test speed and realism.

GreetingController.java
import org.springframework.web.bind.annotation.*;
import org.springframework.boot.SpringApplication;
import org.springframework.boot.autoconfigure.SpringBootApplication;

@SpringBootApplication
public class DemoApplication {
    public static void main(String[] args) {
        SpringApplication.run(DemoApplication.class, args);
    }
}

@RestController
class GreetingController {
    @GetMapping("/hello")
    public String hello(@RequestParam(defaultValue = "world") String name) {
        return "Hello, " + name + "!";
    }
}
TaskService.java
import org.springframework.data.jpa.repository.JpaRepository;
import org.springframework.stereotype.Service;
import org.springframework.web.bind.annotation.*;
import java.util.List;

record Task(Long id, String title, boolean done) {}

interface TaskRepository extends JpaRepository<Task, Long> {
    List<Task> findByDone(boolean done); // query generated from the method name
}

@Service
class TaskService {
    private final TaskRepository repository;

    // Constructor injection: Spring supplies the repository bean automatically
    TaskService(TaskRepository repository) {
        this.repository = repository;
    }

    List<Task> pendingTasks() { return repository.findByDone(false); }
}

@RestController
@RequestMapping("/tasks")
class TaskController {
    private final TaskService service;
    TaskController(TaskService service) { this.service = service; }

    @GetMapping("/pending")
    List<Task> pending() { return service.pendingTasks(); }
}
Key points
  • Spring Boot bundles an embedded server and sensible defaults so apps can run standalone with minimal setup.
  • Dependency injection lets Spring construct and wire beans, decoupling classes from their collaborators; constructor injection is preferred for testability.
  • @RestController plus mapping annotations turn plain methods into HTTP endpoints; @RequestBody and @PathVariable extract request data.
  • Beans annotated with @Component/@Service/@Repository are auto-discovered and injected where needed.
  • Auto-configuration inspects the classpath and wires sensible defaults based on which dependencies are present.
  • Spring Data JPA generates repository implementations and queries from interface method names, removing most CRUD boilerplate.
  • @WebMvcTest tests the web layer in isolation; @SpringBootTest loads the full context for integration testing.
