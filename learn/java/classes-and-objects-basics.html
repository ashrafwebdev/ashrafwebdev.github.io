Classes and objects basics

Java · part of the free zero-to-hero guide

Builds on: Control flow and methods

A class is a blueprint; an object is an instance created from that blueprint with the new keyword. Classes group together fields (state) and methods (behavior) that operate on that state, and each object created from a class gets its own independent copy of the instance fields.

A constructor is a special method, named after the class with no return type, that runs when an object is created and typically initializes its fields. If you write no constructor at all, Java supplies a no-argument default one automatically; but as soon as you write any constructor yourself, that automatic default disappears and must be written explicitly if you still want it.

The keyword this refers to the current instance, most commonly used to disambiguate a field from a constructor parameter that shares its name (this.title = title), but it can also be used to call another constructor in the same class as the first statement (this(defaultValue)), a technique called constructor chaining.

Encapsulation — keeping fields private and exposing controlled access through methods — is a core Java habit, not just a style preference. It lets a class validate input in a setter, change its internal representation later without breaking callers, and clearly separate what an object promises to do (its public API) from how it does it (its private implementation).

Java objects are compared with == by reference identity by default (do the two variables point to the exact same object?), not by content. To compare objects by their logical content you must override equals (and, whenever you override equals, also override hashCode so the object still behaves correctly inside hash-based collections like HashMap).

Overriding toString() lets you control how an object prints, which is invaluable for debugging: instead of the default unhelpful Book@1b6d3586, a well-written toString returns something like Book{title='Clean Code', pages=464}.

Book.java
public class Book {
    private String title;
    private int pages;

    public Book(String title, int pages) {
        this.title = title;
        this.pages = pages;
    }

    public String summary() {
        return title + " (" + pages + " pages)";
    }

    public static void main(String[] args) {
        Book b = new Book("Clean Code", 464);
        System.out.println(b.summary());
    }
}
Product.java
import java.util.Objects;

public class Product {
    private final String sku;
    private double price;

    public Product(String sku) {
        this(sku, 0.0); // constructor chaining
    }

    public Product(String sku, double price) {
        this.sku = sku;
        setPrice(price);
    }

    public void setPrice(double price) {
        if (price < 0) throw new IllegalArgumentException("price cannot be negative");
        this.price = price;
    }

    @Override
    public boolean equals(Object o) {
        if (!(o instanceof Product other)) return false;
        return sku.equals(other.sku);
    }

    @Override
    public int hashCode() { return Objects.hash(sku); }

    @Override
    public String toString() { return "Product{sku='" + sku + "', price=" + price + "}"; }
}
Key points
  • Fields marked private are accessible only inside the class, which protects internal state and lets validation live in setters.
  • A constructor initializes an object's fields when it is created with new; writing any constructor removes the automatic no-arg default.
  • this.field = field is the standard pattern for assigning a constructor parameter to a field of the same name.
  • this(...) as the first line of a constructor chains to another constructor in the same class.
  • == compares reference identity for objects; override equals to compare by logical content.
  • Whenever you override equals, also override hashCode, or the object will misbehave in HashMap/HashSet.
  • Overriding toString gives you a readable, debuggable representation instead of the default class@hashcode form.
Try it yourself

Write a Person class with private name and age fields, a constructor, and a method greet() that returns a friendly introduction sentence. Then add a second constructor that takes only a name and chains to the first with a default age of 0, and override equals, hashCode, and toString so two Person objects with the same name and age are considered equal.
