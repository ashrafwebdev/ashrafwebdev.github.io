01 Zero stage

Syntax, variables, and types

Java · part of the free zero-to-hero guide

Every Java program lives inside a class, and every standalone program needs a public static void main(String[] args) method as its entry point — the JVM looks for exactly that signature when it starts your program. Java is a statically typed language: every variable is declared with a type, and that type is checked at compile time, before the program ever runs, which is a major reason a huge class of bugs never makes it past javac.

The primitive types are int, long, double, float, boolean, char, byte, and short. Anything that is not a primitive — String, arrays, your own classes — is a reference type, meaning the variable holds a pointer to an object on the heap rather than the value itself. This distinction matters a lot when you pass values into methods: primitives are copied by value, while reference variables copy the pointer, so mutating the object a reference points to is visible to the caller.

Since Java 10, the var keyword lets the compiler infer a local variable's type from its initializer, such as var count = 0. This is still fully statically typed — the compiler locks in int at that line — it just saves you from typing the type name; var is only legal for local variables with an initializer, never for fields, method parameters, or return types.

Every primitive has a corresponding wrapper class (Integer for int, Double for double, and so on), which Java converts to and from automatically through autoboxing and unboxing. This convenience hides a real trap: unboxing a null wrapper (for example, an Integer field that was never assigned) throws a NullPointerException the instant it's used in a context expecting a primitive.

Converting between numeric types is called casting. Widening conversions (int to long, float to double) happen implicitly because no information can be lost. Narrowing conversions (double to int, long to int) require an explicit cast like (int) someDouble because they can silently truncate or overflow, so the compiler forces you to acknowledge the risk in the source code.

Fields (variables declared inside a class but outside any method) are automatically given a default value if you don't initialize them — 0 for numeric types, false for boolean, null for references. Local variables inside a method get no such default: the compiler refuses to compile code that reads a local variable before it has definitely been assigned, which is another compile-time safety net.

Main.java
public class Main {
    public static void main(String[] args) {
        int age = 30;
        double price = 19.99;
        boolean active = true;
        String name = "Zainab";

        System.out.println(name + " is " + age + " years old.");
    }
}
TypesDemo.java
public class TypesDemo {
    static final double SALES_TAX = 0.08; // constants use final + UPPER_SNAKE_CASE

    public static void main(String[] args) {
        var itemCount = 3;              // inferred as int
        var unitPrice = 12.50;           // inferred as double

        double subtotal = itemCount * unitPrice;
        double total = subtotal * (1 + SALES_TAX);

        // Narrowing cast: fractional cents are truncated, not rounded
        int totalCents = (int) Math.round(total * 100);

        Integer boxedCount = itemCount;  // autoboxing int -> Integer
        int unboxedCount = boxedCount;   // unboxing Integer -> int

        System.out.println("Total: $" + total + " (" + totalCents + " cents)");
    }
}
UnboxingPitfall.java
public class UnboxingPitfall {
    static Integer cachedDiscount; // never assigned -> defaults to null

    public static void main(String[] args) {
        int price = 100;

        // Throws NullPointerException: Java tries to unbox null into an int
        int finalPrice = price - cachedDiscount;
        System.out.println(finalPrice);
    }
}
Key points
  • Java files must be named exactly after the public class they contain (Main.java for class Main).
  • Primitives store raw values and are copied by value; reference types store an address to an object on the heap.
  • var infers a local variable's type at compile time; it cannot be used for fields, parameters, or return types.
  • Autoboxing/unboxing converts between primitives and their wrapper classes automatically, but unboxing a null wrapper throws NullPointerException.
  • Widening numeric conversions are implicit; narrowing conversions require an explicit cast and can lose data.
  • Fields get automatic default values (0, false, null); local variables must be explicitly assigned before use.
  • Compilation happens before execution, so type errors and unassigned-variable errors are caught early.
Try it yourself

Write a Main class that declares an int, a double, a boolean, and a String, then prints a single sentence combining all four values. Then add a second method that takes an Integer parameter, deliberately calls it with null, and confirms in a comment where and why the NullPointerException occurs when that value is used in arithmetic.
