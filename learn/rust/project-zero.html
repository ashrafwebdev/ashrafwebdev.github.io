01 Zero stage capstone

A grep clone, built entirely from scratch

Rust · ties together everything in the Zero stage

The five Zero-stage topics — syntax and variables, ownership basics, control flow and functions, structs and enums, and cargo — exist to get you writing a real, working program without a safety net of borrowed idioms you haven't learned yet. This project asks you to build a stripped-down version of grep: a command-line tool that searches a text file for lines containing a given substring and prints them out.

It's a deliberately small target with a surprisingly large surface area for a beginner: reading command-line arguments, owning a file's contents as a String, looping over lines, branching on a case-sensitivity flag, and organizing the whole thing with a struct instead of a pile of loose variables. Every one of those maps directly onto something this stage taught you.

You're not allowed to reach for Result-returning functions you write yourself, generics, or third-party crates here — that's all later stages. Stick to std::env::args, ordinary control flow, and the .expect() pattern you've already seen for the handful of places something might legitimately fail (a missing argument, an unreadable file).

  • Syntax and variables
  • Ownership basics (the core Rust idea)
  • Control flow and functions
  • Structs and enums
  • cargo basics: build, run, test
Requirements
  • The program reads two command-line arguments — a search substring and a file path — using std::env::args, and prints a clear message (via .expect() or a manual check) if either is missing, rather than panicking with a confusing default error.
  • A dedicated function reads the whole file into an owned String and hands it back to the caller; the rest of the program works with that owned value without ever hitting a use-after-move compile error.
  • A struct (e.g. Config) groups the search term and file path together, and gets passed around as one value instead of two separate loose parameters.
  • An enum represents case-sensitive vs. case-insensitive search, and a match on it decides which string comparison to use.
  • Every matching line is printed with its 1-based line number prefixed, using a for loop over the file's lines.
  • A final summary line reports how many lines matched in total.
  • When nothing matches, the program prints an explicit "no matches found" message rather than silently printing nothing.
Suggested approach
  1. Run cargo new and get a plain "Hello, world!" printing with cargo run before writing any real logic.
  2. Add argument parsing first, and just print what you received — confirm that part works before touching files at all.
  3. Write the file-reading logic as its own function that returns an owned String, and print the raw contents to confirm ownership is flowing correctly before you add any search logic on top.
  4. Introduce the Config struct and the case-sensitivity enum, then write the actual line-matching function that takes a search term and the file contents and returns the matching lines.
  5. Add line numbering and the final summary count last, and test against a small sample text file with both a case that matches and one that doesn't.
Stretch goals
  • Accept multiple file paths in a single run and report which file each match came from.
  • Add a flag that also prints one line of context before and after each match, similar to real grep -C.
  • Write a couple of #[test] functions for your matching function directly, calling it with hard-coded strings instead of going through std::env::args at all.
