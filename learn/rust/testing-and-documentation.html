Testing and documentation

Rust · part of the free zero-to-hero guide

Rust tests are ordinary functions annotated #[test], typically kept in a #[cfg(test)] mod tests block in the same file as the code they test, and run with cargo test with zero extra configuration or external test framework needed.

Assertions use assert!, assert_eq!, and assert_ne! macros, and a test panicking (including via a failed assertion) is what marks it as failed — there's no separate assertion library to install.

Doc comments (///) support runnable code examples inside triple-backtick blocks, and cargo test actually compiles and executes those examples as doctests, which keeps documentation from silently going stale as the code changes.

lib.rs
/// Adds two numbers together.
///
/// ```
/// assert_eq!(my_crate::add(2, 3), 5);
/// ```
pub fn add(a: i32, b: i32) -> i32 {
    a + b
}

#[cfg(test)]
mod tests {
    use super::*;

    #[test]
    fn adds_two_numbers() {
        assert_eq!(add(2, 3), 5);
    }
}
Key points
  • #[test] functions run with cargo test, no external test framework required.
  • assert_eq! and friends panic on failure, which is what marks a test as failed.
  • Doc comments (///) can include runnable code examples, executed as doctests.
  • Doctests keep documentation accurate, since stale examples fail the build.
Try it yourself

Write a function is_even(n: i32) -> bool with a doc comment containing a runnable example, plus a #[test] function covering both true and false cases, and run cargo test.
