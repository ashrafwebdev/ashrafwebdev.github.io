01 Zero stage

Syntax and variables

Rust · part of the free zero-to-hero guide

A Rust program's entry point is fn main(). Variables are declared with let and are immutable by default — let x = 5; cannot be reassigned unless you explicitly opt in with let mut x = 5;, a deliberate design choice that makes accidental mutation a compile error rather than a runtime surprise.

Rust is statically typed with strong type inference: let age = 30; infers i32 without you writing it, but you can always be explicit with let age: u32 = 30; when it matters. The numeric types form a small family: signed integers i8 through i128, unsigned u8 through u128, pointer-sized isize/usize (used for indexing and lengths), and floats f32/f64 (with f64 as the default, matching double precision).

Shadowing is different from mutation: writing let x = ...; a second time in the same scope creates a brand-new binding that happens to reuse the name, and unlike mut it is allowed to change the type entirely — parsing a string into a number and reusing the same variable name is a common, idiomatic use of shadowing.

Constants, declared with const NAME: Type = value;, always require an explicit type annotation and must be computable at compile time; by convention their names are SCREAMING_SNAKE_CASE. Unlike an immutable let binding, a const has no fixed memory address — the compiler is free to inline its value everywhere it's used.

Rust has no null; a variable is always guaranteed to hold a valid value of its declared type by the time it's used. This pairs with the fact that a block { ... } is itself an expression: its value is whatever its final line evaluates to, as long as that line has no trailing semicolon — add a semicolon and the block instead evaluates to the empty unit value ().

Output typically goes through the println!/print!/format! macros (note the !, marking them as macros rather than ordinary functions). The {} placeholder uses a type's Display formatting, while {:?} uses Debug formatting (available automatically on types annotated #[derive(Debug)]) and {:#?} pretty-prints that same debug output across multiple indented lines.

main.rs
fn main() {
    let name = "Sumaya";
    let age: u32 = 30;
    let mut score = 0;
    score += 10;

    println!("{} is {} years old, score: {}", name, age, score);
}
shadow_and_const.rs
const MAX_ATTEMPTS: u32 = 3;

fn main() {
    let input = "42";
    // shadowing: `input` starts as &str, ends up as i32
    let input: i32 = input.parse().expect("not a number");
    let input = input * 2;

    println!("doubled: {}", input);
    println!("max attempts allowed: {}", MAX_ATTEMPTS);

    let point = (3, 4);
    println!("{:?}", point); // Debug formatting on a tuple
}
mistakes.rs
fn main() {
    let count = 5;
    // count = 6; // ERROR: cannot assign twice to immutable variable `count`

    let a: i32 = 10;
    let b: u32 = 5;
    // let sum = a + b; // ERROR: mismatched types, i32 vs u32
    let sum = a + b as i32; // explicit cast required
    println!("{}", sum);
}
Key points
  • Variables are immutable by default; add mut to allow reassignment.
  • Type inference fills in types automatically, but explicit annotations are always allowed and sometimes required.
  • Integer defaults to i32 and float defaults to f64; sized variants like u8, i64, and usize exist for specific needs.
  • Shadowing (repeating let with the same name) creates a new binding and can change the type, unlike mut.
  • const requires an explicit type and a compile-time-computable value, and has no fixed memory address.
  • Rust has no null value — every variable holds a genuinely valid value of its type.
  • A block is itself an expression; a trailing semicolon turns it into a statement evaluating to ().
  • println! is a macro, and {}, {:?}, and {:#?} select different formatting styles.
Try it yourself

Write a Rust program with an immutable name variable and a mutable counter variable that gets incremented three times, printing the counter after each increment. Then add a const for a maximum limit, and demonstrate shadowing by parsing a string into a number and reusing the same variable name, printing the final value with the debug formatter.
