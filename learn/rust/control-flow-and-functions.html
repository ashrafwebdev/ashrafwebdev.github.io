Control flow and functions

Rust · part of the free zero-to-hero guide

Builds on: Ownership basics (the core Rust idea)

Rust's if, loop, while, and for work much like other C-family languages, with one key difference: if is an expression, so let x = if cond { 1 } else { 2 }; is valid and idiomatic Rust.

Functions are declared with fn, and the last expression in a block (without a trailing semicolon) is implicitly returned — writing return explicitly is only needed for early returns. Unlike local variables, function parameters and return types must always be written out explicitly; Rust never infers them across a function signature.

match is Rust's powerful pattern-matching control-flow construct, and the compiler enforces exhaustiveness: every possible case must be handled, or the code simply won't compile, catching a whole class of "forgot a case" bugs.

loop is itself an expression that can produce a value: break value; exits the loop and yields value as the result of the whole loop expression, which is handy for retry-until-success logic. while let and if let are shorthand for matching a single pattern (commonly Some(x)) without writing a full match just to handle one case and ignore the rest.

Nested loops can be given labels, written 'outer: loop { ... }, so that break 'outer; or continue 'outer; can target a specific enclosing loop instead of only the innermost one — essential once loops nest two or three levels deep.

A common beginner mistake is an accidental trailing semicolon: adding ; after what was meant to be a function's final returned expression silently turns it into a statement that evaluates to (), which then fails to type-check against the function's declared return type. The compiler's error message in this case is one of the more famous "gotcha" errors for newcomers to Rust.

main.rs
fn categorize(score: i32) -> &'static str {
    match score {
        90..=100 => "A",
        80..=89 => "B",
        70..=79 => "C",
        _ => "F",
    }
}

fn main() {
    for score in [95, 82, 61] {
        println!("{} -> {}", score, categorize(score));
    }
}
loop_and_labels.rs
fn find_pair(grid: &[Vec<i32>], target: i32) -> Option<(usize, usize)> {
    let mut found = None;
    'outer: for (r, row) in grid.iter().enumerate() {
        for (c, &value) in row.iter().enumerate() {
            if value == target {
                found = Some((r, c));
                break 'outer;
            }
        }
    }
    found
}

fn main() {
    let grid = vec![vec![1, 2, 3], vec![4, 5, 6]];
    match find_pair(&grid, 5) {
        Some((r, c)) => println!("found at ({}, {})", r, c),
        None => println!("not found"),
    }

    // loop as an expression that yields a value
    let mut attempts = 0;
    let result = loop {
        attempts += 1;
        if attempts == 3 {
            break attempts * 10;
        }
    };
    println!("result: {}", result);
}
semicolon_mistake.rs
fn double(n: i32) -> i32 {
    n * 2; // BUG: trailing semicolon makes this a statement returning ()
    // ERROR: expected `i32`, found `()`
}

fn double_fixed(n: i32) -> i32 {
    n * 2 // no semicolon: this is the returned expression
}
Key points
  • if is an expression in Rust and can be used directly on the right side of a let.
  • The final expression of a function body (no semicolon) is its implicit return value.
  • Function parameters and return types must always be explicitly typed, unlike local variables.
  • match must be exhaustive; the compiler rejects code that misses a possible case.
  • Range patterns (90..=100) match inclusive ranges concisely inside a match arm.
  • loop can produce a value via break value;; while let/if let match a single pattern concisely.
  • Labeled loops ('outer: loop) let break/continue target a specific nested loop.
  • A stray trailing semicolon silently turns a returned expression into a () statement, a classic beginner error.
Try it yourself

Write a function using a labeled loop to search a 2D grid (a Vec of Vecs) for a target value, breaking out of both loops immediately once found and returning the coordinates as an Option of a tuple. Then write a for loop over a vector of Options that uses if let to print only the values that are Some, skipping the None entries.
