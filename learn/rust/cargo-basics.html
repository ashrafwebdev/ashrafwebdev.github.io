cargo basics: build, run, test

Rust · part of the free zero-to-hero guide

Builds on: Structs and enums

cargo is Rust's build tool and package manager, used for virtually every Rust project. cargo new my_project scaffolds a new project with a Cargo.toml manifest describing metadata and dependencies, and a src/main.rs starter file.

cargo build compiles the project, cargo run compiles and runs it in one step, and cargo build --release produces an optimized binary suitable for production, trading longer compile times for significantly faster runtime performance.

cargo test runs all functions annotated #[test] anywhere in the project, and cargo add fetches and adds a new dependency from crates.io directly into Cargo.toml.

cargo check is worth reaching for constantly while iterating: it runs the compiler's full type-checking and borrow-checking passes without generating an actual binary, which is noticeably faster than a full cargo build and gives you the same compile errors as fast feedback.

Larger projects often use a workspace: a top-level Cargo.toml listing multiple member crates that share one target/ build directory and one Cargo.lock, which avoids recompiling shared dependencies separately for each crate and is the standard way to split a project into a library plus one or more binaries or supporting crates.

[profile.dev] and [profile.release] sections in Cargo.toml let you tune optimization level, debug symbols, and panic behavior separately per build profile; alongside cargo, cargo fmt formats code to a canonical style, cargo clippy lints for unidiomatic or bug-prone patterns, and cargo doc --open builds and opens local documentation for your project and every one of its dependencies.

terminal
$ cargo new hello_rust
$ cd hello_rust
$ cargo run
   Compiling hello_rust v0.1.0
    Finished dev [unoptimized + debuginfo]
     Running `target/debug/hello_rust`
Hello, world!

$ cargo test
$ cargo build --release
Cargo.toml (workspace + profiles)
# top-level Cargo.toml
[workspace]
members = ["app", "core_lib"]

[profile.dev]
opt-level = 0
debug = true

[profile.release]
opt-level = 3
lto = true
panic = "abort"
terminal (dev tools)
$ cargo check          # fast type-check, no binary produced
$ cargo fmt             # format all source files
$ cargo clippy --all-targets   # lint for common mistakes
$ cargo doc --open      # build and open docs for this crate + dependencies
Key points
  • Cargo.toml declares a project's metadata and dependencies, similar to package.json or pom.xml.
  • cargo run builds and runs in one step; cargo build --release produces an optimized binary.
  • cargo test automatically discovers and runs every #[test]-annotated function.
  • cargo add fetches a dependency from crates.io and records it in the manifest.
  • cargo check gives fast compiler feedback without producing a binary at all.
  • A workspace groups multiple crates under one Cargo.toml, sharing a build directory and lockfile.
  • [profile.dev]/[profile.release] tune optimization, debug info, and panic behavior per build type.
  • cargo fmt, cargo clippy, and cargo doc --open round out the standard local development loop.
Try it yourself

Scaffold a new project with cargo new, add one dependency with cargo add, write a small test function, and run it with cargo test. Then set up a two-member workspace (a library crate and a binary crate that depends on it), and run cargo check followed by cargo fmt and cargo clippy before a final cargo build --release.
