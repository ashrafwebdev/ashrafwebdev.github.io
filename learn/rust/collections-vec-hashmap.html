Collections (Vec, HashMap)

Rust · part of the free zero-to-hero guide

Builds on: Traits and generics basics

Vec is Rust's resizable array type, created with Vec::new() or the vec! macro, and grown with .push(). Like all Rust collections, it owns its elements, and accessing an out-of-range index with [] panics, while .get() returns an Option instead for safe access.

HashMap associates keys with values, imported from std::collections. Inserting with .insert() and looking up with .get() (which returns an Option, since the key might not exist) follow the same explicit-absence philosophy as the rest of Rust.

Because collections own their contents, iterating with for item in &vec borrows each element rather than moving it out, which is why the & is idiomatic unless you specifically intend to consume the collection.

The standard library offers several other collections worth knowing: VecDeque is a double-ended queue with efficient push and pop at both ends (unlike Vec, which is only efficient at the end), HashSet stores unique unordered values, and BTreeMap is a map that keeps its keys in sorted order at the cost of slightly slower operations than HashMap. Which one to reach for depends on whether you need order, uniqueness, or queue-like access patterns.

Idiomatic Rust leans heavily on iterator adapter chains: .iter().filter(...).map(...).collect() transforms a collection functionally rather than through a manual loop with an accumulator. This isn't just a style preference — iterators are a zero-cost abstraction, meaning the compiler typically compiles a chain like this down to code just as tight as an equivalent hand-written loop.

HashMap's entry API, map.entry(key).or_insert(default), is the idiomatic way to insert-or-update a value in a single step, without a separate contains_key check followed by a conditional insert. It's the standard pattern behind counting occurrences or grouping items by key.

main.rs
use std::collections::HashMap;

fn main() {
    let mut scores = vec![88, 92, 75];
    scores.push(100);

    let mut stock: HashMap<&str, i32> = HashMap::new();
    stock.insert("apples", 50);
    stock.insert("bananas", 30);

    for (item, qty) in &stock {
        println!("{}: {}", item, qty);
    }
    println!("{:?}", scores);
}
iterator_chain.rs
fn main() {
    let scores = vec![55, 88, 92, 40, 75, 100];

    let passing: Vec<i32> = scores
        .iter()
        .filter(|&&s| s >= 60)
        .map(|&s| s + 5) // bonus points
        .collect();

    println!("{:?}", passing);

    let total: i32 = scores.iter().sum();
    println!("total: {}", total);
}
entry_api.rs
use std::collections::HashMap;

fn main() {
    let words = vec!["rust", "go", "rust", "python", "go", "rust"];
    let mut counts: HashMap<&str, i32> = HashMap::new();

    for word in &words {
        *counts.entry(word).or_insert(0) += 1;
    }

    let repeated: Vec<(&&str, &i32)> = counts.iter().filter(|(_, &c)| c > 1).collect();
    println!("{:?}", repeated);
}
Key points
  • Vec is Rust's growable array type; .get() returns an Option for safe, non-panicking access.
  • HashMap pairs keys with values; lookups return an Option since a key might not exist.
  • Iterating with &collection borrows elements instead of consuming the collection.
  • The {:?} debug format specifier prints a readable representation of most collections.
  • VecDeque, HashSet, and BTreeMap round out the standard collection toolbox for queues, uniqueness, and ordering.
  • Iterator adapter chains (filter/map/collect) are idiomatic and typically compile as fast as manual loops.
  • The entry API (.entry(key).or_insert(default)) inserts-or-updates in a single step.
  • collect() often needs a target type annotation so the compiler knows what to build.
Try it yourself

Given a Vec of strings, use the entry API on a HashMap to count occurrences of each word. Then use an iterator chain with filter and collect to keep only the words that appear more than once, and print the filtered results alongside the original full count map.
