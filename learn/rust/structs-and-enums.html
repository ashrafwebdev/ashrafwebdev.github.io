Structs and enums

Rust · part of the free zero-to-hero guide

A Rust struct groups named fields together, similar to a class's data. Methods are attached separately in an impl block, keeping data definitions and behavior visually distinct from each other.

Rust enums are far more powerful than in most languages: each variant can carry its own associated data, making an enum a natural way to model "one of several distinct shapes of data" — the Option and Result types covered in later lessons are themselves just enums.

match pairs naturally with enums: matching on an enum's variants, and optionally destructuring the data each variant carries, is one of the most common patterns in everyday Rust code.

main.rs
struct Book {
    title: String,
    pages: u32,
}

impl Book {
    fn summary(&self) -> String {
        format!("{} ({} pages)", self.title, self.pages)
    }
}

enum Shape {
    Circle(f64),
    Square(f64),
}

fn area(shape: &Shape) -> f64 {
    match shape {
        Shape::Circle(radius) => 3.14159 * radius * radius,
        Shape::Square(side) => side * side,
    }
}

fn main() {
    let b = Book { title: String::from("Rust Book"), pages: 500 };
    println!("{}", b.summary());
    println!("{}", area(&Shape::Circle(2.0)));
}
Key points
  • Methods live in a separate impl block, keeping data and behavior clearly separated.
  • Enum variants can each carry their own associated data, unlike simple enums in many other languages.
  • Matching on an enum's variants with destructuring is a core, everyday Rust pattern.
  • &self as the first method parameter borrows the instance rather than taking ownership of it.
